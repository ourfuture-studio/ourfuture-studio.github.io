submit 이벤트 처리 예제

예제는 form 요소에 submit 리스너를 등록합니다. 제출 버튼의 click만 처리하는 대신 폼의 제출 이벤트를 처리하므로 버튼 클릭과 가능한 Enter 제출 경로를 같은 핸들러로 받을 수 있습니다.

핸들러는 입력값을 읽어 p 요소의 textContent를 바꿉니다. 예제에는 서버로 데이터를 저장하는 요청이 없습니다.

이벤트 등록과 기본 동작 취소

addEventListener("submit", handler)는 이벤트가 발생할 때 실행할 함수 참조를 등록합니다. handler()를 즉시 실행하는 것과 다릅니다. 이벤트 객체의 preventDefault()는 취소 가능한 기본 제출 동작을 막습니다.

new FormData(form)는 포함 조건을 만족하는 컨트롤의 name과 현재 값으로 폼 데이터 객체를 만듭니다. preventDefault()는 이벤트 전파를 중지하는 stopPropagation()과 다른 메서드입니다.

FormData와 입력값 검증

student 입력을 ‘연습생’, course 값을 web 또는 css로 설정한 뒤 제출합니다. 핸들러는 FormData.get()으로 값을 읽고 이름 문자열에 trim()을 적용해 공백만 있는 입력을 검사합니다.

정상 입력이면 선택값을 포함한 텍스트를 표시하고, 공백 문자열이면 이름 검사 문구를 표시합니다. required에 걸리는 빈 입력은 submit 핸들러가 실행되기 전에 브라우저의 제약 검증에서 차단될 수 있습니다.

화면 확인과 서버 접수의 차이

클라이언트에서 표시한 결과는 DOM 변경의 결과이며 서버 저장의 증거가 아닙니다. 실제 전송이 필요하면 요청을 구현하고 서버 응답과 업무 처리 결과를 별도로 확인해야 합니다.

preventDefault()는 다른 이벤트 리스너나 작성한 모든 코드를 중단하는 메서드가 아닙니다. 어떤 이벤트의 어떤 기본 동작을 취소하는지 명시합니다.

입력·이벤트·DOM의 처리 순서

처리 순서는 컨트롤의 현재 값 → submit 이벤트 → FormData → 입력 검사 → textContent 변경입니다. 각 단계의 객체와 값이 무엇인지 구분해 추적합니다.
