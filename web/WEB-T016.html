HTTP 요청·응답과 Fetch API.

HTTP 요청은 URL의 리소스를 요청하고, 응답은 상태·헤더·본문 등을 제공합니다. Fetch API로 응답을 받은 뒤 HTTP 상태를 검사하고 본문을 JSON으로 파싱해 사용합니다.

직접 확인

정상 조회 뒤 없는 파일 버튼을 누르고 네트워크 패널의 상태를 비교하세요.

예상 결과 · 정상 요청은 강좌 이름을 표시하고 없는 파일은 HTTP 404 안내를 표시합니다.

JSON 데이터 요청 예제

예제의 courses.json은 객체 배열을 담은 JSON 파일입니다. JavaScript는 fetch("courses.json")으로 파일을 요청하고 각 객체의 title 문자열을 읽어 DOM에 표시합니다.

JSON 텍스트와 파싱된 JavaScript 값, HTML의 출력 요소를 구분합니다. 이 예제는 정적 데이터 조회이며 폼 데이터 저장이나 데이터베이스 갱신을 수행하지 않습니다.

HTTP 상태와 응답 본문

fetch()는 Response를 처리할 Promise를 반환합니다. response.status는 HTTP 상태 코드이고 response.ok는 200~299 상태 범위인지 나타냅니다. response.json()은 응답 본문을 JSON으로 파싱하는 비동기 처리입니다.

404 같은 HTTP 오류 응답도 Response로 받을 수 있으므로 fetch()의 거부 처리만으로 구분하지 않습니다. 네트워크 실패, HTTP 상태 오류, JSON 파싱 오류는 서로 다른 단계의 실패입니다.

HTTP 요청·응답 관찰

GitHub Pages에서 실행하거나 예제 폴더를 HTTP 서버로 제공해 엽니다. 정상 조회 버튼을 실행하고 개발자 도구에서 courses.json의 요청 URL·상태·응답 본문을 확인합니다. 상대 URL은 문서의 기준 URL에서 해석됩니다.

없는 파일 버튼은 missing.json을 요청합니다. 예제 코드는 response.ok를 검사해 HTTP 404를 오류로 처리하고, 정상 JSON에서는 배열 여부와 각 title의 문자열 자료형을 검사합니다.

전송 성공·형식·데이터 검증

200 응답은 JSON 문법이나 필요한 데이터 필드까지 보장하지 않습니다. 본문 파싱과 데이터 구조 검사를 별도로 수행합니다. file: URL에서의 fetch 동작에도 의존하지 않도록 HTTP 환경에서 확인합니다.

클라이언트가 문자열을 화면에 표시한 결과와 서버의 업무 처리는 다릅니다. 예제에서 확인한 범위는 정적 JSON 요청·상태 검사·구조 검사·DOM 출력입니다.

쿠키와 브라우저 저장소

요청 URL·응답 상태·본문·파싱된 값을 단계별로 기록하면 실패 위치를 구분할 수 있습니다. 요청에 조건에 맞는 쿠키가 포함되는 경우와 localStorage의 값을 읽는 경우도 서로 다른 동작입니다.
