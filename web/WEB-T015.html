Window 객체와 타이머.

Window 객체의 setTimeout()은 지연 후 실행할 콜백을 예약하고 식별자를 반환합니다. clearTimeout()은 해당 예약을 취소합니다. 지정한 지연은 정확한 실행 시각을 보장하지 않습니다.

예제는 시작 버튼의 click 이벤트에서 setTimeout()을 호출하고 반환된 식별자를 timer 변수에 저장합니다. 취소 버튼은 같은 식별자를 clearTimeout()에 전달합니다.

예약 시점의 DOM 상태와 콜백 실행 후의 DOM 상태를 비교합니다. p 요소의 텍스트는 상태를 표시하기 위한 출력입니다.

Window·Document와 타이머 API

Window는 브라우저 창이나 프레임의 실행 환경을 다루는 인터페이스이고 Document는 문서를 나타내는 인터페이스입니다. 타이머 예약은 setTimeout()으로, 결과 표시는 Document에서 선택한 요소의 프로퍼티 변경으로 수행합니다.

setTimeout(callback, 1000)은 지정한 지연 뒤 콜백을 실행할 수 있도록 예약합니다. 메인 스레드 작업이나 브라우저 정책에 따라 실제 실행이 더 늦어질 수 있습니다. 반환된 식별자는 아직 실행하지 않은 예약을 취소할 때 사용합니다.

타이머 실행·취소

시작 버튼을 누르면 p의 텍스트가 ‘기다리는 중’으로 바뀌고 예약된 콜백이 실행되면 결과 텍스트로 바뀝니다. 시작 직후 취소하면 예약된 변경이 발생하지 않아야 합니다.

시작을 다시 누를 때에는 기존 timer를 먼저 취소하고 새로 예약합니다. 같은 동작으로 예약이 중복되는 경우를 방지합니다.

지연 시간과 실제 실행 시각

긴 동기 반복문으로 대기하면 메인 스레드의 이벤트 처리를 지연시킬 수 있습니다. 타이머 예약은 반복문을 실행하며 시간을 소비하는 방식과 다릅니다.

1000ms를 지정했다는 이유만으로 콜백이 정확히 1초 시각에 실행되었다고 판단하지 않습니다. 정밀한 시간 측정과 업무 마감 판정에는 그에 맞는 별도 기준이 필요합니다.

타이머와 비동기 응답

타이머 콜백은 예약 시점의 다음 문장과 다른 시점에 실행됩니다. HTTP 요청의 응답 처리도 요청을 시작한 직후 완성된 값을 읽는 동기 처리와 구분합니다.
