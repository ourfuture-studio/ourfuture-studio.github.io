비동기 처리 상태 예제

예제의 mockRequest()는 setTimeout()과 Promise로 구성한 모의 비동기 함수입니다. 성공 입력에서는 문자열로 이행하고 실패 입력에서는 Error로 거부합니다. 실제 네트워크 지연을 측정하는 예제는 아닙니다.

버튼의 disabled 프로퍼티와 결과 요소의 textContent를 변경해 실행 전·대기·완료 상태를 표시합니다.

Promise·async·await와 예외 처리

Promise의 상태는 pending, fulfilled, rejected로 구분합니다. async 함수 안의 await는 전달된 값이나 Promise의 완료 결과를 받아 다음 처리를 이어 가며, 거부된 경우 예외 처리 흐름으로 이동합니다.

try는 정상 결과 처리, catch는 오류 처리, finally는 두 경로 이후의 정리를 담당하도록 구성합니다. await가 함수의 진행을 대기시킨다는 것과 브라우저의 모든 실행을 동기 반복문으로 차단하는 것은 다릅니다.

대기·성공·실패 상태

모의 성공 버튼을 누르면 두 버튼의 disabled가 true가 되고 결과 요소에 대기 텍스트가 표시됩니다. 모의 작업이 이행되면 성공 결과를 표시하고 finally에서 버튼을 복원합니다.

모의 실패도 같은 대기 상태를 거쳐 catch에서 오류를 표시한 뒤 버튼을 복원합니다. 성공·실패 모두 재실행이 가능한 상태로 돌아오는지 확인합니다.

중복 요청과 응답 순서

이 예제는 처리 중 버튼을 비활성화해 중복 실행을 제한합니다. 여러 요청을 동시에 허용하는 경우에는 응답 순서가 요청 순서와 다를 수 있으므로 요청 식별자나 취소 전략 등을 별도로 설계해야 합니다.

타이머 기반 모의 성공은 HTTP 연결이나 서버 응답의 검증 결과가 아닙니다. 실제 fetch를 사용할 때에는 HTTP 상태와 응답 본문 검사도 유지합니다.

비동기 작업의 UI 상태는 실행 흐름을 표시하는 일시적 데이터입니다. 새로고침 후에도 유지할 데이터를 저장하는 API와 역할이 다릅니다.
