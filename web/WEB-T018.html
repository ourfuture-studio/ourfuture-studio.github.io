Web Storage와 localStorage.

localStorage는 origin별 브라우저 저장소에 문자열 키·값을 저장합니다. setItem()·getItem()·removeItem()으로 쓰기·읽기·삭제를 수행하며 서버 저장과 구분합니다.

강좌 선택값 저장 예제

예제는 select 요소의 현재 value인 web 또는 css를 저장합니다. 저장 키는 ourfuture.web.course이며 다른 실습의 저장값과 구별하기 위해 이름을 지정했습니다.

입력 컨트롤의 현재 값, 저장소에 기록된 문자열, 문서를 다시 열 때 복원하는 값을 구분합니다. 이름·연락처·계정 토큰은 저장하지 않습니다.

localStorage 쓰기·읽기·삭제

localStorage.setItem(key, value)은 값을 문자열로 저장합니다. getItem(key)은 저장된 문자열이나 키가 없을 때 null을 반환하고, removeItem(key)은 지정한 키만 삭제합니다.

origin은 스킴·호스트·포트를 기준으로 구분합니다. 경로만 다른 같은 origin의 문서들은 저장소를 사용할 수 있으므로 키 이름을 구분해야 합니다. localhost와 127.0.0.1, 서로 다른 포트는 같은 origin이라고 가정하지 않습니다.

새로고침 후 복원과 삭제

select에서 css를 선택해 저장한 뒤 같은 origin에서 새로고침합니다. 초기화 코드는 저장값이 web 또는 css인지 검사하고 유효하면 select.value에 적용합니다.

삭제 버튼은 해당 키만 제거하고 select를 기본값 web으로 변경합니다. 삭제 후 새로고침해 기본값이 표시되는지 확인합니다. 예제는 저장소 접근 예외도 처리합니다.

저장 수명과 origin 조건

브라우저 설정·저장 공간·사용자 삭제 등의 조건에 따라 저장이 실패하거나 값이 없어질 수 있습니다. localStorage를 영구 보관이나 다른 기기와의 동기화로 설명하지 않습니다. file: URL의 저장 동작에도 의존하지 않습니다.

객체를 그대로 객체 형태로 저장하는 API도 아닙니다. 이 예제는 이미 문자열인 값만 저장하며, 저장소에 쓴 값이 자동으로 서버에 전송되지는 않습니다.

쿠키·sessionStorage·localStorage 구분

sessionStorage는 origin과 탭의 페이지 세션에 관련된 저장소이며 새로고침과 탭 종료의 조건을 구분합니다. 쿠키는 조건에 맞는 요청에 포함될 수 있어 Web Storage와 전달 방식도 다릅니다.
