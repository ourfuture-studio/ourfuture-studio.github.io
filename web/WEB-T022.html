Web Worker와 메시지 통신.

전용 Web Worker는 메인 문서와 별도의 실행 문맥에서 JavaScript를 실행합니다. postMessage()와 message 이벤트로 데이터를 전달하고, DOM 변경은 메인 문서에서 수행합니다.

연결 파일 전체 코드

worker.js

self.onmessage = event => {
  const n = event.data;
  if (!Number.isInteger(n) || n < 1 || n > 1000000) throw new RangeError("입력 범위 오류");
  let sum = 0;
  for (let i = 1; i <= n; i++) sum += i;
  self.postMessage(sum);
};

직접 확인

입력 n을 10과 100000으로 바꾸어 실행하고 횟수 버튼도 누르세요.

예상 결과 · 합은 각각 55와 5000050000입니다. 화면 횟수는 별도 버튼 동작에 따라 증가합니다.

전용 Worker 계산 예제

예제는 index.html의 메인 스크립트와 worker.js를 사용합니다. 메인 스크립트가 정수 n을 전달하면 Worker가 1부터 n까지의 합을 계산해 반환합니다.

메인 문서의 별도 버튼은 click 횟수를 표시합니다. 이 예제는 실행 문맥과 메시지 흐름을 구분하기 위한 것이며 성능 향상률을 측정하는 벤치마크가 아닙니다.

Worker 생성과 메시지 통신

new Worker("worker.js")는 전용 Worker 스크립트를 로드해 실행합니다. 메인 쪽 worker.postMessage(n)과 Worker 쪽 message 이벤트의 data로 입력값을 전달합니다.

Worker는 self.postMessage(sum)으로 결과를 보내며 메인 문서의 message 핸들러가 DOM에 표시합니다. 일반적인 메시지 데이터는 구조화된 복제 방식으로 전달됩니다. Worker에서는 메인 문서의 document·DOM에 직접 접근할 수 없습니다.

HTTP 환경의 Worker 실행

GitHub Pages 또는 로컬 HTTP 환경에서 index.html과 worker.js를 같은 폴더에 두고 실행합니다. 입력 n은 1 이상 1,000,000 이하의 정수로 제한하며 메인 쪽과 Worker 양쪽에서 검사합니다.

n=10의 합은 55이고 n=100000의 합은 5000050000입니다. 결과를 받은 뒤 terminate()로 Worker를 종료합니다. 새 계산을 시작할 때에도 기존 Worker를 종료하고 새 인스턴스를 사용합니다.

Worker 비용·오류·종료

Worker 생성과 메시지 전달에도 비용이 있으므로 모든 계산의 전체 시간이 줄어드는 것은 아닙니다. 계산 결과의 정확성과 화면 반응·처리 시간의 개선 주장은 별도의 기준으로 검증해야 합니다.

스크립트 URL·동일 출처 조건·제공 환경·브라우저 정책 등의 실행 조건을 확인하고 오류 경로를 처리합니다. 이 예제는 오류를 표시하고 Worker를 종료하지만 서버 기능이나 실제 업무 처리까지 구현하지는 않습니다.

문서·스타일·통신·계산의 역할

HTML은 문서 구조, CSS는 스타일과 배치, JavaScript는 값·제어 흐름·DOM 조작을 다룹니다. HTTP는 리소스 요청·응답, Web Storage는 브라우저 저장, Worker는 별도의 계산 실행 문맥을 제공합니다.

각 기능의 입력·출력·실행 조건을 구분하면 문서 구조와 코드 동작을 함께 추적할 수 있습니다. 서버 저장이나 계정·동시 요청 처리는 이 브라우저 기초 실습과 별도로 설계해야 합니다.
