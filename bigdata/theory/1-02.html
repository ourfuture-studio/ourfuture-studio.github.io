저장소와 작업 실행 순서 관리

파일을 보관하는 장소와 다음 작업을 시작하는 규칙은 서로 다른 역할이다.

관련 문제 풀기조건 바꿔 체험
핵심 이론작은 예제직접 고르기

핵심 이론

매일 받은 주문 파일을 저장한 뒤 정제하고, 정제가 성공하면 매출을 집계한다고 하자. 저장소는 주문 파일과 결과를 보관한다. 워크플로 관리 도구는 정제와 집계 사이의 선후 관계, 성공·실패에 따른 다음 실행을 관리한다. 파일이 잘 저장됐다는 사실만으로 집계까지 실행되지는 않는다.

문제에서 “무엇을 저장하는가”와 “언제 어떤 작업을 실행하는가”를 나누어 읽는다. 분산 저장을 위한 기술을 골랐다고 작업 의존성이 자동으로 정의되는 것은 아니다. 반대로 스케줄러를 설치했다고 원본 파일의 내구성과 접근 권한이 저절로 확보되지 않는다.

Oozie는 Hadoop 작업의 실행 흐름을 연결하던 과거 워크플로 스케줄러 사례다. Apache 기록상 2025년 2월 은퇴했으므로 현재 신규 도입을 권하는 예로 쓰지 않는다. 시험 공부에서는 이름보다 저장·처리·실행 조정 중 어떤 책임을 맡았는지를 확인한다.

작은 예제로 확인하기

자체 주문 집계 파이프라인의 책임을 나누어 보자.

단계 책임
원본 파일 보관 저장소
잘못된 주문 행 정제 처리 작업
정제 성공 후 집계 시작 워크플로 관리

정제가 실패했을 때 집계를 멈추고 재시도 조건을 확인하는 것은 실행 조정의 문제다. 정제 내용이 옳은지는 별도로 확인해야 한다. 파일 보관이 끝났어도 정제 결과가 실패이면 “정제 성공 뒤 집계”라는 규칙에서는 집계를 시작하지 않는다. 반대로 정제 성공이면 집계를 시작할 수 있지만 집계 계산의 정확성까지 확인된 것은 아니다. 실행 허용, 작업 성공, 산출물 정확성을 세 번 나누어 확인한다.

그림으로 확인하기

직접 고르기

정제가 성공한 뒤에만 매출 집계를 실행해야 한다.

직접 필요한 역할은?

  • 1. 파일 영구 보관
  • 2. 작업 의존성 관리
  • 3. 영상 압축
  • 4. 분류 확률 계산
정답과 오답의 이유 확인하기

정답 2번 — 작업 의존성 관리

성공 조건과 다음 작업의 연결을 정하는 것은 워크플로의 작업 의존성 관리다.

  • 1번은 결과를 보관하지만 시작 조건을 정하지 않는다.
  • 3번은 특정 자료의 변환 작업이다.
  • 4번은 분석모형의 계산이다.

조건 하나 바꾸어 풀기

조건을 “원본 주문 파일을 여러 장비에 나누어 보관”으로 바꾸면 필요한 책임은?

풀이: 분산 저장의 책임이다.

질문이 실행 순서에서 자료 보관으로 바뀌었다. 같은 파이프라인 안에서도 요구하는 책임에 따라 답이 달라진다.
