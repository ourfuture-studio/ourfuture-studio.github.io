추출·변환·적재(ETL, Extract, Transform, Load)와 추출·적재·변환(ELT, Extract, Load, Transform)

둘의 핵심 차이는 데이터를 어디에 적재(Loading)한 뒤 변환(Transformation)하는지다.

관련 문제 풀기조건 바꿔 체험
개념도핵심 수식·판단예제로 이해문제·체험

그림으로 먼저 이해하기

단위를 통일한 곳이 데이터베이스 안인지 밖인지 왜 중요할까?

추출·변환·적재(ETL, Extract, Transform, Load)와 추출·적재·변환(ELT, Extract, Load, Transform)은 정한 목적지의 적재 전후 변환 위치가 다르다.

정식 용어와 정의

추출·변환·적재(ETL, Extract, Transform, Load)는 원천에서 추출(Extraction)한 데이터를 대상 저장소(Target Data Store)에 적재(Loading)하기 전에 변환(Transformation)하는 데이터 통합(Data Integration) 방식이다. 추출·적재·변환(ELT, Extract, Load, Transform)은 대상 저장소(Target Data Store)에 먼저 적재(Loading)하고 그 저장소(Storage)의 연산 능력으로 변환(Transformation)하므로, 문제에서 정한 대상 저장소(Target Data Store)와 변환(Transformation) 위치를 기준으로 구별한다.

핵심 이론

추출·변환·적재(ETL, Extract, Transform, Load)는 추출(Extraction)한 자료를 대상 저장소(Target Data Store)에 적재(Loading)하기 전에 별도 처리 단계에서 변환(Transformation)하는 흐름으로 설명한다. 추출·적재·변환(ELT, Extract, Load, Transform)은 먼저 대상 저장소(Target Data Store)에 적재(Loading)한 뒤 그 저장소(Storage)의 처리 능력으로 변환(Transformation)한다. E·T·L의 순서를 보면 변환(Transformation)이 적재(Loading)의 앞인지 뒤인지 확인할 수 있다.

이때 적재(Loading)가 어느 목적지를 가리키는지 명시해야 한다. 중간 임시 파일을 썼다는 이유만으로 모든 파이프라인(Pipeline)이 추출·적재·변환(ELT, Extract, Load, Transform)이 되는 것은 아니다. 여러 변환(Transformation) 단계가 섞인 실제 시스템도 있으므로 자체 문제에서는 최종 분석 저장소(Storage)를 기준으로 정한다.

둘 중 어느 방식이 항상 더 빠르거나 안전하다고 단정하지 않는다. 원본 보관, 변환(Transformation)에 필요한 처리 능력, 민감정보의 이동 범위와 품질 검증 위치가 설계 판단에 영향을 준다. 같은 SQL을 사용했는지가 아니라 주된 변환(Transformation)이 대상 저장소(Target Data Store)의 어디에서 이뤄지는지를 본다.

핵심 판단 원리

핵심 판단 규칙

목적지 적재 전 주된 변환 → ETL / 목적지 적재 후 주된 변환 → ELT

inside는 E→L→T, before는 E→T→L이다.

적용 조건: 목적지를 먼저 정한다. 여러 변환이 섞인 실제 시스템은 각 변환의 위치를 따로 표시한다.

정의와 원리 참고: Microsoft Learn: Extract, transform, load

기존 예제의 조건과 표 자세히 보기

목적지를 분석 데이터베이스(DB, Database)로 고정한 자체 예다.

흐름 구분
추출(Extraction)→외부에서 단위 통일→분석 데이터베이스(DB, Database) 적재(Loading) 추출·변환·적재(ETL, Extract, Transform, Load)
추출(Extraction)→분석 데이터베이스(DB, Database) 원본 적재(Loading)→데이터베이스(DB, Database) 안에서 단위 통일 추출·적재·변환(ELT, Extract, Load, Transform)

단위 통일의 내용이 같아도 실행 위치와 적재(Loading) 순서가 다르다. 임시 보관과 최종 목적지를 구분한다. 추출(Extraction) 파일을 잠시 디스크에 쓴 뒤 외부 엔진에서 정리하고 분석 데이터베이스(DB, Database)에 넣었다면, 그 임시 파일을 L로 삼지 않는다. 문제에서 고정한 목적지는 분석 데이터베이스(DB, Database)이므로 주된 변환(Transformation)이 목적지 적재(Loading) 전이면 추출·변환·적재(ETL, Extract, Transform, Load)이다. 실제 시스템이 여러 변환(Transformation)을 함께 쓰면 각 변환(Transformation)의 위치를 따로 표시한 뒤 주된 흐름을 설명한다.

직접 고르기

목적지는 분석 DB다. 원본을 분석 데이터베이스(DB, Database)에 적재(Loading)한 뒤 그 데이터베이스(DB, Database) 안에서 값을 정리한다.

  • 1. 추출·변환·적재(ETL, Extract, Transform, Load)
  • 2. 추출·적재·변환(ELT, Extract, Load, Transform)
  • 3. 저장 없는 시각화
  • 4. 추출(Extraction) 없는 백업(Backup)
정답과 오답의 이유 확인하기

정답 2번 — 추출·적재·변환(ELT, Extract, Load, Transform)

목적 데이터베이스(DB, Database)에 먼저 적재(Loading)하고 그 안에서 변환(Transformation)하므로 E→L→T다.

  • 1번은 목적지 적재(Loading) 전에 변환(Transformation)하는 흐름이다.
  • 3번은 적재(Loading)·변환(Transformation)이 있다는 조건과 다르다.
  • 4번은 원본을 추출(Extraction)해 옮긴다는 조건을 누락한다.

조건 하나 바꾸어 풀기

원본을 외부 처리 엔진에서 정리한 뒤 분석 데이터베이스(DB, Database)에 적재(Loading)하도록 바꾸면?

풀이: 추출·변환·적재(ETL, Extract, Transform, Load)이다.

같은 목적지를 기준으로 변환(Transformation)이 적재(Loading)보다 앞으로 이동했다.

다시 떠올릴 단서

대상 저장소(Target Data Store)에 넣기 전 변환인지, 넣은 뒤 변환인지.
