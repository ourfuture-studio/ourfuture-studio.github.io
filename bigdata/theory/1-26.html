데이터 수집(Data Collection): 웹 크롤링(Web Crawling)·API(Application Programming Interface)·데이터베이스(Database)

화면을 읽는 방법, 제공된 인터페이스를 호출하는 방법, 데이터베이스(DB, Database)를 질의(Query)하는 방법을 구분한다.

개념도핵심 수식·판단예제로 이해문제·체험

그림으로 먼저 이해하기

API가 120건 중 첫 50건만 돌려줬다면 수집이 끝난 걸까?

데이터 수집(Data Collection)은 응용 프로그래밍 인터페이스(API, Application Programming Interface)의 요청·응답 명세와 페이지별 반환 결과를 함께 확인하는 일이다.

정식 용어와 정의

데이터 수집(Data Collection) 경로는 웹 문서의 탐색을 자동화하는 웹 크롤링(Web Crawling), 제공된 인터페이스로 요청하는 응용 프로그래밍 인터페이스(API, Application Programming Interface), 권한이 있는 데이터베이스(DB, Database)의 조회 등으로 구분할 수 있다. 공식 응용 프로그래밍 인터페이스(API, Application Programming Interface)가 목적에 맞게 제공되면 인증(Authentication), 호출 제한(Rate Limit), 페이지 나누기(Pagination)와 이용 조건을 확인하며, 웹 페이지에서 필요한 내용을 추출하는 웹 스크레이핑(Web Scraping)과 탐색 자체를 구분한다.

핵심 이론

웹 페이지는 사람이 보는 화면과 HTML 구조를 중심으로 구성된다. 공개 응용 프로그래밍 인터페이스(API, Application Programming Interface)는 요청 주소, 매개변수(Parameter), 응답 항목, 인증(Authentication)과 호출 한도 같은 명세를 통해 기계가 데이터를 요청하도록 한다. 데이터베이스(DB, Database) 접근은 허용된 계정과 범위 안에서 질의(Query)를 실행하는 방식이다.

필요한 필드를 제공하는 공식 응용 프로그래밍 인터페이스(API, Application Programming Interface)가 있고 이용 조건을 충족했다면 화면 구조를 해석하는 대신 그 명세를 사용하는 경로를 먼저 검토할 수 있다. 다만 응용 프로그래밍 인터페이스(API, Application Programming Interface)라는 이름만으로 모든 자료가 있고 자유롭게 무제한 사용할 수 있다고 가정하지 않는다. 페이지 구분, 갱신 주기, 누락과 오류 응답을 확인한다.

이 문항은 접근 권한을 우회하는 방법을 다루지 않는다. 수집과 재이용이 허용된 자료라는 조건에서 자료의 제공 형태에 맞는 경로를 고른다. 수집 후에는 요청 조건·수집 시각·반환 건수와 원본을 기록해야 나중에 같은 결과를 설명할 수 있다.

핵심 수식

고정 페이지 크기의 필요한 페이지 수

P=⌈NB⌉

긴 수식은 좌우로 넘겨 전체 식을 볼 수 있습니다.

N
전체 건수 120
B
페이지당 최대 건수 50
P
필요한 페이지 수
⌈ ⌉
올림(Ceiling)

⌈120/50⌉=3페이지다. 마지막 페이지는 20건이다.

적용 조건: 전체 건수와 페이지 크기를 고정하고, 마지막 페이지를 제외한 각 페이지가 B건씩 반환되며 중복·누락 없이 분할되는 자체 예제다. 동적 갱신·중복 여부는 추가 확인한다.

정의와 원리 참고: 공공데이터포털: 전국평생학습강좌표준데이터

작은 예제로 확인하기

기존 자체 API 예제는 전체 120건을 페이지당 50건씩 제공한다.

  1. 1페이지 수 계산

    120÷50=2.4이므로 마지막 일부 페이지까지 받아야 한다.

  2. 2건수 대조

    50·50·20건을 합하면 120건이다.

  3. 3수집 조건 확인

    요청 조건과 중복 식별자, 응답 시각을 함께 기록한다.

첫 50건은 전체가 아니다. 이 고정 조건에서는 3페이지가 필요하다.

이 수치는 실제 공공 API의 한도나 현재 반환 건수를 측정한 결과가 아니다.

기존 예제의 조건과 표 자세히 보기

공공데이터포털의 실제 명세는 요청변수와 출력결과를 구분한다. 아래 상황은 자체 예다.

제공 형태 수집에서 확인할 것
응용 프로그래밍 인터페이스(API, Application Programming Interface) 매개변수(Parameter)·페이지·응답 필드·한도
허용된 데이터베이스(DB, Database) 테이블·필드·조건·권한
허용된 웹 페이지 HTML 구조·갱신·이용 조건

같은 항목을 얻더라도 화면 문구와 응용 프로그래밍 인터페이스(API, Application Programming Interface) 필드명이 다를 수 있다. 수집 경로와 원천의 의미를 함께 기록한다. 전체 120건을 페이지당 50건씩 주는 자체 응용 프로그래밍 인터페이스(API, Application Programming Interface)라면 첫 응답 50건은 전체가 아니다. 다음 페이지에서 50건과 20건을 더 받아 120건인지 대조해야 한다. 명세에 전체 건수가 없거나 수집 중 자료가 바뀌면 단순 합계만으로 완전성(Completeness)을 확정하지 말고 응답 시각·페이지 조건·중복 식별자를 함께 남긴다.

직접 고르기

필요한 필드를 반환하는 공식 응용 프로그래밍 인터페이스(API, Application Programming Interface)가 있고 이용 권한과 조건을 충족했다.

직접 맞는 수집 경로는?

  • 1. 화면 픽셀을 무조건 수기 복사
  • 2. 응용 프로그래밍 인터페이스(API, Application Programming Interface) 명세에 따라 요청·응답 수집
  • 3. 데이터베이스(DB, Database) 권한 우회
  • 4. 응용 프로그래밍 인터페이스(API, Application Programming Interface)는 자료를 반환할 수 없음
정답과 오답의 이유 확인하기

정답 2번 — 응용 프로그래밍 인터페이스(API, Application Programming Interface) 명세에 따라 요청·응답 수집

제공된 필드와 요청·응답 명세를 사용해 자료를 수집할 수 있다.

  • 1번은 공식 인터페이스가 있다는 조건을 활용하지 않는다.
  • 3번은 허용된 경로를 벗어난다.
  • 4번은 응용 프로그래밍 인터페이스(API, Application Programming Interface)가 필드를 반환한다는 조건과 모순된다.

조건 하나 바꾸어 풀기

응용 프로그래밍 인터페이스(API, Application Programming Interface)가 없고 읽기 권한이 있는 내부 데이터베이스(DB, Database)에 필요한 표가 있다면?

풀이: 허용된 데이터베이스(DB, Database) 질의(Query)를 수집 경로로 검토한다.

자료의 제공 형태와 권한이 바뀌었으므로 경로를 다시 고른다.
