핵심 이론작은 예제직접 고르기

핵심 이론

웹 페이지는 사람이 보는 화면과 HTML 구조를 중심으로 구성된다. 공개 API는 요청 주소, 매개변수, 응답 항목, 인증과 호출 한도 같은 명세를 통해 기계가 데이터를 요청하도록 한다. DB 접근은 허용된 계정과 범위 안에서 질의를 실행하는 방식이다.

필요한 필드를 제공하는 공식 API가 있고 이용 조건을 충족했다면 화면 구조를 해석하는 대신 그 명세를 사용하는 경로를 먼저 검토할 수 있다. 다만 API라는 이름만으로 모든 자료가 있고 자유롭게 무제한 사용할 수 있다고 가정하지 않는다. 페이지 구분, 갱신 주기, 누락과 오류 응답을 확인한다.

이 문항은 접근 권한을 우회하는 방법을 다루지 않는다. 수집과 재이용이 허용된 자료라는 조건에서 자료의 제공 형태에 맞는 경로를 고른다. 수집 후에는 요청 조건·수집 시각·반환 건수와 원본을 기록해야 나중에 같은 결과를 설명할 수 있다.

작은 예제로 확인하기

공공데이터포털의 실제 명세는 요청변수와 출력결과를 구분한다. 아래 상황은 자체 예다.

제공 형태 수집에서 확인할 것
API 매개변수·페이지·응답 필드·한도
허용된 DB 테이블·필드·조건·권한
허용된 웹 페이지 HTML 구조·갱신·이용 조건

같은 항목을 얻더라도 화면 문구와 API 필드명이 다를 수 있다. 수집 경로와 원천의 의미를 함께 기록한다. 전체 120건을 페이지당 50건씩 주는 자체 API라면 첫 응답 50건은 전체가 아니다. 다음 페이지에서 50건과 20건을 더 받아 120건인지 대조해야 한다. 명세에 전체 건수가 없거나 수집 중 자료가 바뀌면 단순 합계만으로 완전성을 확정하지 말고 응답 시각·페이지 조건·중복 식별자를 함께 남긴다.
