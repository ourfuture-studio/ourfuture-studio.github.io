데이터베이스 관리자(DBA, Database Administrator)의 역할과 모형 개발(Model Development)

직함을 외우기 전에 맡긴 업무의 결과물이 무엇인지 확인한다.

관련 문제 풀기조건 바꿔 체험
핵심 이론작은 예제직접 고르기

정식 용어와 정의

데이터베이스 관리자(DBA, Database Administrator)는 데이터베이스(DB, Database)의 사용자 권한, 가용성(Availability), 백업(Backup)과 복구(Recovery) 등 운영·보호 업무를 담당한다. 모형 개발(Model Development)은 예측 목표와 특성(Feature)을 정해 모형(Model)을 학습·평가(Evaluation)하는 업무이며, 실제 담당 범위는 조직의 직무 정의에 따라 달라진다.

  • 데이터베이스 관리자(DBA, Database Administrator)
  • 데이터베이스(DB, Database)
  • 백업(Backup)
  • 복구(Recovery)
  • 접근 통제(Access Control)
  • 가용성(Availability)
  • 모형 개발(Model Development)

정의 참고: Oracle Database Concepts — Concepts for Database Administrators · IBM — How to structure a modern data team

핵심 이론

고객 데이터베이스(DB, Database)를 통합하고 접근 권한을 설정하며 장애 시 복구(Recovery) 절차를 유지하는 업무는 데이터를 안정적으로 제공하기 위한 관리 업무다. 반면 이탈 여부를 예측할 변수를 정하고 학습·평가(Evaluation)를 수행하는 업무는 분석모형 개발에 해당한다. 둘은 협업하지만 책임을 확인하는 질문은 다르다.

Oracle의 데이터베이스 관리자(DBA, Database Administrator) 문서는 저장 관리, 사용자·보안 관리, 백업(Backup)·복구(Recovery), 성능 모니터링(Performance Monitoring) 등을 예로 든다. 데이터 표준과 품질 책임은 조직에 따라 데이터 관리자나 스튜어드 등과 나누기도 한다. 따라서 “통합·보호를 한다”는 짧은 단서만으로 모든 조직에 동일한 직함을 강제하지 않는다.

시험의 보기를 비교할 때는 전체 업무 묶음을 읽는다. 데이터베이스(DB, Database)의 가용성(Availability)과 권한을 책임지는지, 분석 결과를 해석하는지, 모델을 학습하는지가 판단 근거다. 여기의 자체 문항은 역할 이름의 모호함을 피하고 구체적인 업무를 정답으로 묻는다.

작은 예제로 확인하기

쇼핑몰에서 두 담당자에게 다음 일을 맡겼다.

담당 요청된 결과
가 데이터베이스(DB, Database) 권한·백업(Backup)·복구(Recovery) 계획 유지
나 다음 달 이탈 확률을 예측하고 평가(Evaluation)

가는 데이터베이스(DB, Database) 운영·보호 책임, 나는 모형 개발(Model Development) 책임이다. 나의 성능이 높아도 가의 접근 권한 검토를 대신하지 못한다. 백업(Backup) 파일이 있다는 것과 복구(Recovery)가 되는 것은 다르다. 가 담당자의 결과는 권한 검토 기록과 복구(Recovery) 가능한 백업(Backup)처럼 운영 기준으로 확인한다. 나 담당자의 결과는 정해 둔 평가자료의 예측 오차로 확인한다. 서로 다른 결과물을 같은 “정확도(Accuracy)” 하나로 평가(Evaluation)하지 않는다.

정답과 오답의 이유 확인하기

정답 3번 — 데이터베이스(DB, Database) 운영·보호

권한과 백업(Backup)·복구(Recovery)는 데이터베이스(DB, Database)를 안전하고 지속적으로 사용할 수 있게 하는 운영·보호 업무다.

  • 1번은 예측모형을 개발하는 업무다.
  • 2번은 차원 축소(Dimensionality Reduction)의 설정이다.
  • 4번은 군집 분석(Clustering)의 설정이다.
