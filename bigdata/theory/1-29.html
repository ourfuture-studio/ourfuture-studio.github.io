그림으로 먼저 이해하기

마케팅 부서용 분석 범위를 만들면 회사 전체가 하나의 저장 방식만 써야 할까?

데이터 웨어하우스(Data Warehouse)·데이터 마트(Data Mart)·데이터 레이크(Data Lake)·데이터 레이크하우스(Data Lakehouse)는 요구 범위와 기능을 비교하는 개념이다.

정식 용어와 정의

데이터 웨어하우스(DW, Data Warehouse)는 분석용으로 통합·정비한 데이터를 관리하고, 데이터 마트(Data Mart)는 특정 부서나 주제의 분석 요구에 초점을 맞추며, 데이터 레이크(Data Lake)는 다양한 형식의 데이터를 폭넓게 보관하는 저장 구조다. 데이터 레이크하우스(Data Lakehouse)는 데이터 레이크(Data Lake)의 저장 유연성에 스키마(Schema) 관리·트랜잭션(Transaction) 등 데이터 웨어하우스(DW, Data Warehouse) 기능을 결합하려는 구조이며, 이름만으로 모든 구현의 품질이나 성능이 보장되지는 않는다.

핵심 이론

데이터 웨어하우스(DW, Data Warehouse)는 여러 원천을 통합해 일관된 분석·보고를 지원하는 정리된 자료 체계로 설명한다. 데이터 마트(Data Mart)는 특정 부서나 주제에 초점을 맞춘 분석 범위다. 데이터 마트(Data Mart)가 반드시 전사 데이터 웨어하우스(DW, Data Warehouse)에서만 파생되는 것은 아니며, 범위와 목적을 함께 확인한다.

데이터 레이크(Data Lake)는 표뿐 아니라 원본 파일, 로그, 이미지 등 다양한 자료를 담는 저장 접근이다. 데이터 레이크하우스(Data Lakehouse)는 이런 저장 기반에 테이블 관리, 질의(Query)와 스키마(Schema)·트랜잭션(Transaction) 관리 같은 데이터 웨어하우스(DW, Data Warehouse)의 성격을 결합하려는 접근으로 이해한다. 실제 제공 기능은 제품과 구현에 따라 다르다.

데이터 레이크(Data Lake)에 넣었다고 품질 검증이 끝나는 것은 아니며 데이터 레이크하우스(Data Lakehouse)라는 이름만으로 어떤 질의(Query)에서도 더 빠르다고 할 수 없다. 원본 보존, 전사 지표, 부서별 분석, 관리 기능처럼 문제에 명시된 요구를 기준으로 구분한다.

핵심 판단 원리

핵심 판단 규칙

전사 통합 / 부서·주제 범위 / 다양한 원본 / 관리 기능 결합을 각각 확인

마케팅 캠페인 범위는 Data Mart에 초점을 둔다.

적용 조건: 한 조직에서 여러 구조가 공존할 수 있다. 이름만으로 비용·성능·품질의 우열을 확정하지 않는다.

정의와 원리 참고: AWS: Data lake vs data warehouse vs data mart · Microsoft Learn: Store data in Microsoft Fabric

작은 예제로 확인하기

기존 요구는 마케팅 부서의 캠페인 분석 범위이며 기본 선택은 mart다.

  1. 1범위 읽기

    전사 전체인지 특정 부서·주제인지 확인한다.

  2. 2자료와 기능 읽기

    원본 저장 요구인지 관리되는 테이블·질의 기능 결합 요구인지 구별한다.

특정 부서·주제의 분석 범위를 강조한 기본 요구는 데이터 마트다.

데이터 마트와 기반 저장 구조가 서로 하나만 선택하는 전체 조직 형태라고 단정하지 않는다.

기존 예제의 조건과 표 자세히 보기

소매 회사의 자체 저장 요구를 비교한다.

요구 연결되는 개념
전사 매출 지표를 통합해 보고 데이터 웨어하우스(DW, Data Warehouse)
마케팅 부서의 캠페인 분석 범위 데이터 마트(Data Mart)
원본 영상·로그·표 파일 보관 데이터 레이크(Data Lake)
데이터 레이크(Data Lake) 자료에 관리되는 테이블·질의(Query) 기능 결합 데이터 레이크하우스(Data Lakehouse)

한 조직에서 이 구조들을 함께 사용할 수 있다. 네 개를 서로 배타적인 발전 단계로 외우지 않는다. 데이터 마트(Data Mart)는 누구와 어떤 주제에 필요한 범위인지에 초점이 있고, 데이터 레이크하우스(Data Lakehouse)는 저장과 관리 기능을 결합하는 구조에 초점이 있다. 따라서 데이터 레이크하우스(Data Lakehouse) 기반 안에 마케팅 데이터 마트(Data Mart) 범위를 구성할 수도 있다. 네 이름을 한 줄의 발전 단계나 서로 하나만 고르는 전체 조직 형태로 외우지 않는다.

그림으로 확인하기

직접 고르기

전사 자료 중 마케팅 부서의 캠페인 분석에 필요한 범위를 구성한다.

분석 범위를 가장 직접 설명하는 것은?

  • 1. 데이터 마트(Data Mart)
  • 2. 원본 영상 코덱
  • 3. 항상 전사 전체와 같은 범위
  • 4. 워크플로 스케줄러(Workflow Scheduler)
정답과 오답의 이유 확인하기

정답 1번 — 데이터 마트(Data Mart)

특정 부서와 주제에 초점을 맞춘 분석 자료 범위는 데이터 마트(Data Mart)로 설명할 수 있다.

  • 2번은 영상 표현 방식이다.
  • 3번은 부서·주제로 한정한다는 조건과 다르다.
  • 4번은 작업 실행 순서를 관리하는 역할이다.

조건 하나 바꾸어 풀기

요구를 “원본 영상·로그를 보관하면서 관리되는 테이블과 질의(Query) 기능도 함께 제공”으로 바꾸면?

풀이: 데이터 레이크하우스(Data Lakehouse) 접근을 검토할 수 있다.

자료의 다양성(Variety)에 더해 테이블 관리와 분석 기능의 결합을 명시했다. 실제 지원 여부는 구현을 확인해야 한다.

다시 떠올릴 단서

전사 통합·주제 범위·원본 다양성(Variety)·관리 기능을 나눈다.
