전처리 파이프라인(Preprocessing Pipeline)과 모형 배포(Model Deployment)

모형(Model) 파일이 같아도 열 순서와 단위, 결측값(Missing Value) 처리, 학습한 변환이 달라지면 다른 입력을 계산한다. 실제 적용에서는 원시 입력부터 출력의 의미까지 한 계약으로 확인한다.

그림으로 먼저 이해하기

학습 때 표준화한 모형에 운영 원시 입력14를 바로 넣어도 될까요?

전처리 파이프라인(Preprocessing Pipeline)은 학습 때 저장한 변환과 모형을 같은 순서로 적용해야 합니다.

정식 용어와 정의

전처리 파이프라인(Preprocessing Pipeline)은 학습한 변환과 모형(Model)을 순서대로 연결한다. 운영 예측에서도 학습 때 정한 열 순서와 단위, 전처리(Preprocessing) 모수(Parameter)를 적용해 입력과 출력의 의미를 유지한다.

핵심 이론

학습한 모형(Model)은 이름 없는 숫자 묶음에 의미를 스스로 붙이지 않는다. 학습 때 가격과 수량의 순서로 넣었다면 서비스에서도 같은 특성·순서·자료형·단위를 전달해야 한다. 열 두 개의 값이 모두 숫자라서 실행된다고 의미까지 맞는 것은 아니다. 필수 열이 빠졌을 때의 처리, 알 수 없는 범주, 허용 범위와 결측값(Missing Value) 규칙을 입력 스키마(Schema)에 기록하면 조용히 잘못된 예측을 내는 경로를 줄일 수 있다.

전처리(Preprocessing)에 학습된 값이 있다면 모형(Model)과 함께 보관한다. 표준화(Standardization)의 평균(Mean)·표준편차(SD, Standard Deviation), 대체값, 범주 인코딩 사전은 학습 자료에서 결정한 변환의 일부다. 새 요청마다 평균(Mean)을 다시 학습하면 같은 값도 함께 들어온 요청에 따라 다른 숫자로 변한다. 평가(Evaluation) 자료나 운영 입력에 fit을 다시 실행하는 것과 저장한 변환의 transform을 적용하는 것은 다르다. 파이프라인(Pipeline)은 이 단계를 묶어 전달하는 방법이지만 올바른 스키마(Schema)와 학습 범위까지 자동으로 보장하지는 않는다.

출력에도 계약이 필요하다. 이진 분류에서 배열의 어느 열이 관심 양성의 확률인지, 점수가 큰 쪽이 어느 클래스(Class)를 뜻하는지, 임계값(Critical Value)과 후처리는 무엇인지 정한다. 회귀 결과는 통화·기간·로그 변환(Log Transformation)의 역변환 여부를 설명한다. 모형(Model)·전처리(Preprocessing)·스키마(Schema) 버전을 함께 식별하고, 알려진 소수 입력에 대한 기대 출력을 배포(Deployment) 전후에 비교한다. 테스트 입력이 맞았다는 사실과 이후 모든 운영 자료에서 성능이 유지된다는 주장은 구분한다.

핵심 수식

이 예의 전처리와 예측 연결

z=x−102ŷ=3z+1

긴 수식은 좌우로 넘겨 전체 식을 볼 수 있습니다.

x
원시 입력
z
저장한 평균·표준편차로 변환한 모형 입력
ŷ
지정한 선형식의 예측값

x14 → z2 → ŷ7

적용 조건: 학습 때 저장한 평균10·표준편차2와 모형식이 고정된 자체 예입니다.

정의와 원리 참고: scikit-learn Pipelines · Google MLCC Monitoring pipelines

작은 예제로 확인하기

학습 평균10·표준편차2를 저장했고 모형은 표준화한 z에 ŷ=3z+1을 적용합니다.

  1. 1저장 변환 적용

    운영 x=14에도 z=(14−10)/2=2를 계산합니다.

  2. 2모형 입력

    원시14가 아니라 z=2를 전달합니다.

  3. 3기대 출력

    3×2+1=7입니다.

전처리와 모형을 하나의 입력·출력 계약으로 점검합니다.

새 요청 한 건으로 평균과 표준편차를 다시 학습하는 것은 저장된 transform 적용과 다릅니다.

기존 예제의 조건과 표 자세히 보기

자체 예에서 학습 시 저장한 평균(Mean)은10, 표준편차(SD, Standard Deviation)는2다. z=(x−10)/2를 만든 뒤 ŷ=3z+1을 계산한다. 운영 입력x=14에도 저장한 값을 적용한다.

단계 계산 값
표준화(Standardization) (14−10)/2 2
예측 3×2+1 7

원시 입력14를 모형식에 곧바로 넣으면43이 되어 지정한 파이프라인(Pipeline)의7과 다르다. 한 요청만 보고 평균(Mean)을14로 다시 정하는 것도 학습한 변환과 다르다. 이 예는 변환의 연결을 검사하며 실제 자료의 예측 정확도(Accuracy)를 측정하지는 않는다.

직접 고르기

저장된 전처리(Preprocessing)는 z=(x−10)/2, 모형(Model)은 ŷ=3z+1이다. 운영 입력 x=14에 같은 파이프라인(Pipeline)을 적용한다.

올바른 처리와 출력은?

  • 1. 원시 입력 14를 바로 넣어 43을 출력한다
  • 2. 새 입력의 평균(Mean)을 다시 학습해 항상 1을 출력한다
  • 3. 저장한 평균(Mean)·표준편차(SD, Standard Deviation)로 변환해 7을 출력한다
  • 4. 출력 단위는 숫자만 맞으면 확인하지 않는다
정답과 오답의 이유 확인하기

정답 3번 — 저장한 평균(Mean)·표준편차(SD, Standard Deviation)로 변환해 7을 출력한다

저장한 변환에서 z=2이고 ŷ=7이다. 학습된 변환과 입력·출력 의미를 함께 유지해야 동일한 파이프라인(Pipeline)을 적용한 것이다.

  • 1번: 표준화(Standardization) 단계를 빠뜨려 학습 때와 다른 숫자를 모형(Model)에 넣었다.
  • 2번: 저장된 평균(Mean) 10·표준편차(SD, Standard Deviation) 2를 적용하면 입력 14는 z=2가 된다. 새 요청 한 건으로 평균(Mean)을 14로 다시 맞추면 중심화(Centering) 값 0에서 출력 1이 나올 수 있지만, 학습 때 정한 변환을 바꾼 계산이다. 이 보기를 제외하는 이유는 1이라는 숫자가 불가능해서가 아니라 저장한 파이프라인(Pipeline)을 유지하지 않았기 때문이다.
  • 4번: 같은 숫자라도 단위·기간·클래스(Class) 의미가 다르면 사용자가 다른 행동을 할 수 있다. 출력 계약도 확인한다.

조건 하나 바꾸어 풀기

학습한 변환과 모형(Model)을 그대로 두고 운영 입력만 x=10으로 바꾸면 출력은?

풀이: z=0이고 ŷ=1이다.

(10−10)/2=0, 3×0+1=1이다. 입력 하나가 달라졌을 뿐 평균(Mean)·표준편차(SD, Standard Deviation)를 새로 학습하지 않는다.
