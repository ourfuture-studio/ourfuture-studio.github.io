정수 나눗셈과 형변환 (Integer Division and Cast)

9개를 4개씩 묶으면 완성된 묶음은 2개입니다. C의 정수 나눗셈(Integer Division)도 두 피연산자(Operand)가 정수이면 정수 몫을 계산합니다. 소수 부분은 0 방향으로 버리므로 9 / 4는 2, −9 / 4는 −2입니다. 음수에서 내림(Floor)과 다르다는 점을 보세요.

형변환(Cast)의 위치가 계산 방법을 바꿉니다. (double)(a / b)는 정수 계산이 끝난 뒤 결과를 double로 바꿉니다. (double)a / b는 나누기 전에 한쪽을 double로 바꾸므로 일반 산술 변환(Usual Arithmetic Conversions)에 따라 실수 나눗셈을 합니다. 아래에서 강조한 줄과 변수 상자를 함께 따라가세요.

double / int → double 계산 · 결과를 저장할 변수의 자료형만 보고 판단하지 않습니다.

값 전달과 포인터 (Pass by Value and Pointer)


C의 함수 호출은 값 전달(Pass by Value)입니다. 호출자의 인자(Argument) 값이 함수의 매개변수(Parameter)에 복사됩니다. change(x)에서 매개변수 v를 바꾸면 복사본만 달라지고, 호출자의 x는 그대로입니다. 원본 문서의 복사본에 메모해도 원본은 변하지 않는 것과 같습니다.
포인터(Pointer)도 값으로 복사됩니다. 다만 change(&x)로 복사한 값은 x의 주소(Address)입니다. *p로 역참조(Indirection)하면 그 주소가 가리키는 원래 객체를 지정하므로 *p = 11은 x를 바꿉니다. 반면 p = &local은 함수 안의 포인터 변수만 다른 곳을 가리키게 합니다.


구분할 두 대입 *p = 값 → 가리키는 객체 수정
p = 주소 → 포인터 변수의 값 수정

오버로딩과 오버라이딩 (Overloading and Overriding)




같은 이름의 f(Object)와 f(String) 중 무엇을 호출할까요? 먼저 오버로딩(Overloading) 규칙으로 컴파일 시점(Compile Time)의 인자 표현식 자료형을 보고 메서드 시그니처(Method Signature)를 고릅니다. Object x = "sun";이면 x가 가리키는 객체가 문자열이어도 표현식 x의 자료형은 Object입니다.


그다음 일반 인스턴스 메서드(Instance Method)의 실행 시점(Runtime)에는 실제 수신 객체(Receiver Object)를 따라 오버라이딩(Overriding)한 구현을 찾습니다. 메뉴에서 먼저 ‘Object용 주문’을 고른 뒤, 실제 담당자인 A 또는 B가 그 주문을 처리한다고 생각해 보세요. B가 담당한다고 이미 고른 주문이 String용으로 바뀌지는 않습니다.

참조의 복사와 객체 수정 (Reference Copy and Object Mutation)




Box b = a;는 Box 객체를 복제하지 않고 참조값(Reference Value)을 복사합니다. 두 변수에 같은 사물함 번호를 적은 것처럼, a와 b로 같은 객체(Object)의 필드(Field)를 읽을 수 있습니다. 그래서 b.n = 7;로 객체를 수정하면 a.n으로도 7을 읽습니다.


재대입(Reassignment)은 다른 동작입니다. b = new Box(7);은 b가 가리키는 대상을 새 객체로 바꿉니다. a의 참조값은 그대로이므로 a가 보던 객체의 n은 바뀌지 않습니다. ‘같은 객체를 고쳤는가, 변수 하나를 다른 객체로 옮겼는가’를 화살표로 구별하세요.


핵심 규칙 · b.n = 값 → 가리키는 객체의 필드 수정. b = 새 객체 → b의 참조값 변경. Java의 인자 전달도 값 전달(Pass by Value)이며, 참조값을 전달한다고 참조에 의한 전달(Pass by Reference)이 되는 것은 아닙니다.

할당·얕은 복사·깊은 복사 (Assignment, Shallow Copy, Deep Copy)


변수 이름은 물건에 붙인 이름표처럼 객체(Object)를 가리킵니다. b = a는 리스트를 하나 더 만드는 연산이 아닙니다. 두 이름이 같은 리스트를 가리키게 됩니다. 그래서 b.append(...)로 바깥 리스트를 바꾸어도 a에서 그 변화를 봅니다.
얕은 복사(Shallow Copy)인 a.copy()는 바깥 리스트만 새로 만듭니다. 안에 든 리스트의 참조(Reference)는 함께 사용하므로 b[0].append(9)가 원래 내부 리스트도 바꿉니다. 반면 깊은 복사(Deep Copy)인 copy.deepcopy(a)는 이 중첩 리스트의 내부 리스트까지 새로 만듭니다.
핵심 규칙: “변수 이름이 다른가?”보다 “지금 수정하는 객체를 함께 가리키는가?”를 확인합니다. 이 예제는 중첩된 정수 리스트이며, 사용자 정의 객체의 복사 정책까지 일반화하지 않습니다.

슬라이싱과 range (Slicing and range)


슬라이싱(Slicing)의 a[start:stop:step]은 시작 인덱스(Index)에서 간격(Step)만큼 이동하며 값을 고릅니다. 종료 경계(Stop)는 포함하지 않습니다. 양수 간격은 오른쪽, 음수 간격은 왼쪽으로 이동합니다. 배열의 칸을 짚으며 실제 선택 순서를 따라가 보세요.
range(start, stop, step)는 정수들을 생성합니다. 반면 슬라이싱은 시퀀스(Sequence) 길이를 기준으로 음수 인덱스와 생략한 경계를 해석합니다. 따라서 range(-1, -7, -2)의 값 [-1, -3, -5]와 a[-1:-7:-2]에서 선택되는 실제 인덱스 [5, 3, 1]는 다릅니다.
핵심 규칙: stop은 제외하며 step = 0은 허용되지 않습니다. a[::-1]의 생략한 종료점과 a[:-1:-1]의 명시한 -1은 다릅니다. 뒤의 식은 마지막 칸에서 시작하자마자 같은 경계에 닿아 빈 리스트가 됩니다.






시작·종료는 -99~99 정수 또는 None을 입력하세요. 빈칸도 생략(None)으로 취급합니다. None은 Python에서 경계를 생략한다는 뜻입니다.
