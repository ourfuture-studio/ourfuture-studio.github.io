TCP 전달 보장과 응용의 업무 완료

관련 문제 1개조건 바꿔 체험

전송계층이 제공하는 기능과 서버 프로그램이 실제로 끝낸 작업을 구별한다.

핵심 이론

TCP는 연결 기반으로 순서 있는 신뢰성 있는 바이트 스트림을 제공한다. 데이터 손실을 탐지하고 재전송하는 기능이 있지만 응용 메시지의 경계를 자동으로 보존하는 방식은 아니다.

UDP는 데이터그램을 보내며 기본 프로토콜 자체에서 전달과 중복 방지를 보장하지 않는다. 응용이 순번·확인·재전송을 구현해 필요한 신뢰성을 더할 수 있으므로 UDP 사용이 곧 응용 전체의 무신뢰를 뜻하지 않는다.

TCP의 전송 확인은 DB 저장·결제 같은 업무 완료 확인과 별개이다. 실제 요구에는 응용 응답이나 트랜잭션 상태 확인이 필요하다. UDP가 항상 더 빠르거나 TCP가 항상 지연이 크다는 수치상의 우열은 프로토콜 이름만으로 확정할 수 없다.

작은 예제로 확인하기

클라이언트가 TCP로 주문 바이트를 전송했다. 상대 TCP의 수신 확인은 관찰했지만 서버 응용의 DB 저장 완료 응답은 아직 없다.
