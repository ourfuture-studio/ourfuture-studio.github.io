자식 생성자 본문 전 부모 생성자 호출

관련 문제 1개조건 바꿔 체험

자식 인스턴스를 초기화할 때 부모 생성자 호출을 먼저 마친다.

핵심 이론

생성자는 새 객체의 초기화 절차를 정하며 일반 메서드처럼 상속되어 오버라이딩되는 대상이 아니다. 자식 생성자는 this(...) 또는 super(...)를 통해 다른 생성자 호출을 연결한다.

Java SE 17에서 명시적 호출이 없는 자식 생성자에는 보통 super()가 삽입된다. 부모에 접근 가능한 무인자 생성자가 없으면 적절한 super(인자)를 명시해야 한다.

부모 생성자 본문이 끝난 뒤 자식의 인스턴스 초기화와 자식 생성자 본문을 진행한다. 여기서는 필드 초기화·초기화 블록·생성자 안 재정의 메서드 호출을 제외하여 부모 본문과 자식 본문의 순서만 비교한다.

작은 예제로 확인하기

Java SE 17, Main.java로 저장. java.lang은 자동 import하며 외부 입력·다중 스레드·사용자 정의 예외 처리 없음. A/B 생성자 외 초기화 출력은 없고 new B()만 실행한다.

조건 또는 단계 판단 또는 값
new B() A() 본문 A→B() 본문 B
new B(7) A(7) 본문 P7→B(int) 본문 C
생성자 관계 상속된 메서드의 재정의가 아님

B라는 객체 한 개를 만드는 동안 부모 부분과 자식 부분의 초기화가 순서대로 일어난다.

다시 떠올릴 단서

생성자 호출 연결을 따라 부모 초기화부터 추적한다.

적용 범위

Java SE 17의 생성자 규칙에 고정한다. 더 최신 언어판의 생성자 문법 변화를 이 예제로 일반화하지 않는다.
