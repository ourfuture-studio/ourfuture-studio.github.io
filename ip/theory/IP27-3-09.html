필드와 메서드는 같은 방식으로 선택되지 않는다

관련 문제 1개조건 바꿔 체험

필드는 참조 표현식의 자료형, 재정의 인스턴스 메서드는 실제 객체를 확인한다.

핵심 이론

부모와 자식이 같은 이름의 인스턴스 필드를 선언하면 자식 필드는 부모 필드를 숨긴다. A a=new B()에서 a.v는 a의 컴파일 시점 자료형 A의 필드이다.

같은 참조로 a.f()를 호출할 때 f가 재정의된 인스턴스 메서드라면 실제 객체 B의 구현을 찾는다. 같은 a를 사용해도 필드 접근과 메서드 호출은 서로 다른 선택 규칙을 따른다.

(B)a.v처럼 괄호 위치를 잘못 쓰지 말고 ((B)a).v처럼 참조를 변환한 뒤 필드에 접근해야 한다. 실제 객체가 B일 때만 이 다운캐스트가 안전하다. static 메서드와 필드는 이 예제의 동적 호출 규칙에 넣지 않는다.

작은 예제로 확인하기

Java SE 17, Main.java로 저장. java.lang은 자동 import하며 외부 입력·다중 스레드·사용자 정의 예외 처리 없음. A a=new B().

조건 또는 단계 판단 또는 값
A a=new B() a.v=4
같은 a의 a.f() 20
((B)a).v 9

부모형 참조가 자식 객체를 가리킨다는 한 사실로 필드까지 자식 값이라고 결론 내리지 않는다.

다시 떠올릴 단서

필드는 표현식 자료형, 재정의 메서드는 실제 객체를 본다.

적용 범위

일반 필드와 접근 가능한 인스턴스 메서드이며 실제 객체가 보장된 캐스트만 사용한다.
