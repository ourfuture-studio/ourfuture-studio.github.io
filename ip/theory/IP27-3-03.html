식의 묶음과 평가 순서를 나누어 읽기

관련 문제 1개조건 바꿔 체험

우선순위는 어떤 연산에 어떤 피연산자가 붙는지 정한다. 모든 피연산자를 실행하는 시간 순서와는 다르다.

핵심 이론

우선순위는 a+bc를 a+(bc)로 묶는 규칙이다. 결합 방향은 a-b-c를 (a-b)-c로 묶는 규칙이다. 이 두 규칙으로 식의 구조를 읽을 수 있다.

C에서 +와 *의 피연산자는 일반적으로 왼쪽부터 평가된다고 보장되지 않는다. 곱셈이 더 강하게 묶인다는 사실에서 a를 읽는 것보다 b를 먼저 읽는다는 결론은 나오지 않는다.

아래 식은 값을 바꾸는 부수효과가 없어서 평가 순서가 달라도 수치가 같다. 호출 순서가 필요하다면 함수를 별도 완전식으로 분리한다. UB와 허용된 여러 평가 순서를 구별해야 한다.

작은 예제로 확인하기

C11 의미 규칙(N1570), signed int이며 아래 작은 값에서 범위 초과 없음. 각 코드는 표준 헤더와 main을 포함한 독립 프로그램이고 입력 없음. 0으로 나누지 않는다.

조건 또는 단계 판단 또는 값
2+3*4 2+(3*4)=14
(2+3)*4 20
20-5-3 (20-5)-3=12

곱셈·덧셈의 구조를 확정한 뒤 계산하되, 구조를 부수효과의 순서 보장으로 해석하지 않는다.

다시 떠올릴 단서

괄호는 묶음을, 순서 규칙은 부수효과의 앞뒤를 정한다.

적용 범위

모든 수는 signed int의 안전한 범위이며 함수 호출 부수효과는 없다.
