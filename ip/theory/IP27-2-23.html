로그의 새 값 재현과 이전 값 복원

관련 문제 1개조건 바꿔 체험

커밋 기록과 갱신 로그를 함께 읽어야 장애 뒤 남길 효과를 정할 수 있다.

핵심 이론

로그 기반 복구에서 갱신 기록은 어떤 거래가 어떤 값을 바꾸었는지 보관한다. 교육 모형의 <T,X,old,new>는 거래 T가 항목 X를 old에서 new로 바꾼 기록이다. 로그를 데이터 페이지보다 먼저 안정 저장하는 조건을 전제한다.

여기서는 교재의 역사를 재현하는 2단계 모형을 고정한다. 먼저 기록된 갱신을 순방향 REDO해 new 값을 적용하고, 완료하지 못한 거래는 역방향 UNDO해 old 값으로 되돌린다. 이 방식에서는 미완료 거래도 REDO 단계에 포함될 수 있다.

커밋 거래만 REDO한다는 규칙을 모든 복구 알고리즘의 정의로 쓰면 안 된다. 실제 제품은 체크포인트, 페이지의 로그 위치, 보상 로그 등으로 대상을 정한다. 아래 예제는 손상 없는 안정 저장장치·서로 다른 항목 두 개의 명시적 모형이며 실제 DBMS 장애 복구를 수행한 것은 아니다.

작은 예제로 확인하기

대표 사례의 모형은 모든 갱신 REDO 후 미완료 거래 UNDO다. T1은 X10→14 후 커밋, T2는 Y20→27 후 미완료이며 장애 시 디스크는 X10·Y27이다.

로그 상태
T1: X10→14 커밋
T2: Y20→27 미완료
장애 디스크 X10,Y27

모든 갱신을 REDO하면 X14·Y27, 미완료 T2를 UNDO하면 Y20으로 복원되어 최종 X14·Y20이다.

다시 떠올릴 단서

복구 알고리즘의 REDO·UNDO 대상과 순서를 문제의 모형에서 먼저 고정한다.

적용 범위

모든 갱신 REDO 후 미완료 UNDO라는 명시적 교육 모형을 Python으로 검산했다. 실제 DBMS 복구 알고리즘·디스크 장애 실행 결과가 아니다.
