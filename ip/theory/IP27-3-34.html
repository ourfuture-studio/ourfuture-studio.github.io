3과목 · 3-34 · 이론 읽기

finally의 새 반환과 예외가 남기는 결과

관련 문제 1개조건 바꿔 체험

finally가 정상 종료하는지, 새 return이나 throw로 끝나는지 먼저 구분한다.

핵심 이론

Java에서 return과 throw는 현재 문장의 정상 진행을 끝내는 비정상 완료 이유이다. 여기서 비정상 완료는 반드시 오류가 발생했다는 뜻이 아니라 정상적으로 다음 문장으로 진행하지 않는다는 명세 용어이다. try에서 return을 만나도 해당 try-finally의 finally를 실행하는 규칙이 있다.

finally가 정상 완료하면 앞서 보류된 return 또는 throw의 이유를 계속 전달한다. finally가 새 return이나 throw로 비정상 완료하면 이전 이유는 버려지고 새 이유가 결과를 정한다.

이 때문에 finally에서 무조건 return하는 코드는 이전 예외까지 가릴 수 있다. 프로세스 강제 종료·VM 중단·끝나지 않는 실행까지 포함해 finally가 언제나 실행된다고 일반화하지 않는다. 아래 실험은 일반적인 메서드 호출과 정상 VM 실행에 고정한다.

작은 예제로 확인하기

Java SE 17, Main.java로 저장한다. 외부 입력은 없다. f의 try는 return 3, finally는 return 8로 끝난다. main이 f의 반환값을 한 번 출력한다.

조건 또는 단계 판단 또는 값
try return3 반환3 보류
finally return8 새반환8이앞이유대체
최종호출결과 8

finally 실행 여부와 최종 반환값의 보존 여부를 별도로 확인한다.

다시 떠올릴 단서

finally가 정상 끝나면 앞 이유를 유지하고 새 return·throw면 그 이유가 남는다.

적용 범위

Java SE 17 일반 실행이다. System.exit·강제 종료·무한 반복·try-with-resources는 제외한다.
