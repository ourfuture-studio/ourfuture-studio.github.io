finally의 return과 throw가 정하는 최종 결과

관련 문제 1개조건 바꿔 체험

try에서 return을 만나도 호출자에게 값을 전달하기 전에 finally를 실행한다. finally가 끝나는 방식에 따라 최종 반환값이나 전달되는 예외가 달라진다.

핵심 이론

finally가 return이나 throw를 실행하지 않고 정상적으로 끝나면, try 또는 catch에서 이미 정해진 반환값이나 전파 중인 예외를 그대로 유지한다.

반대로 finally에서 return 8;이 실행되면, try에서 반환하려던 값이 3이더라도 메서드는 8을 반환한다. finally에서 throw가 실행되면, 반환값을 전달하는 대신 그 예외를 호출자에게 전달한다.

Java 명세는 return이나 throw처럼 제어 흐름을 다른 곳으로 옮기는 종료를 비정상 완료(Abrupt Completion)라고 부른다. 여기서 ‘비정상’은 반드시 실행 오류가 발생했다는 뜻이 아니다. 이 글에서는 추상적인 ‘이유의 대체’ 대신 실제로 유지되는 반환값과 전달되는 예외를 구분한다.

finally의 return은 앞서 발생한 예외까지 가릴 수 있으므로 반환값을 바꾸는 용도로 사용하지 않는 편이 안전하다. 아래 예제는 동작 규칙을 비교하기 위한 교육용 코드다.

작은 예제로 확인하기

Java SE 17 기준이다. 아래 코드를 Main.java로 저장한다. 외부 입력은 없으며 main이 f()의 반환값을 한 번 출력한다.

public class Main {
    static int f() {
        try {
            return 3;
        } finally {
            return 8;
        }
    }

    public static void main(String[] args) {
        System.out.println(f());
    }
}
실행 단계 실제로 일어나는 일
try에서 return 3; 실행 반환할 값 3을 계산하지만, 호출자에게 전달하기 전에 finally를 실행한다.
finally에서 return 8; 실행 반환하려던 3은 전달되지 않고, 메서드가 반환할 값이 8로 결정된다.
main에서 f()의 결과 출력 최종 반환값인 8을 한 번 출력한다. return 자체는 출력문이 아니다.

출력은 다음과 같다.

8

finally의 마지막 동작만 바꾸어 비교하기

finally의 동작 try의 return 3; 이후 최종 결과
int local = 8;을 실행하고 정상 종료 지역 변수 대입은 반환값을 바꾸지 않으므로 3을 반환한다.
return 8; 실행 3 대신 8을 반환한다.
throw new IllegalStateException("x"); 실행 3을 반환하지 않고 IllegalStateException을 호출자에게 전달한다. 연결된 조건 체험의 main은 이 예외를 잡아 클래스 이름을 출력한다.

다시 떠올릴 단서

finally가 정상 완료하면 기존 결과를 유지한다. finally에서 return이나 throw가 실행되면 그 결과를 따른다.

적용 범위

Java SE 17의 일반적인 메서드 호출을 비교한다. System.exit, 프로세스·VM 강제 종료, 끝나지 않는 실행, try-with-resources는 이 예제의 범위에서 제외한다. 모든 상황에서 finally가 반드시 실행된다고 일반화하지 않는다.

근거와 확인 범위

  • Java SE 17 JLS §14.20.2 — try-finally의 실행 규칙: finally의 정상 완료 시 기존 제어 흐름 유지와, finally의 return·throw 실행 시 최종 제어 흐름 결정 규칙을 확인했다. 공식 문서 확인일: 2026-11-26.
