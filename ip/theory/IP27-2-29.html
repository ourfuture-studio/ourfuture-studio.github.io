UNKNOWN은 FALSE와 다르다

관련 문제 1개조건 바꿔 체험

NULL과의 일반 비교를 뒤집어도 TRUE가 되지 않는다. WHERE가 통과시키는 진릿값을 따로 확인하자.

핵심 이론

NULL은 이 예제에서 값이 알려지지 않았음을 나타내는 표지다. 일반 비교 value=0은 NULL에 대해 UNKNOWN이다. TRUE·FALSE·UNKNOWN의 세 가지로 판단하므로 NULL을 숫자0이나 FALSE로 치환하지 않는다.

NOT UNKNOWN도 UNKNOWN이다. 따라서 WHERE NOT(value=0)은 value가 NULL인 행을 남기지 않는다. WHERE는 최종 조건이 TRUE인 행만 남기므로 FALSE와 UNKNOWN은 결과에서 모두 빠진다.

NULL 자체를 검사할 때는 IS NULL을 사용한다. TRUE OR UNKNOWN은 TRUE지만 FALSE OR UNKNOWN은 UNKNOWN이며, FALSE AND UNKNOWN은 FALSE다. 실제 표현식의 평가 순서 보장과 진리표는 별개이고, 문자열·NULL 처리 차이가 있는 다른 DBMS로 무조건 확대하지 않는다.

작은 예제로 확인하기

Observation의 행은 (1,NULL),(2,0),(3,4)다. 정수 비교의 SQL 3값 논리를 적용한다.

id value value=0 NOT(value=0)
1 NULL UNKNOWN UNKNOWN
2 0 TRUE FALSE
3 4 FALSE TRUE

NOT으로 뒤집어도 id1은 UNKNOWN이다. 최종 TRUE인 id3만 남는다.

다시 떠올릴 단서

각 행의 TRUE·FALSE·UNKNOWN을 계산한 뒤 TRUE만 통과시킨다.

적용 범위

명시한 작은 예제의 조건에서 판단한다. 다른 DBMS의 실행 결과나 실제 성능 측정으로 일반화하지 않는다.
