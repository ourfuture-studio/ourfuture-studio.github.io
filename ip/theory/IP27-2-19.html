인덱스의 접근 경로와 유지 비용

관련 문제 1개조건 바꿔 체험

인덱스는 조회 결과를 바꾸지 않으면서 접근 경로를 추가한다. 빨라졌다는 판단에는 실제 계획과 시간이 필요하다.

핵심 이론

인덱스는 특정 열의 값을 통해 행을 찾는 보조 구조다. 전체를 훑기보다 적은 행을 찾는 조건에서 유용할 수 있지만, 어떤 경로를 사용할지는 DBMS의 통계와 비용 판단에 달려 있다.

일반 인덱스를 추가해도 동일한 데이터와 질의의 논리 결과는 같아야 한다. UNIQUE 인덱스처럼 추가 제약을 주는 경우는 별도이며, 이 예제는 비유일 score 인덱스를 사용한다.

삽입·삭제·인덱스 열 갱신에는 인덱스 유지 작업이 필요하다. 선택도, 정렬, 테이블 크기, 캐시, 쓰기 비중까지 확인해야 전체 성능을 판단할 수 있다. 여기서는 동일 결과와 작은 실행 계획을 확인할 뿐 처리 시간 향상을 측정하지 않는다.

작은 예제로 확인하기

Task는 id1~200이고 score=id%100이다. 아래 대표 질의에는 아직 score 보조 인덱스가 없다. 결과 시간은 측정하지 않는다.

id score 생성 규칙
1~200 id를 100으로 나눈 나머지
score=37 id 37,137

인덱스 유무와 관계없이 score=37의 결과는 id37·137이다. 인덱스를 만든 뒤 score를 바꾸면 새로운 값에 맞는 결과가 나와야 한다.

다시 떠올릴 단서

논리 결과의 동일성과 접근 경로·실제 실행 시간을 각각 확인한다.

적용 범위

명시한 작은 예제의 조건에서 판단한다. 다른 DBMS의 실행 결과나 실제 성능 측정으로 일반화하지 않는다.
