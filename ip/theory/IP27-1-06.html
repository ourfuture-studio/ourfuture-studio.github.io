핵심 이론

자료흐름도(DFD, Data Flow Diagram)는 처리 요소 사이에서 어떤 데이터가 이동하는지 표현한다. 화살표 이름은 이동하는 데이터의 의미를 붙인다.

주문 정보가 접수 처리에서 검증 처리로 흐른다는 사실만으로 검증의 실행 시각이나 다른 처리와의 전체 선후가 정해지지는 않는다.

실행 선후가 필요하면 제어 흐름이나 메시지 순서를 별도 명세한다. 데이터 이동 관계에 없는 시간 정보를 그림에서 추측하지 않는다.

자료흐름도의 네 요소

자료흐름도는 처리(Process), 자료 흐름(Data Flow), 자료 저장소(Data Store), 외부 개체·단말(External Entity / Terminator)을 구별한다. 이름 붙은 화살표는 자료가 이동하는 방향을 나타낸다.

구성 요소 전통적 원·평행선 표기의 기호 읽는 방법
처리(Process) 원 입력 자료를 어떤 자료로 바꾸는가
자료 흐름(Data Flow) 이름 붙은 화살표 어떤 자료를 어느 쪽으로 보내는가
자료 저장소(Data Store) 두 평행선 어느 자료를 보관하고 다시 읽는가
외부 개체(External Entity) 사각형 시스템 밖에서 자료를 주거나 받는 대상

표기법에 따라 처리를 둥근 사각형으로 그리거나 저장소 모양을 다르게 그리기도 한다. 도형의 변형보다 네 역할과 화살표의 자료 이름을 먼저 읽는다. 화살표만으로 작업 실행의 전체 선후를 결정하지 않는다.

작은 예제로 확인하기

자료흐름도에서 '접수 처리 → 검증 처리' 화살표에 '신청 데이터'라고 적혀 있다. 실행 시각·동시성·스케줄 조건은 별도로 없다.

조건 판단과 결과
접수→검증 화살표 이름=신청 데이터; 시간·제어 조건 없음. 신청 데이터의 전달 방향만 확정
검증→접수 화살표 이름=오류 목록; 시간·제어 조건 없음. 오류 목록이 검증에서 접수로 전달
접수→검증 화살표 이름=신청 데이터; 별도 실행 명세에 '접수 완료 후 검증 시작' 추가. 전달 관계와 별도 명세로 정한 선후 확인

화살표 출발은 접수, 도착은 검증이며 이름은 신청 데이터다. 따라서 전달 방향과 데이터 종류만 확정할 수 있다.

다시 떠올릴 단서

화살표의 데이터 이름을 읽고 시간 조건은 따로 찾는다.

적용 범위

DFD 표기 체계의 모든 문법이나 스케줄러를 구현하지 않는다.
