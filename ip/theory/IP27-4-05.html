브라우저 검증과 서버 신뢰 경계

관련 문제 1개조건 바꿔 체험

서버는 화면을 거치지 않은 요청도 받을 수 있다.

핵심 이론

입력 검증은 수신 값이 타입·범위·업무 조건을 만족하는지 확인한다. 브라우저 검사는 즉각적인 피드백을 주지만 서버의 신뢰 경계를 대신하지 않는다.

요청은 화면 코드를 우회해 전송될 수 있다. 서버가 사용할 값은 서버에서 다시 검증한다.

입력 검증이 SQL 매개변수화나 출력 문맥별 인코딩을 대신하지는 않는다. 값의 유효성과 사용 위치의 안전성을 나눠 다룬다.

작은 예제로 확인하기

신청 수량은 정수1~5만 허용한다. 브라우저는 이 범위를 검사하지만 서버는 검사 없이 값을 저장한다. 브라우저를 거치지 않은 자체 시험 요청 quantity=9가 서버에 도착한다.

조건 판단과 결과
허용=정수1~5; 브라우저 검사 존재; 서버에도 동일 규칙 추가; 우회 요청quantity=9. 서버 거부
허용=정수1~5; 브라우저 검사 존재; 서버에도 동일 규칙 추가; 우회 요청quantity=3. 검증 통과
허용=정수1~5; 브라우저 검사 존재; 서버에도 동일 규칙 추가; quantity는 숫자 아닌 문자열 'three'; 자동 변환 안 함. 서버 거부

수량9는 정수지만9≤5가 거짓이다. 서버가 직접 검증해 저장 전에 거부해야 화면 우회에도 규칙이 유지된다.

다시 떠올릴 단서

서버가 사용할 값은 서버에서 타입·범위·업무 규칙을 확인한다.

적용 범위

실서비스 요청을 보내지 않는 수량 검증 모형이다. 모든 공격을 입력 범위 검사 하나로 차단한다고 주장하지 않는다.
