MVC의 화면과 업무 규칙 책임

관련 문제 1개조건 바꿔 체험

화면 형식만 바뀌는 요구에서 책임의 경계를 확인한다.

핵심 이론

MVC는 Model·View·Controller로 책임을 나누는 패턴이다. 이 예제에서 Model은 업무 규칙과 상태, View는 표현, Controller는 요청 처리와 화면 선택을 맡는다.

금액의 표시 색이나 천 단위 구분자만 바꾸는 일과 할인율 계산을 바꾸는 일은 영향받는 책임이 다르다.

MVC가 모든 변경을 한 파일에 가둔다고 보장하지는 않는다. 계약이나 데이터가 달라지면 여러 책임을 함께 검토해야 한다.

작은 예제로 확인하기

가격 계산은 Model, 가격 표시 HTML은 View, 요청과 화면 선택은 Controller에 구현돼 있다. 계산 값·요청·반환 필드는 그대로 두고 가격 표시를 '12000'에서 '12,000원'으로만 변경한다.

조건 판단과 결과
Model=계산, View=표현, Controller=요청/선택; 값 12000 및 필드 동일; 표시만 12000→12,000원. View 변경
Model=계산, View=표현, Controller=요청/선택; 정가 10000; 할인율 10%→20%; 표시 형식 동일. Model 계산 변경; 금액 9000→8000
Model=계산, View=표현, Controller=요청/선택; 계산/표시 동일; 요청 완료 후 선택 화면만 A→B. Controller 선택 로직 변경

계산 값과 요청 계약이 고정돼 있다. 바뀐 것은 숫자를 화면에 표현하는 형식뿐이므로 View가 직접 변경 대상이다.

다시 떠올릴 단서

값 계산, 값 표현, 요청 흐름 중 실제로 달라진 항목을 찾는다.

적용 범위

명시한 MVC 책임 분담의 작은 모형이다. 모든 프레임워크의 파일 구조나 변경 범위를 일반화하지 않는다.
