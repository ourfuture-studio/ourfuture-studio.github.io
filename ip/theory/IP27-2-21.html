같은 행 재조회와 격리 수준

관련 문제 2개조건 바꿔 체험

다른 거래가 커밋한 뒤 같은 행을 다시 읽는 장면을 고정하면 읽기 현상을 구별할 수 있다.

핵심 이론

비반복 읽기(non-repeatable read)는 한 트랜잭션이 같은 행을 다시 읽을 때 다른 트랜잭션이 커밋한 변경으로 값이 달라지는 현상이다. 커밋 전의 값을 읽는 더티 읽기(dirty read), 조건에 맞는 행 집합이 달라지는 팬텀 읽기(phantom read)와 구분한다.

PostgreSQL 18의 Read Committed에서 일반 SELECT는 각 문장이 시작할 때의 커밋 상태를 본다. 두 SELECT 사이에 다른 거래가 커밋하면 첫 번째와 두 번째 값이 달라질 수 있다.

PostgreSQL 18의 Repeatable Read는 첫 비제어 문장 시점의 스냅샷을 유지해 여기의 단순 재조회가 다른 거래의 후속 커밋을 보지 않는다. 자신의 갱신, 잠금 읽기, 쓰기 충돌·재시도는 별도 규칙이다. 아래 일정은 명세를 따라 계산한 것이며 실제 동시 연결 실행은 아니다.

격리 수준(isolation level)과 허용 가능한 이상 현상

SQL 표준의 격리 수준 더티 읽기(Dirty Read) 비반복 읽기(Non-repeatable Read) 팬텀 읽기(Phantom Read)
READ UNCOMMITTED 가능 가능 가능
READ COMMITTED 방지 가능 가능
REPEATABLE READ 방지 방지 가능
SERIALIZABLE 방지 방지 방지

이 표는 표준의 허용 범위이며 각 제품이 실제로 반드시 이상 현상을 일으킨다는 뜻은 아니다. PostgreSQL 18은 READ UNCOMMITTED 요청도 READ COMMITTED로 처리하며, REPEATABLE READ에서 팬텀 읽기도 허용하지 않는다. 표의 세 현상을 막는 것과 모든 직렬화 이상(Serialization Anomaly)을 막는 것은 별도이므로 제품의 구현과 충돌 처리도 확인한다.

PostgreSQL 18: 같은 행을 두 번 읽기

작은 예제로 확인하기

PostgreSQL 18 명세. 초기 R(id=7,v=20) 한 행. T1은 READ COMMITTED에서 일반 SELECT로 id7을 읽는다. 이어 T2가 v25로 UPDATE하고 COMMIT한 뒤 T1이 같은 행을 다시 읽는다. T1의 쓰기·잠금 SELECT·그 밖의 거래는 없다.

순서 T1 T2
1 BEGIN READ COMMITTED; SELECT v →20
2 UPDATE v=25
3 COMMIT
4 같은 id SELECT →25

동일한 id 한 행의 값이 20에서 25로 바뀌므로 비반복 읽기다. 행 수 변화나 미커밋 읽기는 없다.

다시 떠올릴 단서

격리 수준, SELECT 시작 시점, 상대 거래의 커밋 순서를 함께 적는다.

적용 범위

PostgreSQL 18의 일반 SELECT와 명시한 일정에 한정한 명세 계산이다. 실제 두 세션 실행이나 다른 제품의 격리 구현 검증으로 표시하지 않는다.
