테스트 수준의 대상과 목적

관련 문제 2개조건 바꿔 체험

테스트를 한 사람보다 무엇을 확인했는지 먼저 본다.

핵심 이론

단위 테스트(unit test)는 분리된 구성요소, 통합 테스트(integration test)는 구성요소나 시스템의 상호작용, 시스템 테스트(system test)는 전체 시스템의 동작을 확인한다. 인수 테스트(acceptance test)는 사용자 업무 필요와 배포 준비를 확인하는 데 초점을 둔다.

ISTQB v4.0.1은 구성요소 통합과 시스템 통합을 나눠 다섯 수준으로 설명한다. 여기서는 이 둘을 통합이라는 상위 묶음으로 부른다.

개발자가 실행했다고 무조건 단위 테스트는 아니다. 테스트 대상·목적·근거가 수준을 구분하며 실제 일정에서 수준이 겹칠 수도 있다.

V-모델에서 개발 산출물과 테스트 기준 연결하기

V-모델(V-Model)은 개발 단계의 산출물과 대응하는 테스트 수준(Test Level)을 함께 읽는 방식이다. 계획한 산출물이 나중에 무엇을 검증할 기준이 되는지 연결한다.

개발 쪽 산출물·활동 대응하여 읽을 테스트 수준
사용자·업무 요구사항 분석 인수 테스트(Acceptance Testing)
시스템의 기능·동작 설계 시스템 테스트(System Testing)
구성 요소와 인터페이스의 구조 설계 통합 테스트(Integration Testing)
모듈 상세 설계·구현 단위·컴포넌트 테스트(Unit / Component Testing)

자료마다 개발 단계 이름은 조금씩 다를 수 있다. 같은 높이의 이름을 외우는 데서 멈추지 말고, 오른쪽 테스트가 왼쪽의 어떤 요구·인터페이스를 확인하는지 묻는다.

V-모델: 개발 단계와 테스트 수준의 짝

관련 문제풀이기존 조건 체험전체 도식 보기

작은 예제로 확인하기

접수 모듈과 결제 모듈은 각각 단독 시험을 끝냈다. 이번 시험은 두 실제 모듈을 연결해 요청 필드와 오류 응답의 교환이 맞는지만 확인한다. 전체 업무 인수 승인은 하지 않는다.

조건 판단과 결과
접수·결제 단독 시험 완료; 두 실제 모듈 연결; 요청/오류 교환 확인; 인수 승인 안 함. 구성요소 통합 테스트
시험 대상=결제 금액 함수 하나; 외부 의존 대체; 입력/출력만 확인; 전체 시스템 미연결. 단위 테스트
의도된 사용자가 완성 시스템에서 실제 신청→결제→취소 시나리오가 업무 필요를 충족하는지 확인하고 인수 여부 결정. 사용자 인수 테스트

이미 분리 시험을 마친 두 모듈의 연결을 확인한다. 대상은 인터페이스와 상호작용이므로 구성요소 통합 테스트다.

다시 떠올릴 단서

분리 요소, 연결, 전체 동작, 업무 수용 중 목적을 찾는다.

적용 범위

테스트 수준을 모든 프로젝트의 엄격한 시간 순서로 강제하지 않는다.
