스텁과 드라이버의 호출 방향

관련 문제 1개조건 바꿔 체험

시험 대상이 부르는 쪽과 시험 대상을 부르는 쪽을 나눈다.

핵심 이론

스텁은 시험 대상이 호출하는 하위 의존 모듈을 대신한다. 드라이버는 시험 대상을 호출하고 입력을 주는 상위 역할을 대신한다.

A→B에서 B를 시험하려고 A 대신 호출기를 만들면 드라이버다. A를 시험하려고 B 대신 고정 응답을 돌려주면 스텁이다.

같은 프로그램도 무엇을 시험 대상으로 삼는지에 따라 보조물의 역할이 달라진다. 위아래 위치를 절대적인 이름으로 외우지 않는다.

작은 예제로 확인하기

호출 관계는 A→B→C다. 시험 대상은 B이며 C는 미구현이다. B가 C를 부르면 고정 결과를 반환하는 대체물 X를 만든다. A의 대체는 묻지 않는다.

조건 판단과 결과
A→B→C; 시험 대상=B; C 미구현; X는 B의 호출에 고정 응답 반환. X는 스텁
A→B→C; 시험 대상=B; A 미구현; X가 입력을 만들어 B 호출 후 결과 기록; C 사용 가능. X는 드라이버
A→B→C; 시험 대상=A; B 미구현; X가 A의 B 호출에 고정 응답 반환. X는 스텁

시험 대상 B에서 X로 호출이 나간다. X는 미구현 C의 응답을 대신하므로 스텁이다.

다시 떠올릴 단서

대상을 부르면 드라이버, 대상에게 불리면 스텁이다.

적용 범위

스텁·목·페이크의 모든 테스트 더블 분류를 한 가지로 합치지 않는다.
