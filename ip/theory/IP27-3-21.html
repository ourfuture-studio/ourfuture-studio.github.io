해시 충돌과 키의 동등성

관련 문제 1개조건 바꿔 체험

같은 버킷에 도착해도 원래 키를 다시 비교해야 한다.

핵심 이론

해시 함수 h(k)는 키를 버킷 위치 등 작은 범위의 값으로 대응시킨다. 서로 다른 키 k1,k2가 같은 해시값을 가지는 것을 충돌이라고 한다. 작은 버킷 수에서는 서로 다른 입력이 같은 위치로 갈 수 있다.

이 예제는 정수 키와 h(k)=k mod 5, 별도 체인법을 사용한다. 별도 체인은 버킷마다 키 목록을 두는 방식이다. 6과11은 모두 버킷1에 들어가지만 서로 다른 정수 키이다.

조회는 해시로 버킷을 고른 뒤 그 버킷의 원래 키들을 동등성 비교해야 한다. 암호학적 충돌 저항성이나 Java의 실제 HashMap 내부 구현을 이 작은 모형으로 검증한 것은 아니다.

작은 예제로 확인하기

Python 3.13, UTF-8 독립 스크립트, 외부 입력 없음. 키6,11을 버킷5개에 저장, h(k)=k%5. query=16의 버킷번호와 포함 여부를 출력한다.

조건 또는 단계 판단 또는 값
h(6) 1
h(11) 1
버킷1의 키 6,11 두 개
query=16 같은 버킷이나 저장 안 됨

나머지 연산과 실제 키 비교를 각각 수행하면 충돌을 같은 키로 오해하지 않는다.

다시 떠올릴 단서

해시는 후보 위치를 좁히고 키 비교가 일치를 확정한다.

적용 범위

비음수 정수, 버킷5개, 중복 키 없는 삽입, 별도 체인법의 자체 모형이다.

근거와 확인 범위

  • Java SE 17 Object.hashCode contract — hashCode 일반 계약: equals인 객체의 같은 해시; 서로 다른 객체의 다른 해시는 요구하지 않음. 확인일 2026-10-31.
