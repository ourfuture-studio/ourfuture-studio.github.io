괄호로 해결되지 않는 C의 비순서 부수효과

관련 문제 1개조건 바꿔 체험

한 식에서 같은 변수를 바꾸고 읽을 때는 숫자를 따라가기 전에 순서 보장을 검사한다.

핵심 이론

부수효과는 변수 값을 바꾸는 것처럼 실행 상태를 변경하는 효과이다. i++는 이전 값을 식에 제공하면서 i를 증가시킨다. 읽기와 변경 사이의 순서가 보장되는지는 연산자별 규칙으로 판단한다.

C11에서 같은 스칼라 객체의 변경과 그 값을 사용하는 계산이 서로 비순서이면 동작이 정의되지 않는다(UB). i++ + i의 +는 두 피연산자 사이에 필요한 순서를 만들지 않는다. 괄호로 (i++) + i로 묶어도 해결되지 않는다.

문장 끝 세미콜론으로 완전식을 분리하거나 &&처럼 순서를 보장하는 연산자의 조건을 정확히 사용하면 흐름을 추적할 수 있다. UB 프로그램에서 한 번 관찰한 출력은 언어가 보장한 정답이 아니다.

작은 예제로 확인하기

C11 의미 규칙(N1570), signed int이며 아래 작은 값에서 범위 초과 없음. 각 코드는 표준 헤더와 main을 포함한 독립 프로그램이고 입력 없음. 0으로 나누지 않는다. i++ + i를 사용한다.

조건 또는 단계 판단 또는 값
i++ + i 같은 i의 변경·읽기가 비순서
int old=i++; 다음 문장 old+i 두 완전식 사이의 순서 보장
(i++) + i 괄호만 추가해도 UB 유지

이 문제의 판단 대상은 특정 컴파일러 출력이 아니라 표준의 순서 규칙이다.

다시 떠올릴 단서

적용 범위

UB 사례는 컴파일 진단과 명세로 검토하고 실행 숫자를 정답으로 사용하지 않는다.
