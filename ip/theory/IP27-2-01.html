2과목 · 2-01 · 이론 읽기

응용의 열을 유지하고 저장 방법 바꾸기

관련 문제 1개조건 바꿔 체험

인덱스를 추가해도 응용이 읽는 열을 바꿀 필요는 없다. 무엇이 바뀌었는지 스키마 층으로 나누어 보자.

핵심 이론

스키마는 데이터베이스의 구조를 정한 설명이다. 외부 스키마는 사용자가 보는 일부 구조, 개념 스키마는 전체 논리 구조, 내부 스키마는 파일 배치와 접근 경로 같은 저장 구조를 나타낸다.

물리 데이터 독립성은 내부 저장 구조를 바꾸면서 논리 구조를 유지할 수 있는 성질이다. 예를 들어 같은 Member(id, name)를 조회하면서 name 인덱스를 추가하는 변경은 열의 의미를 바꾸지 않는다.

논리 데이터 독립성은 개념 구조의 변경을 외부 뷰나 응용 인터페이스가 흡수하는 문제다. 열 이름을 없애거나 의미를 바꾸면 응용까지 고쳐야 할 수 있다. 인덱스 추가가 모든 질의의 속도를 높인다는 뜻도 아니다.

작은 예제로 확인하기

회원 관계 Member(id, name)의 열·자료형·값 의미와 응용의 SELECT id,name을 유지한다. 변경은 name에 대한 보조 인덱스 추가뿐이다.

층 변경 전 변경 후
응용 조회 SELECT id,name SELECT id,name
논리 열 id,name id,name
저장 접근 테이블 스캔 name 인덱스 추가

조회 대상과 열 의미는 같고 접근 경로만 추가되므로 물리 데이터 독립성에 해당한다.

다시 떠올릴 단서

저장 방법의 변경인지, 응용이 읽는 열과 의미의 변경인지 나누어 본다.

적용 범위

명시한 작은 예제의 조건에서 판단한다. 다른 DBMS의 실행 결과나 실제 성능 측정으로 일반화하지 않는다.
