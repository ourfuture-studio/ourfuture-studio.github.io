생성 책임과 인스턴스 수 제한

관련 문제 1개조건 바꿔 체험

생성 창구를 모으는 것만으로 객체가 하나가 되지는 않는다.

핵심 이론

팩터리는 생성할 객체를 정하는 책임을 모으는 방식이다. 싱글턴은 지정한 범위에서 인스턴스를 하나로 제한하려는 패턴이다.

이 예제의 생성 함수가 호출마다 새 객체를 만들면 호출자가 직접 생성하지 않아도 객체 수는 늘어난다.

싱글턴의 범위와 동시성 조건은 구현에 따라 명시해야 한다. 생성 메서드의 이름이 같다는 이유로 전역 유일성을 추정하지 않는다.

작은 예제로 확인하기

단일 프로세스·단일 스레드 모형이다. create()는 호출마다 서로 다른 새 객체를 반환하며 캐시는 없다. create()를 두 번 호출한 뒤 반환 객체를 모두 유지한다.

조건 판단과 결과
단일 프로세스/스레드; create는 매번 새 객체; 캐시 없음; 두 번 호출하고 모두 유지. 유지 객체 2개
단일 프로세스/스레드; create는 첫 호출만 생성하고 이후 같은 캐시 반환; 두 번 호출해 모두 유지. 유지 객체 1개
단일 프로세스/스레드; create는 매번 새 객체; 캐시 없음; 세 번 호출해 모두 유지. 유지 객체 3개

새 객체를 두 번 만들고 둘 다 유지하므로 객체 수는 2다. 생성 창구의 집중과 인스턴스 수 제한은 별개다.
