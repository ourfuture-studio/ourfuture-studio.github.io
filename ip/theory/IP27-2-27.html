ETL 성공 뒤 행·키·단위를 대조하기

관련 문제 1개조건 바꿔 체험

적재 작업이 끝났다는 상태와 값이 맞게 옮겨졌다는 검증은 따로 확인해야 한다.

핵심 이론

데이터 전환은 원본을 읽고 필요한 변환을 적용해 대상으로 옮기는 작업이다. 이 예제의 변환 계약은 원본의 센트 단위 정수를 100으로 나누어 대상의 통화 단위 값으로 저장하는 것이다.

작업 완료 표시는 명령이 끝났음을 알려 줄 수 있지만 행 누락·키 중복·변환 값 오류를 모두 배제하지는 않는다. 행 수, 키 대응, 고유성, NULL, 값과 단위를 계약에 맞춰 대조해야 한다.

행 수가 같아도 한 키가 두 번 들어가고 다른 키가 빠질 수 있다. 키가 모두 있어도 금액을 100으로 나누지 않으면 값은 틀린다. 아래 예제는 SQLite의 작은 대조 질의를 실행하며 AWS DMS나 실제 운영 전환의 성공을 주장하지 않는다.

작은 예제로 확인하기

전환 작업의 상태는 성공이다. 원본 (1,1250),(2,2750)의 cents를 100.0으로 나누어 amount_units에 저장해야 한다. 실제 대상은 (1,1250),(2,2750)으로 적재되었다. 대상은 검증 전이므로 id 고유 제약을 아직 두지 않았다.

id 원본 cents 계약상 대상 amount_units 현재 대상
1 1250 12.5 1250
2 2750 27.5 2750

두 행과 키는 맞지만 변환을 생략해 금액 불일치가 두 건이다. 작업 성공·행 수 일치만으로 전환 정확성을 승인하면 안 된다.

다시 떠올릴 단서

완료 상태와 별도로 행 수, 키 대응, 중복, 단위 변환을 대조한다.

적용 범위

명시한 작은 예제의 조건에서 판단한다. 다른 DBMS의 실행 결과나 실제 성능 측정으로 일반화하지 않는다.
