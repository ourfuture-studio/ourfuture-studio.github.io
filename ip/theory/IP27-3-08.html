오버로드를 고른 뒤 오버라이드를 찾기

관련 문제 1개조건 바꿔 체험

호출 시그니처는 컴파일 시점 자료형으로 고르고, 재정의 구현은 실제 객체로 고른다.

핵심 이론

오버로딩은 같은 이름에 서로 다른 매개변수 목록을 두는 것이다. A의 f(Object)와 f(String) 중 무엇을 부를지는 인자 표현식의 컴파일 시점 자료형 등으로 결정한다.

오버라이딩은 상속받은 인스턴스 메서드의 구현을 자식 클래스가 재정의하는 것이다. 선택된 시그니처가 f(Object)이고 실제 수신 객체가 B이면 B가 재정의한 f(Object)를 실행한다.

Object x="sun"의 실제 내용이 문자열이어도 x의 선언형은 Object이다. 이 조건만으로 f(String)을 다시 선택하지 않는다. static 메서드·private 메서드·제네릭·가변 인자는 제외해 두 단계 규칙을 확인한다.

작은 예제로 확인하기

Java SE 17, Main.java로 저장. java.lang은 자동 import하며 외부 입력·다중 스레드·사용자 정의 예외 처리 없음. A a=new B(); Object x="sun".

조건 또는 단계 판단 또는 값
참조 A a=new B() 실제 수신 객체 B
인자 Object x="sun" 시그니처 f(Object)
실행 구현 B.f(Object) → BO

오버로드 선택의 입력과 오버라이드 선택의 입력을 따로 적는다.

다시 떠올릴 단서

먼저 시그니처, 다음 실제 객체의 재정의 구현을 고른다.

적용 범위

예제는 접근 가능한 일반 인스턴스 메서드만 사용한다.
