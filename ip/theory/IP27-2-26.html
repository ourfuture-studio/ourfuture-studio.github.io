PostgreSQL에서 범위 분할과 CLUSTER 구별하기

관련 문제 1개조건 바꿔 체험

제품을 정하면 같은 단어가 가리키는 저장 동작을 더 정확하게 비교할 수 있다.

핵심 이론

PostgreSQL 18의 범위 파티셔닝은 논리적으로 하나인 테이블의 행을 범위별 물리 조각에 배치한다. 예를 들어 [10,20)는 10 이상 20 미만을 뜻해 경계값 10은 이 파티션에 들어간다.

같은 제품의 CLUSTER는 이미 있는 인덱스를 기준으로 테이블의 물리 배치를 한 번 재정렬하는 명령이다. 이 명령만으로 행을 여러 범위 파티션으로 나누는 것은 아니다.

CLUSTER 뒤 새 행을 넣거나 값을 바꾼다고 그 물리 순서가 계속 자동 유지되는 것은 아니다. 어떤 물리 배치든 SELECT의 결과 순서를 요구하려면 ORDER BY를 써야 한다. 다른 제품의 클러스터형 인덱스·클러스터 테이블 용어와 동일한 기능으로 묶지 않는다.

작은 예제로 확인하기

PostgreSQL 18 명세에서 P는 k의 [0,10),[10,20),[20,30) 범위로 분할한다. U는 별개 테이블이고 기존 k 인덱스를 사용해 CLUSTER를 한 번 수행한다.

대상 규칙
P0 0≤k<10
P1 10≤k<20
P2 20≤k<30
CLUSTER U U를 idx_u_k 기준으로 일회성 물리 재배열

k12는 P1 범위에 들어간다. CLUSTER는 이 범위 분배 규칙과 다른 저장 작업이다.

다시 떠올릴 단서

행의 범위 배치와 인덱스에 따른 물리 재배열을 구별한다.

적용 범위

PostgreSQL 18 공식 명세와 범위 계산의 사례다. 실제 파티션 생성·CLUSTER 실행·물리 페이지 관찰·시간 측정은 수행하지 않았다.
