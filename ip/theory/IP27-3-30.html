최장 프리픽스와 짧은 메트릭의 비교 순서

관련 문제 1개조건 바꿔 체험

전달표에 설치된 유효 경로들 중 목적지와 가장 길게 일치하는 프리픽스를 고른다.

핵심 이론

프리픽스 길이가 길수록 더 작은 주소 범위를 지정한다. /25는 128개 주소, /24는 256개 주소를 포괄한다. 목적지가 두 범위에 모두 포함되면 /25가 더 구체적이다.

일반적인 목적지 기반 전달에서 최장 프리픽스 일치가 우선이다. 이미 설치된 유효 경로 0/0, 192.0.2.0/24, 192.0.2.128/25에 목적지 192.0.2.140이 모두 맞으면 /25를 선택한다.

메트릭은 경로의 비용 등을 나타내는 값으로 동일 프리픽스에 대한 후보 선택 등에서 쓰인다. 모든 프로토콜의 메트릭 숫자를 무조건 서로 비교하는 것은 아니다. 정책 라우팅·서비스 종류별 선택·다중 경로·경로 설치 과정은 제외하고 명시한 단순 전달표만 비교한다.

작은 예제로 확인하기

Python 3.13으로 검산한다. 유효 전달표는 0.0.0.0/0→A(메트릭 1), 192.0.2.0/24→B(50), 192.0.2.128/25→C(100)이다. 목적지는 192.0.2.140이다. 모든 경로는 이미 설치되어 있고 정책 라우팅은 없다.

조건 또는 단계 판단 또는 값
기본경로 /0→A 메트릭1
192.0.2.0/24→B 메트릭50
192.0.2.128/25→C 메트릭100
목적지140 모두일치→가장긴/25

가장 작은 메트릭 1로 바로 선택하지 않고 먼저 일치하는 프리픽스 길이를 비교한다.

다시 떠올릴 단서

경로 설치의 우선순위와 전달 시 최장 프리픽스 일치를 구별한다.

적용 범위

모든 표 항목은 유효하게 설치된 경로이다. 목적지 기반 일반 전달이며 정책·서비스 종류별 선택·다중 경로는 없다. 같은 길이 경로의 동률은 이 예제에 없다.

근거와 확인 범위

  • RFC 1812 Requirements for IP Version 4 Routers — 5.2.4.3 Route Lookup의 최장 일치; 동일 길이 경로의 후속 선택과 구분. 확인일 2026-10-31.
  • RFC 4632 CIDR — 3.1 Basic Concept and Prefix Notation의 32비트 주소와 프리픽스 표기. 확인일 2026-10-31.
