클래스와 개별 객체의 상태

관련 문제 1개조건 바꿔 체험

설계가 같아도 생성한 두 객체의 상태는 다를 수 있다.

핵심 이론

클래스는 객체의 상태와 동작을 정의하는 틀이다. 인스턴스는 그 클래스로 만든 개별 객체이며, 이 예제의 인스턴스 필드는 객체마다 따로 가진다.

같은 Seat 클래스로 좌석 a와 b를 만들더라도 a의 예약 상태 변경이 곧 b의 상태 변경을 뜻하지 않는다.

두 변수가 같은 객체를 가리키는 경우에는 상태를 공유한다. 클래스가 같다는 것과 객체의 동일성이 같다는 것을 나눈다.

작은 예제로 확인하기

언어 중립 객체 모형이다. Seat의 reserved는 공유 변수가 아닌 인스턴스 상태이며 초기값은 false다. a와 b는 각각 새로 생성한 서로 다른 Seat다. a.reserved만 true로 바꾼다.

조건 판단과 결과
Seat.reserved 초기 false, 인스턴스별 필드; a=새 객체1, b=새 객체2; a.reserved=true. a=true, b=false
Seat.reserved 초기 false, 인스턴스별 필드; a=새 객체1, b=a; a.reserved=true. a=true, b=true
Seat.reserved 초기 false, 인스턴스별 필드; a=새 객체1, b=새 객체2; b.reserved=true. a=false, b=true

새 객체가 두 개이고 필드는 인스턴스별이다. a에만 변경이 적용되므로 a는 true, b는 초기값 false다.

다시 떠올릴 단서

같은 클래스인지와 같은 객체인지 따로 확인한다.
