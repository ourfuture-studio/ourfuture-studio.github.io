버전 이력과 승인 기준선

관련 문제 1개조건 바꿔 체험

변경이 저장됐는지와 출시 구성이 승인됐는지는 따로 확인한다.

핵심 이론

버전관리는 파일의 변경 이력을 기록해 특정 상태를 다시 찾게 한다. 형상관리는 식별한 항목과 기준선, 변경 통제 등을 관리한다.

커밋이 존재해도 해당 코드·설정·매뉴얼 조합이 승인된 출시 기준선이라는 뜻은 아니다.

이 예제에서는 출시 구성 목록과 승인 기록을 별도로 요구한다. 파일명에 '최종'을 붙이는 것만으로 이력이나 승인 관계가 생기지는 않는다.

작은 예제로 확인하기

출시 규칙은 승인 기록에 코드 커밋·설정 버전·매뉴얼 버전이 모두 연결돼야 한다. 코드 c2·설정 s1·매뉴얼 m1은 저장소에 있지만 승인 기록은 c1/s1/m1만 가리킨다.

조건 판단과 결과
출시 승인 규칙=코드/설정/매뉴얼 전부 연결; 대상 c2/s1/m1; 승인 c1/s1/m1. 대상 조합 미승인
출시 승인 규칙=코드/설정/매뉴얼 전부 연결; 대상 c2/s1/m1; 승인 c2/s1/m1. 대상 조합 승인 확인
출시 승인 규칙=코드/설정/매뉴얼 전부 연결; 대상 c2/s2/m1; 승인 c2/s1/m1. 대상 조합 미승인

승인 조합은 c1/s1/m1이고 대상은 c2/s1/m1이다. 코드 버전이 다르므로 대상 조합의 승인은 별도 확인해야 한다.

다시 떠올릴 단서

버전 존재와 구성 조합 승인을 따로 확인한다.

적용 범위

출시 규칙은 자체 조직 가정이며 Git 커밋을 실제로 작성하거나 배포하지 않는 비교 예제다.
