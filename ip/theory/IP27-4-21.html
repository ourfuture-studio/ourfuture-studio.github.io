SDN의 규칙 결정과 패킷 전달

관련 문제 1개조건 바꿔 체험

제어기에서 규칙을 바꿔도 실제 패킷을 내보내는 동작은 데이터 평면 장비가 수행한다.

핵심 이론

SDN은 네트워크의 제어 기능과 데이터 전달 기능을 분리해 프로그래밍 가능한 인터페이스로 연결하는 구조다. 제어 평면은 정책·요구에 따라 전달 동작을 정하고 장비의 규칙을 설정할 수 있다.

데이터 평면의 스위치 등은 설치된 규칙에 따라 패킷을 전달·버리는 동작을 수행한다. 모든 패킷을 반드시 제어기 프로세스가 직접 받아서 내보낸다는 뜻은 아니다.

논리적으로 집중된 제어가 반드시 물리 서버 한 대를 뜻하지 않는다. 장비에 위임할 기능, 규칙 만료, 제어기 단절 시 행동도 설계 조건이다. 아래 예제는 기존 규칙을 유지하도록 명시한 작은 전달 표 모형이며 실제 OpenFlow 장비를 동작시키지 않는다.

작은 예제로 확인하기

가상 스위치S에는 목적지X→포트2 규칙이 이미 설치되어 있다. 제어기는 연결되어 기존 규칙을 유지하며, 목적지X 패킷 하나가 도착한다. 규칙 만료·링크 장애는 없다.

구성 대표 동작
제어기 목적지X 규칙 결정·설치
스위치S 규칙에 따라 포트2로 전달

제어기는 규칙을 정하고 스위치는 패킷을 전달한다. 기존 규칙이 유효하면 모형에서 새 제어기 왕복 없이 전달할 수 있다.

다시 떠올릴 단서

규칙을 정하는 제어 기능과 규칙을 적용하는 패킷 전달 기능을 구분한다.

적용 범위

규칙 설치·조회 모형만 계산했다. 실제 제어기·스위치·OpenFlow 통신·장애 전환이나 처리 성능 검증이 아니다.
