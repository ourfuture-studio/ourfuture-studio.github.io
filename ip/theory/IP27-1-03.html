include와 extend의 방향과 실행 조건

관련 문제 1개조건 바꿔 체험

공통 동작 포함과 확장점의 추가 동작을 구분한다.

핵심 이론

유스케이스는 행위자에게 가치 있는 결과를 주는 시스템 동작을 기술한다. include는 다른 유스케이스의 동작을 포함하며 화살표는 포함하는 쪽에서 포함되는 쪽으로 향한다.

extend는 확장 유스케이스가 기본 유스케이스의 확장점에 동작을 삽입하는 관계다. 기본 유스케이스는 확장 없이도 의미가 완결된다.

'항상'과 '가끔'만으로 외우지 않는다. UML 2.5는 조건이 생략된 extend도 허용하므로 기본 동작의 완결성과 관계 방향을 함께 읽는다.

작은 예제로 확인하기

주문 완료 유스케이스는 쿠폰 처리 없이도 완결된다. 할인 쿠폰 적용 유스케이스는 주문 완료의 '금액 확정 전' 확장점에서 '유효 쿠폰이 있음'일 때만 실행된다. 두 유스케이스 사이 관계를 표시한다.

조건 판단과 결과
주문 완료는 쿠폰 없이 완결. 쿠폰 적용은 '금액 확정 전' 확장점에서 유효 쿠폰이 있을 때만 삽입된다. 쿠폰 적용 → 주문 완료, extend
대출 신청과 대출 연장은 모두 본인 확인 동작 전체를 반드시 포함한다. 이를 공통 유스케이스로 분리한다. 각 대출 유스케이스 → 본인 확인, include
보고서 출력은 로고 없이도 완결된다. 로고 삽입을 출력의 확장점에 extend로 명시하고 조건은 생략한다. 명세상 조건 없는 extend

기본 주문은 쿠폰 없이 완결되고, 명명된 확장점과 실행 조건이 있다. 쿠폰 적용이 주문 완료를 확장하므로 쿠폰 적용에서 주문 완료로 extend를 표시한다.

다시 떠올릴 단서

포함되는 공통 동작인지, 완결된 기본 동작의 확장점인지 먼저 본다.

적용 범위

조건을 검사하는 시점과 확장점은 명세에 따른다. 실제 인증 세션의 재사용 정책을 유스케이스 관계만으로 확정하지 않는다.
