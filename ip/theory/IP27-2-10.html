삭제 대상을 먼저 고정하는 DELETE·TRUNCATE·DROP

관련 문제 1개조건 바꿔 체험

무엇을 지울지와 어떤 DBMS인지부터 적으면 삭제 명령의 차이가 선명해진다.

핵심 이론

PostgreSQL 18에서 DELETE는 WHERE 조건에 맞는 행을 삭제하고 조건이 없으면 모든 행을 삭제한다. 테이블 정의는 남는다. DELETE 다음에 열 목록을 쓰는 방식으로 특정 열만 지우지는 않는다.

TRUNCATE는 지정한 테이블 전체를 비우며 WHERE를 받지 않는다. PostgreSQL에서는 명시적 트랜잭션이 커밋되기 전에 롤백하면 TRUNCATE로 지운 데이터도 복구된다. 이 규칙을 다른 DBMS의 자동 커밋 규칙에 그대로 옮기면 안 된다.

DROP TABLE은 테이블 정의 자체를 제거한다. 의존 객체·참조 제약·잠금·트리거·시퀀스 처리는 별도 조건을 가진다. 이 예제는 그런 객체가 없는 테이블로 한정해 행과 구조의 차이만 비교한다.

작은 예제로 확인하기

PostgreSQL 18 명세 사례다. T(id integer)에 1,2,3의 세 행만 있고 제약·의존 뷰·트리거·상속·시퀀스는 없다. 각 사례는 새 T에서 시작하며 필요한 권한이 있다. 서버 실행은 하지 않았다.

요청 직접 맞는 명령
id=2인 행만 제거 DELETE ... WHERE id=2
모든 행 제거, 구조 유지 TRUNCATE
구조 자체 제거 DROP TABLE

세 요청의 차이는 행의 범위를 제한하는지와 테이블 정의를 남기는지다.

다시 떠올릴 단서

삭제할 행의 범위와 테이블 정의를 남길지를 먼저 정한다.

적용 범위

PostgreSQL 18 문서에 따른 명세 판단이다. PostgreSQL 서버 실행·시간 측정·다른 DBMS의 롤백 가능성 검증으로 표현하지 않는다.
