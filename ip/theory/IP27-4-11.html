비밀번호 KDF와 솔트의 역할

관련 문제 1개조건 바꿔 체험

솔트는 복호화 키가 아니라 사용자별 입력을 구분하는 값이다.

핵심 이론

비밀번호 저장에는 검증된 비밀번호 해시/KDF를 사용해 입력을 검증용 값으로 변환한다. KDF는 키 유도 함수라는 뜻이며 여기서는 비밀번호 기반 유도 함수를 말한다.

솔트는 비밀번호와 함께 KDF에 들어가는 사용자별 값이다. 서로 다른 솔트는 같은 비밀번호라도 입력 조합을 다르게 하며, 솔트 자체가 비밀 복호화 키는 아니다.

서로 다른 입력이 모든 경우에 다른 출력을 보장한다는 뜻은 아니다. 아래는 고정한 시험용 입력의 실제 결과이며 생산 환경에서 솔트를 고정하라는 권고가 아니다.

작은 예제로 확인하기

Python3.13.9 hashlib.pbkdf2_hmac('sha256',password,salt,600000,dklen=16)을 사용한다. password/salt는 ASCII 바이트다. 두 계정의 password는 모두 'same-pass', 솔트는 각각 'salt-A-000000001'과 'salt-B-000000002'이다. 고정 솔트는 재현용 시험값이다.

조건 판단과 결과

Python3.13.9; PBKDF2-HMAC-SHA256,600000회,dklen16; 계정1=(ASCII same-pass,salt-A-000000001),계정2=(ASCII same-pass,salt-A-000000001). 두 값 모두83be0607a38181e2114b974fe5327de1
Python3.13.9; PBKDF2-HMAC-SHA256,600000회,dklen16; 계정1=(ASCII same-pass,salt-A-000000001),계정2=(ASCII other-pass,salt-A-000000001). 83be0607a38181e2114b974fe5327de1 / eff3ed4c3f0b79a1f533380bc3230499

두 계정은 비밀번호가 같아도 salt 인수가 다르다. 실행 결과는83be0607a38181e2114b974fe5327de1과39dd32431e432be5f379055c75c6f3b7로 달랐다. 이는 솔트의 입력 구분 역할이며 복호화 기능이 아니다.

다시 떠올릴 단서

솔트·비밀번호·비용 설정의 입력을 구분하고 복호화라는 말을 붙이지 않는다.

적용 범위

고정 바이트·반복 횟수·출력 길이는 재현 시험의 조건이다. 실제 비밀번호 저장 설계는 라이브러리·비용·솔트 생성·접근통제를 함께 정해야 한다.
