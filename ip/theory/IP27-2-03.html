2과목 · 2-03 · 이론 읽기

유일성 다음에 최소성 검사하기

관련 문제 1개조건 바꿔 체험

중복 없이 식별한다는 사실만으로 후보키가 되지는 않는다. 속성을 덜어도 식별되는지 확인해야 한다.

핵심 이론

슈퍼키는 모든 적법한 데이터에서 행을 유일하게 식별하는 속성 집합이다. 후보키는 그중 불필요한 속성이 없는 최소 슈퍼키다. 최소성은 글자 수가 전역적으로 가장 짧다는 뜻이 아니라 진부분집합이 슈퍼키가 아니라는 뜻이다.

함수 종속 X→Y는 X가 같으면 Y도 같아야 한다는 제약이다. X의 폐쇄 X+는 종속을 반복 적용해 X로 결정할 수 있는 모든 속성이다. X+가 전체 속성이면 X는 슈퍼키이고, 속성을 하나씩 빼서 최소성을 검사한다.

현재 표본에서 이메일이 우연히 중복되지 않는 것과 이메일을 키로 보장하는 업무 제약은 다르다. SQL UNIQUE의 NULL 처리도 제품에 따라 달라지므로 이 예제는 NULL 없는 수학적 관계와 명시한 종속만 사용한다.

작은 예제로 확인하기

NULL 없는 관계 R(M,E,N)에서 성립하는 FD는 M→EN, E→M이며 이들로부터 추론되는 종속뿐이다. M은 회원번호, E는 이메일, N은 이름이다.

속성 집합 폐쇄 판단
{M} {M,E,N} 후보키
{E} {M,E,N} 후보키
{M,N} {M,E,N} 최소성 없음

M만으로 전체 속성을 결정하므로 {M,N}은 N을 제거해도 슈퍼키다. 따라서 후보키가 아니다.

다시 떠올릴 단서

전체 속성을 결정하는지 확인한 뒤 속성을 빼도 되는지 검사한다.

적용 범위

명시한 작은 예제의 조건에서 판단한다. 다른 DBMS의 실행 결과나 실제 성능 측정으로 일반화하지 않는다.
