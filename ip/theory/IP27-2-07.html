BCNF는 모든 비자명 종속의 결정자를 검사한다

관련 문제 1개조건 바꿔 체험

기본키를 골랐다는 사실만으로 다른 결정자가 사라지지 않는다. 결정자가 전체 행을 식별하는지 계산하자.

핵심 이론

결정자는 함수 종속의 왼쪽 속성 집합이다. BCNF는 모든 비자명 FD X→Y에서 X가 슈퍼키일 것을 요구한다. 비자명은 Y가 X에 이미 포함되어 있지 않다는 뜻이다.

3정규형은 모든 비자명 FD X→Y에서 X가 슈퍼키이거나, 우변 중 X에 포함되지 않은 각 속성(Y-X)이 주요 속성인 경우를 허용한다. 주요 속성은 적어도 하나의 후보키에 포함되는 속성이다. 그래서 3NF를 만족하면서 BCNF는 위반하는 스키마가 가능하다.

BCNF의 결정자는 반드시 최소 후보키일 필요는 없다. 후보키에 다른 속성을 덧붙인 슈퍼키도 조건을 만족한다. 전체 FD의 논리적 귀결을 고려하되 속성 폐쇄를 이용하면 작은 예제에서 검사할 수 있다.

작은 예제로 확인하기

NULL 없는 관계 R(A,B,C)에서 F={AB→C,C→B}와 그 논리적 귀결만 성립한다. 모든 속성값은 원자적이다.

항목 계산
R(A,B,C)의 FD AB→C, C→B
후보키 AB, AC
C+ BC

C→B의 C는 A를 결정하지 못한다. B가 주요 속성이므로 3NF는 가능하지만 BCNF는 위반한다.

다시 떠올릴 단서

비자명 종속의 결정자가 슈퍼키인지 먼저 검사하고 3NF의 주요 속성 예외를 확인한다.

적용 범위

명시한 작은 예제의 조건에서 판단한다. 다른 DBMS의 실행 결과나 실제 성능 측정으로 일반화하지 않는다.
