출력 위치에 맞춘 XSS 방어

관련 문제 1개조건 바꿔 체험

같은 문자열도 텍스트·URL·스크립트 위치에서 다르게 해석된다.

핵심 이론

XSS는 신뢰하지 않는 내용이 브라우저에서 코드 등으로 해석되는 문제다. 출력 인코딩은 값을 넣는 문맥에 맞춰 데이터로 표현한다.

HTML 본문의 텍스트와 링크 URL은 같은 문맥이 아니다. URL 전체를 받을 때는 허용할 스킴을 검증하고 속성에 넣을 때는 따옴표와 속성 인코딩도 적용한다.

텍스트를 보여 주려면 일반 div 요소의 textContent 같은 안전한 출력 경로를 사용할 수 있다. HTML 인코딩 한 번이 모든 위치의 안전을 보장한다고 일반화하지 않는다.

작은 예제로 확인하기

사용자가 입력한 전체 URL을 따옴표로 둘러싼 a 요소의 href에 넣는다. 서비스 정책은 https URL만 허용한다. 입력 URL의 스킴은 javascript다. 현재 구현은 HTML 속성 인코딩만 하고 스킴 검증은 없다.

조건 판단과 결과
전체 URL을 quoted href로 출력; 허용 스킴=https만; 입력 스킴=javascript; 스킴 검증 후 허용 URL만 속성 인코딩. 입력 거부
전체 URL https://example.test/page 를 quoted href로 출력; 허용 스킴=https만; 스킴 검증 후 허용 URL만 속성 인코딩. 정책상 허용 후 속성 인코딩
사용자 문자열 '<b>안내</b>'를 링크나 HTML로 실행하지 않고 일반 본문 텍스트로 표시하려 한다. textContent로 대입한다. 태그가 아닌 글자 <b>안내</b>로 표시

입력 스킴은 정책의 https와 다르므로 거부한다. 허용되는 URL을 출력할 때도 따옴표로 감싼 속성 문맥에 맞는 인코딩을 유지한다.

다시 떠올릴 단서

값을 넣는 문맥과 그 위치에서 해석되는 의미를 함께 검사한다.

적용 범위

스킴만 검사하면 모든 링크 위험이 사라진다는 뜻은 아니다. 실제 DOM 실행이나 공격 서버 연결을 수행하지 않는 모형이다.
