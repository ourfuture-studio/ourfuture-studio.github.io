집약과 합성에서 부분 객체 다루기

관련 문제 1개조건 바꿔 체험

부분을 누가 소유하며 삭제 전에 분리할 수 있는지 확인한다.

핵심 이론

집약은 전체와 부분 관계를 나타낸다. UML의 공유 집약(shared aggregation)은 세부 의미가 모델러와 적용 영역에 따라 달라지므로 빈 마름모만으로 삭제 전파를 확정하지 않는다.

합성(composite aggregation)은 부분 객체가 한 시점에 최대 하나의 합성 전체에 속하도록 한다. 전체를 삭제하면 그때 포함된 객체 부분도 삭제된다.

삭제 전에 부분을 분리하는 것이 허용된 모델이라면 분리된 부분은 전체 삭제와 함께 삭제되지 않을 수 있다. 생성 순서나 모든 구현의 메모리 해제 방식을 기호만으로 단정하지 않는다.

작은 예제로 확인하기

문서 D가 페이지 P를 합성 관계로 포함한다. P는 다른 합성 전체에 속하지 않는다. P를 분리하지 않은 상태에서 D를 삭제한다. 여기서 삭제는 UML 객체 인스턴스 삭제이며 파일 복구·GC는 고려하지 않는다.

조건 판단과 결과
D가 P를 composite로 포함; 다른 합성 소유자 없음; 사전 분리 없음; UML 객체 삭제로 D 삭제. D와 P 삭제
D가 P를 composite로 포함; 모델이 분리를 허용; 먼저 P를 D에서 분리해 독립 객체로 둔 후 D 삭제. D 삭제, P 존속 가능
D와 P는 shared aggregation으로만 연결; 별도 삭제 정책 없음; D 삭제 후 P의 상태를 묻는다. P 삭제 여부는 이 조건만으로 확정 불가

현재 D의 합성 부분 집합에 P가 있다. 사전 분리가 없으므로 D 삭제 시 P도 삭제된다. 생성 시점이나 파일 저장 방식은 이 모델의 판단 근거가 아니다.

다시 떠올릴 단서

삭제 직전에 합성 부분으로 남아 있는지 확인한다.

적용 범위

공유 집약의 생명주기를 UML이 일률적으로 강제한다고 설명하지 않는다. 운영체제 파일 삭제나 언어별 GC와는 구분한다.
