SQL 값 바인딩과 문자열 보존

관련 문제 1개조건 바꿔 체험

값을 고치는 대신 SQL 구조와 분리해 전달한다.

핵심 이론

핵심 용어: SQL 삽입(SQL injection).

매개변수화는 SQL 구조를 먼저 정하고 데이터값을 별도로 바인딩하는 방식이다. 바인딩한 문자열의 따옴표도 데이터로 취급한다.

준비 전에 입력을 SQL 문자열에 이어 붙이면 구조와 값의 분리가 사라진다. 입력에서 따옴표를 무조건 지우면 정상 이름의 의미도 훼손한다.

값 자리표시자는 표·열 이름이나 ASC/DESC 같은 구조 토큰의 대체물이 아니다. 동적 구조는 코드가 소유한 허용 선택으로 제한한다.

작은 예제로 확인하기

Python3.13.9 sqlite3, SQLite3.51.0의 인메모리 DB다. users(id INTEGER PRIMARY KEY,name TEXT NOT NULL)에(1,"O'Neil"),(2,'Seo') 두 행만 있다. name 중복과 NULL은 없고 ORDER BY id로 정렬한다. 검색 값은 문자열 "O'Neil"이다. 아래 SQL의 ?에 이 값을 API로 바인딩한다.

조건 판단과 결과
Python3.13.9/SQLite3.51.0 인메모리; users(id PK,name TEXT NOT NULL)={(1,"O'Neil"),(2,'Seo')}; 중복/NULL 없음; SELECT id FROM users WHERE name=? ORDER BY id; 바인딩="O'Neil". [(1,)]
Python3.13.9/SQLite3.51.0 인메모리; users(id PK,name TEXT NOT NULL)={(1,"O'Neil"),(2,'Seo')}; 중복/NULL 없음; SELECT id FROM users WHERE name=? ORDER BY id; 바인딩='Seo'. [(2,)]
Python3.13.9/SQLite3.51.0 인메모리; users(id PK,name TEXT NOT NULL)={(1,"O'Neil"),(2,'Seo')}; 중복/NULL 없음; SELECT id FROM users WHERE name=? ORDER BY id; 바인딩='ONeil'. []

바인딩 값은 O'Neil 그대로다. id1의 name과만 일치하므로 결과는[(1,)]이다.

다시 떠올릴 단서

값은 바인딩하고 구조 선택은 허용된 코드 토큰으로 정한다.

적용 범위

자체 인메모리 SELECT 예제다. 실제 계정·실서비스 공격·모든 SQL 방언의 자동 호환을 다루지 않는다.

근거와 확인 범위
