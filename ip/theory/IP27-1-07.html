모델 검사와 요구사항 타당성

관련 문제 1개조건 바꿔 체험

형식 검사 통과와 사용자의 요구 충족은 다른 질문이다.

핵심 이론

모델 검사는 연결이나 타입 같은 정해진 규칙의 위반을 찾는다. 요구사항 타당성 확인은 명세가 이해관계자의 실제 필요를 나타내는지 검토한다.

자동 도구가 모든 필드의 타입을 검사해도 필요한 취소 기능이 빠졌는지는 사용자 요구와 비교해야 알 수 있다.

검사 통과의 결론은 검사 규칙의 범위 안에 둔다. 누락된 규칙이나 잘못 입력한 요구를 도구가 자동으로 바로잡았다고 가정하지 않는다.

작은 예제로 확인하기

분석 도구는 연결 유효성과 타입 일치만 검사하며 모두 통과했다. 사용자 요구 목록에는 신청 취소가 있지만 모델에는 취소 처리가 없다.

조건 판단과 결과
도구 검사=연결/타입만; 두 검사 통과; 요구=신청·취소; 모델=신청만. 형식 통과, 취소 요구 누락
도구 검사=연결/타입만; 두 검사 통과; 요구=신청·취소; 모델=신청·취소. 이 두 요구에 대응 요소 있음
도구 검사=연결/타입만; 연결 오류 한 개 검출; 요구=신청·취소; 모델에 두 기능 존재. 기능 대응은 있지만 형식 오류 남음

도구의 두 검사 규칙은 통과했다. 별도로 요구 목록과 모델을 대응하면 신청 취소에 대응 요소가 없다. 형식 적합성과 업무 요구 충족을 분리해야 한다.

다시 떠올릴 단서

통과한 규칙과 아직 확인하지 않은 요구를 나눈다.

적용 범위

요구가 모두 나열됐거나 사용자가 올바르게 표현했다고 가정해 전체 정확성을 선언하지 않는다.
