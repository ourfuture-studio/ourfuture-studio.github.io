프로세스 자원과 스레드 실행 상태

관련 문제 1개조건 바꿔 체험

같은 프로세스의 스레드는 주소 공간을 공유하지만 각자의 실행 위치와 스택을 가진다.

핵심 이론

프로세스는 프로그램 실행에 필요한 주소 공간과 운영체제 자원을 묶는 단위이다. 서로 다른 일반 프로세스는 별도의 가상 주소 공간을 가지므로 같은 가상 주소 숫자가 곧 같은 객체를 뜻하지 않는다.

스레드는 프로세스 안의 실행 흐름이다. 같은 프로세스의 스레드는 코드와 힙 등 주소 공간을 공유하고 각 스레드는 프로그램 카운터(다음 명령 위치), 레지스터 상태, 스택을 가진다.

개별 스택이 있다는 말은 다른 스레드가 그 스택의 주소를 절대 접근할 수 없다는 뜻은 아니다. 주소 공간을 공유하므로 포인터 공개와 수명·동기화 문제가 생길 수 있다. 공유 메모리 연결을 설정한 별도 프로세스도 있으므로 프로세스 간 공유 불가능이라고 일반화하지 않는다.

작은 예제로 확인하기

단일 프로세스 P 안의 스레드 T1,T2를 비교한다. 프로세스 사이 명시적 공유 메모리는 설정하지 않았다.

조건 또는 단계 판단 또는 값
같은 프로세스의 스레드 T1,T2 힙 객체 공유
T1,T2의 PC·레지스터 각 실행 흐름의 별도 상태
별도 프로세스 P,Q 공유 설정 없는 주소 공간은 별개

공유 대상과 개별 실행 상태를 한 덩어리로 취급하지 않는다.

다시 떠올릴 단서

주소 공간 공유 여부와 실행 상태의 개별 보관을 나누어 판단한다.

적용 범위

일반적인 프로세스·스레드 모형이며 특정 OS의 커널 내부 자료구조 크기나 성능 비교는 하지 않는다.
