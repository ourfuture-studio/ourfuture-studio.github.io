sizeof가 보는 배열과 포인터

실제 배열(Array)과 포인터 매개변수(Pointer Parameter)

sizeof 앞의 이름이 실제 배열인지 포인터 매개변수인지 확인합니다.

그림의 개념 확인: ISO/IEC JTC1/SC22/WG14, C11 Committee Draft N1570

관련 문제풀이기존 조건 체험전체 도식 보기

핵심 이론

sizeof는 해당 식이나 자료형이 차지하는 크기를 C의 바이트 단위로 반환하며 결과형은 size_t이다. 실제 int a[3] 객체에 sizeof a를 적용하면 원소 세 개의 전체 크기를 얻는다.

함수 매개변수 int a[]는 int *a로 조정된다. 따라서 그 함수 안의 sizeof a는 원래 배열 전체가 아닌 포인터의 크기이다. 배열을 전달한다고 길이 정보가 자동으로 같이 복사되지 않는다.

실제 배열 위치에서는 sizeof a / sizeof a[0]로 원소 수를 구할 수 있다. 매개변수 위치에 이 공식을 적용하면 포인터 크기와 int 크기의 비율을 구할 뿐이다. 포인터 바이트 수는 구현마다 달라질 수 있어 문제는 동일 자료형 크기 비교로 작성했다.

작은 예제로 확인하기

C11 의미 규칙(N1570), signed int이며 아래 작은 값에서 범위 초과 없음. 각 코드는 표준 헤더와 main을 포함한 독립 프로그램이고 입력 없음. 0으로 나누지 않는다. 호출자의 int a[3]. probe의 int a[]는 일반 매개변수이다.

조건 또는 단계 판단 또는 값
호출자의 int a[3] sizeof a / sizeof a[0] = 3
매개변수 int a[] 실제 매개변수형은 int *
함수 안 sizeof a == sizeof(int *) 참(1)

포인터가 4바이트인지 8바이트인지 지정하지 않아도 이 비교의 정답은 정해진다.

다시 떠올릴 단서

sizeof 앞의 이름이 실제 배열인지 포인터 매개변수인지 확인한다.

적용 범위

VLA와 배열 포인터 매개변수는 다루지 않는다. sizeof 매개변수 관련 경고는 예상된 진단이며 오류와 구분한다.
