외래키의 삭제 정책과 NULL 허용

관련 문제 1개조건 바꿔 체험

부모 행을 지울 수 있는지는 참조 관계만으로 결정되지 않는다. 삭제 동작과 자식 열의 NULL 제약을 함께 읽자.

핵심 이론

외래키는 자식 열의 값이 참조 대상 키와 맞도록 제한한다. 자식이 존재할 때 부모를 지우면 참조가 끊어질 수 있으므로 DBMS는 선언된 ON DELETE 동작을 적용한다.

RESTRICT는 참조 중인 부모 삭제를 막고, CASCADE는 해당 자식도 삭제하며, SET NULL은 자식의 참조 열을 NULL로 바꾼다. SET NULL이라도 열에 NOT NULL이 있으면 그 결과를 저장할 수 없어 작업이 실패한다.

외래키 자체가 모든 자식 열을 NOT NULL로 만드는 것은 아니다. 여기서는 SQLite의 외래키 집행을 PRAGMA foreign_keys=ON으로 켜고 새 DB마다 검사한다. 지연 제약과 복합 외래키는 이 예제에 포함하지 않는다.

작은 예제로 확인하기

아래 코드는 Parent 7과 이를 참조하는 Child 31을 만들고 부모 7의 삭제를 시도한다.

관계 값
Parent.id 7
Child(id,parent_id) (31,7)
삭제 정책 RESTRICT

자식 31이 부모 7을 참조하므로 RESTRICT에서 부모 삭제는 거부된다.

다시 떠올릴 단서

참조 자식의 존재, ON DELETE 정책, NULL 허용을 함께 확인한다.

적용 범위

명시한 작은 예제의 조건에서 판단한다. 다른 DBMS의 실행 결과나 실제 성능 측정으로 일반화하지 않는다.

근거와 확인 범위
