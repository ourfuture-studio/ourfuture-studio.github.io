핵심 먼저 일대다는 한쪽 한 건에 다른 쪽 여러 건이 연결될 수 있다는 수의 관계입니다. 필수·선택 참여는 연결이 하나도 없어도 되는지의 조건입니다. 자식의 외래 키만으로 모든 부모에게 자식이 존재하도록 보장하지는 않습니다.

어떤 자료와 조건을 볼까요

가입했지만 주문하지 않은 고객을 허용하는 쇼핑몰입니다. 고객과 주문은 일대다 관계여도 고객 SOL의 주문 수는 0일 수 있습니다.

답을 가르는 기준은 무엇일까요

고객 쪽에서 보는 “주문이 반드시 하나 있어야 하는가”와 주문 쪽에서 보는 “고객 번호가 반드시 있어야 하는가”를 각각 정합니다.

자식의 customer_id에 NOT NULL과 유효한 외래 키를 함께 걸면 각 주문의 고객 참조를 보장할 수 있습니다. 모든 고객에게 주문을 하나씩 만들어 주는 조건은 아닙니다.

Oracle에서 첫 조건을 확인해 봅니다

실행 1 · 주문이 없는 고객도 포함

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH customers (customer_id, customer_name) AS (
    SELECT 1, 'MIN' FROM dual
    UNION ALL
    SELECT 2, 'JUN' FROM dual
    UNION ALL
    SELECT 3, 'SOL' FROM dual
),
orders (order_id, customer_id, amount) AS (
    SELECT 101, 1, 10 FROM dual
    UNION ALL
    SELECT 102, 1, 20 FROM dual
    UNION ALL
    SELECT 103, 2, 5 FROM dual
)
SELECT c.customer_id, COUNT(o.order_id) AS order_count
FROM customers c LEFT JOIN orders o
 ON c.customer_id = o.customer_id
GROUP BY c.customer_id ORDER BY c.customer_id;

예상 결과

CUSTOMER_ID ORDER_COUNT
1 2
2 1
3 0

실행 2 · 고객 번호가 없는 주문 찾기

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH orders (order_id, customer_id) AS (
    SELECT 101, 1 FROM dual
    UNION ALL
    SELECT 102, CAST(NULL AS NUMBER) FROM dual
)
SELECT order_id, customer_id FROM orders
WHERE customer_id IS NULL ORDER BY order_id;

예상 결과

ORDER_ID CUSTOMER_ID
102 NULL

첫 결과의 0은 허용한 업무 상황입니다. 두 번째 자료의 NULL 고객 번호를 허용할지는 별도 규칙이며, 허용하지 않는다면 실제 NOT NULL 제약이 필요합니다.

결과를 어디까지 해석할 수 있을까요

LEFT JOIN 뒤 주문 수를 셀 때는 NULL이 되지 않는 주문 키를 셉니다. COUNT(*)는 주문 없는 고객의 보존 행도 1로 세므로 이 질문의 답과 다릅니다.

직접 예상해 볼 질문 주문의 고객 참조가 필수이면 고객 가입 즉시 주문도 있어야 할까요?

직접 예상해 본 뒤 풀이 확인

확인: 그렇지 않습니다. 주문에서 고객을 향한 필수성과 고객에서 주문을 향한 필수성은 방향이 다릅니다.
