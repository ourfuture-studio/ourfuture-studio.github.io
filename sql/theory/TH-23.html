소계의 NULL과 원래 NULL은 어떻게 구분할까

화면의 두 NULL이 서로 다른 의미를 가질 수 있습니다. 값만 바꾸어 표시하기 전에 GROUPING을 확인합니다.

이 주제 직접 체험하기

GitHub SQL 실험실은 SQLite로 실행됩니다. Oracle 전용 코드는 Oracle 체험에서 실행합니다.

핵심 먼저 ROLLUP이 만든 소계 자리의 NULL에는 GROUPING이 1을 반환합니다. 원래 입력의 NULL을 묶은 상세 그룹에는 0을 반환합니다. 단순 NVL만으로는 둘을 구별할 수 없습니다.

어떤 자료와 조건을 볼까요

부서 10의 매출은 10원이고 부서 번호가 없는 매출은 20원입니다. 부서별 결과와 전체 합계를 함께 출력하면 부서가 NULL인 행이 두 개 생깁니다.

답을 가르는 기준은 무엇일까요

원래 부서 값이 없던 20원은 별도의 상세 그룹입니다. 전체 합계 30원은 모든 부서를 합쳐 부서 기준을 생략한 행입니다.

GROUPING(dept)를 먼저 읽고 라벨을 정하면 실제 미기록과 전체 합계를 구분할 수 있습니다. 표시용 문자열을 입력 값으로 덮어쓰는 것과도 다릅니다.

Oracle에서 첫 조건을 확인해 봅니다

실행 1 · GROUPING으로 구분

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH sales (dept, amount) AS (
    SELECT 10, 10 FROM dual
    UNION ALL
    SELECT CAST(NULL AS NUMBER), 20 FROM dual
)
SELECT dept, SUM(amount) AS total, GROUPING(dept) AS g,
 CASE WHEN GROUPING(dept)=1 THEN 'ALL'
      WHEN dept IS NULL THEN 'MISSING'
      ELSE 'DETAIL' END AS row_kind
FROM sales GROUP BY ROLLUP(dept)
ORDER BY GROUPING(dept), dept NULLS FIRST;

예상 결과

DEPT TOTAL G ROW_KIND
NULL 20 0 MISSING
10 10 0 DETAIL
NULL 30 1 ALL

조건과 구조를 바꾸어 비교해 봅니다

실행 2 · NVL로만 바꾸어 표시

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH sales (dept, amount) AS (
    SELECT 10, 10 FROM dual
    UNION ALL
    SELECT CAST(NULL AS NUMBER), 20 FROM dual
)
SELECT NVL(dept, -1) AS displayed_dept, SUM(amount) AS total
FROM sales GROUP BY ROLLUP(dept)
ORDER BY GROUPING(dept), dept NULLS FIRST;

예상 결과

DISPLAYED_DEPT TOTAL
-1 20
10 10
-1 30

첫 결과에서 G가 0인 NULL은 MISSING, 1인 NULL은 ALL입니다. 두 번째 결과는 두 경우를 모두 -1로 보여 주어 값의 출처를 읽기 어렵게 만듭니다.

결과를 어디까지 해석할 수 있을까요

소계 행에 NULL이 보인다고 원본에 NULL이 있었다고 추정하지 않습니다. 반대로 모든 NULL 행을 전체 합계로 분류해서도 안 됩니다.

직접 예상해 볼 질문 GROUPING(dept)=0이면 dept 값이 반드시 NULL이 아닐까요?

직접 예상해 본 뒤 풀이 확인

확인: 아닙니다. 원본 NULL로 구성된 상세 그룹도 0입니다. GROUPING은 NULL 여부 검사가 아니라 소계 자리인지의 표시입니다.
