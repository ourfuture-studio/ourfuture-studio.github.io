이 주제 직접 체험하기

GitHub SQL 실험실은 SQLite로 실행됩니다. Oracle 전용 코드는 Oracle 체험에서 실행합니다.

핵심 먼저 ROWS는 행 단위로 창을 정합니다. RANGE의 UNBOUNDED PRECEDING부터 CURRENT ROW까지는 현재 정렬 키와 같은 동률 행을 함께 포함합니다. 동률 판단은 ORDER BY에 적은 전체 키를 기준으로 합니다.

어떤 자료와 조건을 볼까요

첫날 주문은 8원과 12원, 둘째 날 주문은 7원입니다. 첫 번째 주문의 누계가 8인지 20인지 비교해 봅니다.

답을 가르는 기준은 무엇일까요

ROWS의 계산 순서를 day_no, order_id로 유일하게 정하면 첫 행까지 8, 다음 행까지 20, 마지막까지 27입니다.

RANGE를 day_no 하나로 정렬하면 같은 날의 두 주문이 동률입니다. 두 행에서 모두 첫날 전체 20을 봅니다.

Oracle에서 첫 조건을 확인해 봅니다

실행 1 · 행 단위와 날짜 동률 범위

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH sales (order_id, day_no, amount) AS (
    SELECT 1, 1, 8 FROM dual
    UNION ALL
    SELECT 2, 1, 12 FROM dual
    UNION ALL
    SELECT 3, 2, 7 FROM dual
)
SELECT order_id, day_no, amount,
 SUM(amount) OVER (ORDER BY day_no, order_id ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS rows_sum,
 SUM(amount) OVER (ORDER BY day_no RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS range_sum
FROM sales ORDER BY order_id;

예상 결과

ORDER_ID DAY_NO AMOUNT ROWS_SUM RANGE_SUM
1 1 8 8 20
2 1 12 20 20
3 2 7 27 27

조건과 구조를 바꾸어 비교해 봅니다

실행 2 · RANGE의 전체 정렬 키를 바꾸면

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH sales (order_id, day_no, amount) AS (
    SELECT 1, 1, 8 FROM dual
    UNION ALL
    SELECT 2, 1, 12 FROM dual
    UNION ALL
    SELECT 3, 2, 7 FROM dual
)
SELECT order_id,
 SUM(amount) OVER (ORDER BY day_no, order_id RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS range_sum
FROM sales ORDER BY order_id;

예상 결과

ORDER_ID RANGE_SUM
1 8
2 20
3 27

두 번째 예제는 RANGE여도 정렬 키 전체가 각 행에서 다르므로 이 입력에서는 ROWS와 같은 누계를 냅니다. RANGE라는 이름만 보고 같은 날짜를 언제나 묶는다고 판단하면 안 됩니다.

결과를 어디까지 해석할 수 있을까요

물리적 ROWS의 정렬 키가 동점을 남기면 행별 누계 배정이 일정하지 않을 수 있습니다. 또한 Oracle에서 RANGE의 여러 정렬 키가 허용되는 범위는 창 경계에 따라 다릅니다. 여기서는 허용되는 UNBOUNDED PRECEDING·CURRENT ROW 조합을 썼습니다.

직접 예상해 볼 질문 실행 1의 ROWS 정렬에서 order_id를 빼면 첫 두 행의 개별 누계를 확정할 수 있을까요?

직접 예상해 본 뒤 풀이 확인

확인: 동률 내의 순서가 정해지지 않아 확정할 수 없습니다. 고유한 보조 정렬 키가 있어야 행별 결과를 일정하게 비교할 수 있습니다.
