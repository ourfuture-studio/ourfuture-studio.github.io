SQLD · 제약 조건과 트랜잭션

CHECK가 있으면 NULL도 막을 수 있을까

양수만 허용한다는 조건과 값을 반드시 입력한다는 조건은 다릅니다.

이 주제 직접 체험하기

GitHub SQL 실험실은 SQLite로 실행됩니다. Oracle 전용 코드는 Oracle 체험에서 실행합니다.

핵심 먼저 Oracle CHECK는 조건이 TRUE 또는 UNKNOWN인 행을 허용하고 FALSE인 행을 거부합니다. x > 0에서 NULL은 UNKNOWN이므로 통과합니다. 값도 필수라면 NOT NULL 등을 별도로 명시해야 합니다.

어떤 자료와 조건을 볼까요

수수료 x를 양수로 제한한다고 합시다. 아직 기록하지 않은 NULL도 금지하려는 것인지, 음수와 0만 금지하려는 것인지 먼저 나눕니다.

답을 가르는 기준은 무엇일까요

10 > 0은 TRUE, -1 > 0은 FALSE, NULL > 0은 UNKNOWN입니다. WHERE는 TRUE만 남기지만 CHECK의 허용 조건은 다릅니다.

CHECK(x IS NOT NULL)은 NULL에서 FALSE이므로 NULL을 거부할 수 있습니다. “NULL은 모든 CHECK를 무조건 통과한다”는 설명은 맞지 않습니다.

실행 1 · 두 실습 표 준비와 NULL 허용 확인

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

개인 실습 스키마에서 처음 한 번만 실행합니다. 같은 이름의 표가 있으면 기존 표를 삭제하지 말고 실습 이름을 바꾸세요. CREATE는 암묵적 COMMIT을 수행합니다.

CREATE TABLE OFS_T41_A (x NUMBER CHECK (x > 0));
CREATE TABLE OFS_T41_B (x NUMBER NOT NULL CHECK (x > 0));
INSERT INTO OFS_T41_A (x)
WITH vals (x) AS (
 SELECT CAST(NULL AS NUMBER) FROM dual
 UNION ALL SELECT 10 FROM dual
)
SELECT x FROM vals;
SELECT x FROM OFS_T41_A ORDER BY x NULLS FIRST;

결과를 어디까지 해석할 수 있을까요

CHECK와 WHERE의 UNKNOWN 처리를 같은 규칙으로 외우지 않습니다. 이 실습의 실제 제약은 CREATE TABLE에서 만들며, CASE로 통과 여부를 계산한 화면으로 제약 생성을 대신하지 않습니다.

직접 예상해 볼 질문 CHECK(x > 0)만 있는 표에 0을 넣으면 통과할까요?

직접 예상해 본 뒤 풀이 확인

확인: 거부됩니다. 0 > 0은 UNKNOWN이 아니라 FALSE입니다. NULL과 0은 다른 입력입니다.
