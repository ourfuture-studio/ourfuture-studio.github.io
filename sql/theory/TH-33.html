고객과 고객 한 명과 고객 이름은 어떻게 다를까

같은 이름의 고객 둘을 놓으면 엔터티·인스턴스·속성의 역할이 더 분명해집니다.

GitHub SQL 실험실은 SQLite로 실행됩니다. Oracle 전용 코드는 Oracle 체험에서 실행합니다.

핵심 먼저 고객은 관리할 대상의 유형, 고객 1번은 그 유형의 개별 사례, 고객 이름은 각 사례가 가진 특성입니다. 관계형 표로 표현할 때는 인스턴스를 행으로, 속성을 열로 대응해 볼 수 있습니다.

어떤 자료와 조건을 볼까요

MIN이라는 이름을 가진 고객이 두 명 있습니다. 이름이 같다는 사실만으로 같은 사람이라고 묶으면 고객 두 명의 기록이 하나로 줄어듭니다.

답을 가르는 기준은 무엇일까요

엔터티를 설명할 때는 어떤 업무에서 무엇을 관리하는지 먼저 정합니다. 고객 번호와 이름을 저장한다는 것은 고객별 사례를 구별하고 특성을 기록한다는 뜻입니다.

고객 이름은 식별자로 적합한지 따로 검토해야 합니다. 이 예제에서는 이름의 중복을 허용하고 customer_id로 각 고객을 구분하는 규칙을 정했습니다.

Oracle에서 첫 조건을 확인해 봅니다

실행 1 · 개별 고객의 행

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH customers (customer_id, customer_name) AS (
    SELECT 1, 'MIN' FROM dual
    UNION ALL
    SELECT 2, 'MIN' FROM dual
    UNION ALL
    SELECT 3, 'SOL' FROM dual
)
SELECT customer_id, customer_name FROM customers
ORDER BY customer_id;

예상 결과

CUSTOMER_ID CUSTOMER_NAME
1 MIN
2 MIN
3 SOL

조건과 구조를 바꾸어 비교해 봅니다

실행 2 · 고객 수와 이름 종류 수

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH customers (customer_id, customer_name) AS (
    SELECT 1, 'MIN' FROM dual
    UNION ALL
    SELECT 2, 'MIN' FROM dual
    UNION ALL
    SELECT 3, 'SOL' FROM dual
)
SELECT COUNT(*) AS customer_rows,
 COUNT(DISTINCT customer_name) AS name_kinds FROM customers;

예상 결과

CUSTOMER_ROWS NAME_KINDS
3 2

고객 행은 세 개이고 이름 종류는 두 개입니다. 이름 종류의 개수를 고객 수라고 부를 수 없는 이유가 이 차이에 있습니다.

결과를 어디까지 해석할 수 있을까요

엔터티를 언제나 물리 테이블 한 개와 동일시하지 않습니다. 업무 개념을 논리 구조로 정리한 뒤 실제 테이블로 구현하는 과정에서 분리·변환이 있을 수 있습니다. WITH는 여기서 개념을 살펴볼 표본이며 고객 식별 제약을 실제로 생성하지는 않습니다.

직접 예상해 볼 질문 MIN을 M으로 바꾸면 고객 인스턴스가 새로 생긴 것일까요?

직접 예상해 본 뒤 풀이 확인

확인: 이 업무 규칙에서는 아닙니다. 같은 고객 번호의 이름 속성이 바뀐 것입니다. 무엇을 동일한 개체로 볼지 정한 식별 기준이 필요합니다.
