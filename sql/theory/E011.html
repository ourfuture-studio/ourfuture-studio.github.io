DISTINCT는 첫 번째 열만 보는 걸까

고객 번호만 조회할 때와 주문 번호까지 조회할 때, 중복의 기준이 달라집니다.

관련 문제 풀기 →같은 표로 SQL 실행 →

개념과 판단을 한눈에

중복 제거(DISTINCT), 투영(Projection), 튜플(Tuple)

핵심 판단 규칙

SELECT DISTINCT는 바로 뒤 첫 열만이 아니라 SELECT 목록 전체의 값 조합을 비교한다. 원본 테이블의 행을 지우지 않는다.

아래 이론과 문제·실험은 같은 원리를 다른 입력으로 확인할 수 있습니다. 숫자를 대조할 때는 각 화면에 표시된 표·조건·SQL을 먼저 확인하세요.

GitHub SQL 실험실은 SQLite로 실행됩니다. Oracle 전용 코드는 Oracle 체험에서 실행합니다.

핵심 먼저 SELECT DISTINCT는 SELECT 목록의 값 조합 전체를 기준으로 중복 결과 행을 제거합니다. 고객 번호가 같아도 주문 번호가 다르면 서로 다른 결과 행입니다.

어떤 자료와 조건을 볼까요

고객 1의 주문은 101번과 102번, 고객 2의 주문은 103번입니다. 고객 명단을 원할 때와 고객·주문 쌍을 원할 때의 조회 열을 비교합니다.

답을 가르는 기준은 무엇일까요

고객 번호 하나만 고르면 1, 1, 2 가운데 같은 결과 값 1이 합쳐집니다.

고객 번호와 주문 번호를 함께 고르면 (1,101), (1,102), (2,103)입니다. 세 조합이 모두 다르므로 세 행이 남습니다.

Oracle에서 첫 조건을 확인해 봅니다

실행 1 · 고객 번호만 조회

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH orders (order_id, customer_id, amount) AS (
    SELECT 101, 1, 10 FROM dual
    UNION ALL
    SELECT 102, 1, 20 FROM dual
    UNION ALL
    SELECT 103, 2, 5 FROM dual
)
SELECT DISTINCT customer_id FROM orders
ORDER BY customer_id;

예상 결과

CUSTOMER_ID
1
2

조건과 구조를 바꾸어 비교해 봅니다

실행 2 · 주문 번호까지 조회

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH orders (order_id, customer_id, amount) AS (
    SELECT 101, 1, 10 FROM dual
    UNION ALL
    SELECT 102, 1, 20 FROM dual
    UNION ALL
    SELECT 103, 2, 5 FROM dual
)
SELECT DISTINCT customer_id, order_id FROM orders
ORDER BY customer_id, order_id;

예상 결과

CUSTOMER_ID ORDER_ID
1 101
1 102
2 103

DISTINCT가 적용되는 범위는 같지만 SELECT 목록이 달라졌습니다. 주문 번호를 추가한 뒤 고객 번호가 반복되는 것은 DISTINCT가 무시된 결과가 아닙니다.

결과를 어디까지 해석할 수 있을까요

고객별 최신 주문 한 건을 고르는 문제는 DISTINCT만으로 해결되지 않습니다. 어떤 주문을 남길지 정렬과 선택 기준이 필요합니다. 또한 DISTINCT만으로 출력 정렬이 보장되지 않습니다.

직접 예상해 볼 질문 두 열 앞의 DISTINCT를 고객 번호 바로 앞에 썼으니 고객만 중복 제거한다는 설명은 맞을까요?

직접 예상해 본 뒤 풀이 확인

확인: 맞지 않습니다. 키워드를 적은 위치와 관계없이 SELECT 목록 전체의 값 조합을 비교합니다.
