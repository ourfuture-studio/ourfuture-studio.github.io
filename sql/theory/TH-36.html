GitHub SQL 실험실은 SQLite로 실행됩니다. Oracle 전용 코드는 Oracle 체험에서 실행합니다.

핵심 먼저 식별 관계에서는 부모의 식별자가 자식의 주 식별자 구성에 참여합니다. 비식별 관계에서도 부모를 가리키는 외래 키는 있을 수 있습니다. 연결 열의 존재만으로 식별 관계라고 판단하지 않습니다.

어떤 자료와 조건을 볼까요

주문 안에서 상세 순번을 1부터 매긴다고 합시다. 10번 주문의 1번 줄과 20번 주문의 1번 줄은 서로 다른 상세입니다.

답을 가르는 기준은 무엇일까요

주문 상세의 식별자를 (order_id, line_no)로 정하면 어느 주문의 줄인지가 식별에 필요합니다. 부모 주문 번호가 식별자 일부에 들어갑니다.

상세마다 독립적인 line_id를 부여하고 그것을 주 식별자로 정하면 order_id는 연결을 위한 속성으로 남을 수 있습니다. 부모 참조가 없어지는 것은 아닙니다.

Oracle에서 첫 조건을 확인해 봅니다

실행 1 · 상세 순번만으로는 식별 불가

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH lines (order_id, line_no) AS (
    SELECT 10, 1 FROM dual
    UNION ALL
    SELECT 10, 2 FROM dual
    UNION ALL
    SELECT 20, 1 FROM dual
)
SELECT line_no, COUNT(*) AS occurrences
FROM lines GROUP BY line_no HAVING COUNT(*) > 1
ORDER BY line_no;

예상 결과

LINE_NO OCCURRENCES
1 2

조건과 구조를 바꾸어 비교해 봅니다

실행 2 · 독립 식별자를 부여한 구조

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH lines (line_id, order_id, line_no) AS (
    SELECT 101, 10, 1 FROM dual
    UNION ALL
    SELECT 102, 10, 2 FROM dual
    UNION ALL
    SELECT 103, 20, 1 FROM dual
)
SELECT line_id, order_id, line_no FROM lines ORDER BY line_id;

예상 결과

LINE_ID ORDER_ID LINE_NO
101 10 1
102 10 2
103 20 1

두 번째 구조에서도 (order_id, line_no)의 업무상 중복을 막아야 할 수 있습니다. 주 식별자로 무엇을 채택했는지와 대체 유일성 규칙을 함께 기록합니다.

결과를 어디까지 해석할 수 있을까요

WITH의 열 이름이 order_id라는 사실만으로 실제 외래 키 제약이 생기지는 않습니다. 이 조회는 식별 조합을 이해하기 위한 표본이며 실제 PK·FK 생성은 별도의 DDL입니다.

직접 예상해 볼 질문 자식에 부모 번호가 NOT NULL이면 반드시 식별 관계일까요?

직접 예상해 본 뒤 풀이 확인

확인: 아닙니다. 부모 번호가 필수라는 조건과 자식 주 식별자에 포함된다는 조건은 다릅니다.
