핵심 먼저 인조 식별자는 행을 구별할 번호를 제공하지만 업무상 유일성까지 저절로 보장하지 않습니다. 고객당 월 청구서를 한 장만 허용한다면 (고객 번호, 청구 월)이라는 별도 규칙이 필요합니다.

어떤 자료와 조건을 볼까요

청구서 101번과 102번의 번호는 다릅니다. 하지만 둘 다 고객 1의 2026년 10월 청구서입니다. 서로 다른 행이라는 이유로 두 장을 허용해도 되는지 확인합니다.

답을 가르는 기준은 무엇일까요

기본 키를 invoice_id로 잡으면 번호 중복을 막습니다. 같은 고객·월에 다른 번호로 들어오는 청구서는 그 제약을 위반하지 않습니다.

업무 규칙이 고객별 월 1장이라면 고객 번호와 청구 월의 NOT NULL·UNIQUE 조합 같은 구현 조건을 검토합니다. 여러 장의 정정 청구서를 허용하는 업무라면 버전 등 다른 기준이 필요합니다.

실행 1 · 번호는 모두 다르지만

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH invoices (invoice_id, customer_id, bill_month) AS (
    SELECT 101, 1, 202610 FROM dual
    UNION ALL
    SELECT 102, 1, 202610 FROM dual
    UNION ALL
    SELECT 103, 2, 202610 FROM dual
)
SELECT COUNT(*) AS rows_total, COUNT(DISTINCT invoice_id) AS ids
FROM invoices;

예상 결과

ROWS_TOTAL IDS
3 3

조건과 구조를 바꾸어 비교해 봅니다

실행 2 · 업무 기준의 중복 검사

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH invoices (invoice_id, customer_id, bill_month) AS (
    SELECT 101, 1, 202610 FROM dual
    UNION ALL
    SELECT 102, 1, 202610 FROM dual
    UNION ALL
    SELECT 103, 2, 202610 FROM dual
)
SELECT customer_id, bill_month, COUNT(*) AS copies
FROM invoices GROUP BY customer_id, bill_month
HAVING COUNT(*) > 1
ORDER BY customer_id, bill_month;

예상 결과

CUSTOMER_ID BILL_MONTH COPIES
1 202610 2

번호 수와 행 수가 같아도 두 번째 조회는 중복 업무 조합을 찾습니다. 이 예제에서 월은 계산하지 않는 숫자 코드이며 실제 달력 연산이나 날짜 유효성 검사는 다루지 않습니다.

결과를 어디까지 해석할 수 있을까요

인조 키를 도입하면 자연 키나 업무 키를 더 이상 생각하지 않아도 된다는 결론은 나오지 않습니다. 어느 사실의 중복을 막을지 정한 뒤 각각의 제약을 기록합니다.

직접 예상해 볼 질문 102번의 청구 월을 202611로 바꾸면 두 번째 SQL에 남을 행은 무엇일까요?
