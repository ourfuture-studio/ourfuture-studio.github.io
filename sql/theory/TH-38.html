이 주제 직접 체험하기

GitHub SQL 실험실은 SQLite로 실행됩니다. Oracle 전용 코드는 Oracle 체험에서 실행합니다.

핵심 먼저 2정규형은 1정규형을 전제로 비주요 속성이 후보 키의 일부에만 종속되는 부분 종속을 제거합니다. 3정규형은 모든 비자명 함수 종속 X→A에서 X가 슈퍼키이거나 A가 주요 속성인 조건을 요구합니다. 주요 속성은 어떤 후보 키의 구성에 포함되는 속성입니다. 단순 예제에서는 키→비키→비키의 이행 종속으로 차이를 살펴볼 수 있습니다.

어떤 자료와 조건을 볼까요

주문 상세의 후보 키는 (주문 번호, 상품 번호)라고 정합니다. 주문 번호는 고객 번호를, 고객 번호는 고객 이름을, 상품 번호는 상품 이름을 결정합니다. 주문 수량은 상세 조합에 속합니다.

답을 가르는 기준은 무엇일까요

함수 종속 X→A는 X가 같으면 A도 같아야 한다는 규칙입니다. A가 이미 X의 일부인 자명한 종속을 제외한 것을 비자명 종속이라고 부릅니다.

상세 표에서 주문 번호→고객 번호, 상품 번호→상품 이름은 복합 후보 키 일부에 대한 종속입니다. 주문·상품·상세를 나누면 이 부분 종속을 분리할 수 있습니다.

주문 표를 (주문 번호, 고객 번호, 고객 이름)으로 남기면 주문 번호→고객 번호→고객 이름이라는 이행 종속이 남습니다. 고객 정보를 다시 고객 표로 분리하는 이유입니다.

Oracle에서 첫 조건을 확인해 봅니다

실행 1 · 한 고객 이름이 달라진 표본

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH order_lines (order_id, item_id, item_name, customer_id, customer_name, qty) AS (
    SELECT 1, 10, 'COFFEE', 1, 'MIN', 1 FROM dual
    UNION ALL
    SELECT 1, 20, 'TEA', 1, 'MIN', 2 FROM dual
    UNION ALL
    SELECT 2, 10, 'COFFEE', 1, 'MINTY', 1 FROM dual
)
SELECT customer_id, COUNT(DISTINCT customer_name) AS name_kinds
FROM order_lines GROUP BY customer_id
HAVING COUNT(DISTINCT customer_name) > 1
ORDER BY customer_id;

예상 결과

CUSTOMER_ID NAME_KINDS
1 2

실행 2 · 나눈 자료를 키로 다시 연결

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH customers (customer_id, customer_name) AS (
    SELECT 1, 'MIN' FROM dual
),
orders (order_id, customer_id) AS (
    SELECT 1, 1 FROM dual
    UNION ALL
    SELECT 2, 1 FROM dual
),
items (item_id, item_name) AS (
    SELECT 10, 'COFFEE' FROM dual
    UNION ALL
    SELECT 20, 'TEA' FROM dual
),
lines (order_id, item_id, qty) AS (
    SELECT 1, 10, 1 FROM dual
    UNION ALL
    SELECT 1, 20, 2 FROM dual
    UNION ALL
    SELECT 2, 10, 1 FROM dual
)
SELECT l.order_id, l.item_id, i.item_name, c.customer_name, l.qty
FROM lines l JOIN orders o ON o.order_id=l.order_id
JOIN customers c ON c.customer_id=o.customer_id
JOIN items i ON i.item_id=l.item_id
ORDER BY l.order_id, l.item_id;

예상 결과

ORDER_ID ITEM_ID ITEM_NAME CUSTOMER_NAME QTY
1 10 COFFEE MIN 1
1 20 TEA MIN 2
2 10 COFFEE MIN 1

첫 조회는 현재 표본의 이름 불일치를 찾습니다. 정규형은 한 번의 SELECT 결과만이 아니라 정한 후보 키와 모든 허용 자료에 성립해야 하는 함수 종속을 기준으로 판정합니다.

결과를 어디까지 해석할 수 있을까요

정규화가 언제나 조인을 없애거나 모든 조회를 빠르게 만든다고 말하지 않습니다. 이 예제의 목적은 같은 고객 사실을 여러 상세에서 따로 고치다 생기는 불일치의 경로를 줄이는 것입니다.
