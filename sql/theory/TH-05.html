결과가 없다는 것은 0행일까 NULL 한 칸일까

조건에 맞는 주문이 없어도 집계 결과 한 행이 나올 수 있습니다. 행의 수와 그 안의 값을 따로 읽어 봅니다.

개념과 판단을 한눈에

빈 집합(Empty Set), 전체 집계(Global Aggregation), 그룹 필터(Group Filter, HAVING)

핵심 판단 규칙

입력 0행 ≠ 값이 NULL인 1행 ≠ 집계 값 0. 일반 GROUP BY는 입력이 없으면 그룹도 없지만 GROUP BY 없는 전체 집계는 한 행을 만든다.

핵심 먼저 일반 조회가 0행이어도, GROUP BY 없는 집계는 전체를 하나의 집계 대상으로 다룹니다. COUNT는 0, SUM은 NULL을 반환합니다. 그 집계 행도 HAVING 조건에서 제외되면 결과가 0행이 됩니다.

어떤 자료와 조건을 볼까요

10원과 20원짜리 주문만 있습니다. 100원을 넘는 주문을 찾으면 조회 대상은 비어 있습니다. 이제 주문 목록을 보여 달라는 요청과 주문 수·금액 합계를 보여 달라는 요청을 구분해 봅니다.

답을 가르는 기준은 무엇일까요

COUNT의 0은 센 행이 없다는 값입니다. SUM의 NULL은 더할 NULL 아닌 입력이 없을 때의 결과입니다. 어느 쪽도 0행이라는 화면 구조와 같지 않습니다.

GROUP BY가 있으면 존재하는 그룹별로 결과를 만듭니다. 입력 행이 없으면 일반적인 GROUP BY에서는 만들 그룹도 없습니다. GROUP BY 없는 전체 집계와 구분해야 합니다.

실행 1 · 주문 목록 조회

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH orders (order_id, amount) AS (
    SELECT 101, 10 FROM dual
    UNION ALL
    SELECT 102, 20 FROM dual
)
SELECT order_id, amount FROM orders
WHERE amount > 100
ORDER BY order_id;

예상 결과

반환 행 없음 · 0행.

조건과 구조를 바꾸어 비교해 봅니다

실행 2 · 같은 조건의 전체 집계

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH orders (order_id, amount) AS (
    SELECT 101, 10 FROM dual
    UNION ALL
    SELECT 102, 20 FROM dual
)
SELECT COUNT(*) AS row_count, SUM(amount) AS total
FROM orders WHERE amount > 100;

예상 결과

ROW_COUNT TOTAL
0 NULL

실행 3 · 집계 행을 HAVING으로 제외

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH orders (order_id, amount) AS (
    SELECT 101, 10 FROM dual
    UNION ALL
    SELECT 102, 20 FROM dual
)
SELECT COUNT(*) AS row_count, SUM(amount) AS total
FROM orders WHERE amount > 100
HAVING COUNT(*) > 0;

예상 결과

반환 행 없음 · 0행.

두 번째 SQL은 0과 NULL이 들어 있는 한 행을 반환합니다. 세 번째에서는 집계 값 0이 HAVING의 > 0을 만족하지 않아 그 한 행도 사라집니다.

결과를 어디까지 해석할 수 있을까요

데이터베이스 도구에서 NULL을 빈칸으로 표시할 수 있습니다. 빈칸처럼 보인다는 이유로 결과 행 자체가 없다고 판단하지 말고 행 수와 열 이름을 함께 확인하세요.

직접 예상해 볼 질문 모든 입력 값이 NULL인 세 행에서 COUNT(*)와 SUM(amount)는 무엇을 반환할까요?

직접 예상해 본 뒤 풀이 확인

확인: COUNT(*)는 3, SUM(amount)는 NULL입니다. 행이 없는 경우와 NULL 값인 행이 있는 경우는 다릅니다.
