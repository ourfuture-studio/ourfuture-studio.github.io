같은 조건인데 ON과 WHERE는 왜 다를까

20원 이상인 주문을 연결하되 모든 고객을 남기려면, 주문 조건을 어디에 두어야 할까요?

이 주제 직접 체험하기

GitHub SQL 실험실은 SQLite로 실행됩니다. Oracle 전용 코드는 Oracle 체험에서 실행합니다.

핵심 먼저 LEFT JOIN의 ON에 둔 오른쪽 조건은 연결할 주문을 제한합니다. WHERE에 둔 조건은 조인으로 만들어진 행을 걸러냅니다. 보존된 행의 오른쪽 값이 NULL이면 amount >= 20은 UNKNOWN이므로 WHERE를 통과하지 못합니다.

어떤 자료와 조건을 볼까요

세 고객 중 MIN만 20원짜리 주문이 있습니다. JUN은 작은 주문만 있고 SOL은 주문이 없습니다. 두 고객에게 큰 주문이 없다는 사실까지 보여 주는 보고서를 만들어 봅니다.

답을 가르는 기준은 무엇일까요

ON에서는 고객별로 금액 조건에 맞는 주문을 찾습니다. 찾지 못한 JUN과 SOL도 LEFT JOIN에 의해 남습니다.

WHERE에서는 조인 결과 중 금액 조건이 TRUE인 행만 남습니다. 이 위치의 조건은 오른쪽 NULL을 허용하지 않으므로 JUN과 SOL을 제외합니다.

Oracle에서 첫 조건을 확인해 봅니다

실행 1 · 연결할 주문의 조건

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH customers (customer_id, customer_name) AS (
    SELECT 1, 'MIN' FROM dual
    UNION ALL
    SELECT 2, 'JUN' FROM dual
    UNION ALL
    SELECT 3, 'SOL' FROM dual
),
orders (order_id, customer_id, amount) AS (
    SELECT 101, 1, 10 FROM dual
    UNION ALL
    SELECT 102, 1, 20 FROM dual
    UNION ALL
    SELECT 103, 2, 5 FROM dual
)
SELECT c.customer_id, o.order_id, o.amount
FROM customers c LEFT JOIN orders o
  ON c.customer_id = o.customer_id AND o.amount >= 20
ORDER BY c.customer_id;

예상 결과

CUSTOMER_ID ORDER_ID AMOUNT
1 102 20
2 NULL NULL
3 NULL NULL

실행 2 · 조인 결과의 필터

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH customers (customer_id, customer_name) AS (
    SELECT 1, 'MIN' FROM dual
    UNION ALL
    SELECT 2, 'JUN' FROM dual
    UNION ALL
    SELECT 3, 'SOL' FROM dual
),
orders (order_id, customer_id, amount) AS (
    SELECT 101, 1, 10 FROM dual
    UNION ALL
    SELECT 102, 1, 20 FROM dual
    UNION ALL
    SELECT 103, 2, 5 FROM dual
)
SELECT c.customer_id, o.order_id, o.amount
FROM customers c LEFT JOIN orders o
  ON c.customer_id = o.customer_id
WHERE o.amount >= 20
ORDER BY c.customer_id;

예상 결과

CUSTOMER_ID ORDER_ID AMOUNT
1 102 20

ON 버전은 고객 3명을 모두 보여 주고, WHERE 버전은 조건을 만족하는 MIN의 주문 1행만 보여 줍니다. WHERE에서 고객 표의 조건을 거는 경우까지 무조건 같은 차이가 난다고 외우지는 않습니다.

결과를 어디까지 해석할 수 있을까요

WHERE o.amount >= 20 OR o.order_id IS NULL은 일반적으로 ON에 조건을 넣은 것과 같지 않습니다. 작은 주문과 이미 연결된 JUN에게는 NULL 보존 행이 별도로 만들어지지 않기 때문입니다.

직접 예상해 볼 질문 WHERE 버전에 OR o.order_id IS NULL을 붙이면 JUN도 돌아올까요?

직접 예상해 본 뒤 풀이 확인

확인: 아닙니다. MIN과 SOL만 남습니다. JUN은 작은 주문과 연결된 행의 order_id가 NULL이 아니므로 두 조건 모두 통과하지 못합니다.
