IN과 EXISTS와 NOT EXISTS는 무엇을 물을까

값이 목록에 있는지와 연결되는 행이 있는지는 비슷해 보여도 NULL에서 질문이 갈라집니다.

이 주제 직접 체험하기

GitHub SQL 실험실은 SQLite로 실행됩니다. Oracle 전용 코드는 Oracle 체험에서 실행합니다.

핵심 먼저 IN은 값의 포함 여부를, 상관 EXISTS는 연결 조건을 만족하는 행의 존재를 판단합니다. NOT EXISTS는 그런 행이 없는지를 묻습니다. NULL이 있는 NOT IN을 아무 조건 없이 같은 뜻으로 바꾸면 안 됩니다.

어떤 자료와 조건을 볼까요

고객 번호는 1·2·3이고 주문에는 고객 1과 고객 번호가 NULL인 행이 있습니다. 주문이 없는 고객을 찾는 두 방법의 차이를 확인해 봅니다.

답을 가르는 기준은 무엇일까요

이 예제의 IN과 등호 상관 EXISTS는 고객 1을 찾습니다. 그러나 NOT IN의 목록에 NULL이 있으면 값 2·3도 TRUE로 판정되지 않습니다.

NOT EXISTS는 고객별로 등호로 일치하는 주문이 없는지를 판단합니다. 바깥 고객 번호가 NULL일 수도 있는 자료라면, 등호로 일치하지 않는 그 행을 포함할지 업무 조건도 정해야 합니다.

Oracle에서 첫 조건을 확인해 봅니다

실행 1 · IN과 EXISTS와 NOT EXISTS 비교

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH customers (customer_id) AS (
    SELECT 1 FROM dual
    UNION ALL
    SELECT 2 FROM dual
    UNION ALL
    SELECT 3 FROM dual
),
orders (customer_id) AS (
    SELECT 1 FROM dual
    UNION ALL
    SELECT CAST(NULL AS NUMBER) FROM dual
)
SELECT c.customer_id,
 CASE WHEN c.customer_id IN (SELECT customer_id FROM orders) THEN 'Y' ELSE 'N' END AS in_hit,
 CASE WHEN EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.customer_id) THEN 'Y' ELSE 'N' END AS exists_hit,
 CASE WHEN NOT EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.customer_id) THEN 'Y' ELSE 'N' END AS no_match
FROM customers c ORDER BY c.customer_id;

예상 결과

CUSTOMER_ID IN_HIT EXISTS_HIT NO_MATCH
1 Y Y N
2 N N Y
3 N N Y

실행 2 · NULL이 들어 있는 NOT IN

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH customers (customer_id) AS (
    SELECT 1 FROM dual
    UNION ALL
    SELECT 2 FROM dual
    UNION ALL
    SELECT 3 FROM dual
),
orders (customer_id) AS (
    SELECT 1 FROM dual
    UNION ALL
    SELECT CAST(NULL AS NUMBER) FROM dual
)
SELECT c.customer_id FROM customers c
WHERE c.customer_id NOT IN (SELECT customer_id FROM orders)
ORDER BY c.customer_id;

예상 결과

반환 행 없음 · 0행.

첫 SQL의 IN_HIT에서 N은 CASE의 THEN을 통과하지 않았다는 뜻입니다. 원래 IN 조건의 FALSE와 UNKNOWN을 둘 다 N으로 표시하므로 이를 원래 논리값 그대로라고 해석하지 않습니다.

결과를 어디까지 해석할 수 있을까요

“NOT IN은 언제나 NOT EXISTS로 치환 가능”이라고 외우지 않습니다. 안쪽 NULL 처리와 바깥쪽 NULL을 남길지까지 정해야 동일한 조회 요구가 됩니다.

직접 예상해 볼 질문 두 번째 SQL의 안쪽 조회에서 NULL을 제외하면 결과는 무엇일까요?

직접 예상해 본 뒤 풀이 확인

확인: 바깥 번호가 1·2·3인 이 자료에서는 2와 3이 남습니다. 바깥쪽 NULL을 포함하는 다른 자료까지 같은 결과라고 일반화하지 않습니다.
