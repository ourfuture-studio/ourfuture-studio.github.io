SQLD · NULL과 집계

주문은 세 건인데 COUNT는 왜 다를까

같은 표에서도 3, 2, 1이 나옵니다. COUNT의 괄호 안을 읽으면 무엇을 세었는지 알 수 있습니다.

이 주제 직접 체험하기

GitHub SQL 실험실은 SQLite로 실행됩니다. Oracle 전용 코드는 Oracle 체험에서 실행합니다.

핵심 먼저 COUNT(*)는 조회 대상의 행을 셉니다. COUNT(열)은 그 열에서 NULL이 아닌 값을 세고, COUNT(DISTINCT 열)은 NULL을 제외한 서로 다른 값을 셉니다.

500, NULL, 500이 들어 있는 세 행이라면 결과는 차례로 3, 2, 1입니다. 행 수, 기록된 값의 수, 값의 종류 수가 서로 다른 질문이기 때문입니다.

주문 수와 쿠폰 금액의 수는 같을까

[가상 예시] 카페 주문 세 건을 살펴봅니다. 201번과 203번에는 쿠폰 금액 500원이 기록되어 있고, 202번의 쿠폰 금액은 NULL입니다.

orders · 쿠폰 금액 단위: 원

order_id coupon_amount
201 500
202 NULL
203 500

주문은 분명 세 건입니다. 그런데 “쿠폰 금액이 기록된 주문은 몇 건인가?”라고 물으면 답은 두 건입니다. “기록된 쿠폰 금액은 몇 종류인가?”라고 물으면 500원 한 종류만 남습니다.

NULL을 0원으로 읽으면 여기서부터 답이 어긋납니다. 이 표의 NULL은 쿠폰 금액 값이 없다는 표시입니다. 이 값만 보고 쿠폰을 사용하지 않았다고 단정하지도 않습니다.

COUNT의 괄호 안이 계산 대상을 정한다

[사실] Oracle의 COUNT 문서는 표현식을 넣으면 그 표현식이 NULL이 아닌 행을 세고, 별표를 넣으면 중복과 NULL을 포함해 모든 행을 센다고 설명합니다. DISTINCT를 넣으면 NULL이 아닌 값의 중복도 제거합니다. COUNT · Purpose

표현 세는 대상 이 표의 결과
COUNT(*) 조회 대상 행 3
COUNT(coupon_amount) NULL이 아닌 쿠폰 금액 2
COUNT(DISTINCT coupon_amount) NULL이 아닌 서로 다른 금액 1

두 번 나온 500은 COUNT(coupon_amount)에서 두 번 셉니다. 같은 값이라는 이유로 저절로 한 번만 세지 않습니다. 중복을 제거하라는 DISTINCT를 써야 한 종류가 됩니다.

여기서 “NULL을 제외한다”는 것은 그 COUNT의 계산에서 제외한다는 뜻입니다. 원본 주문 행을 지우거나, 같은 SELECT에 있는 COUNT(*)의 계산 대상에서 함께 빼는 것이 아닙니다.

같은 기준으로 읽어 보기 COUNT(1)도 3입니다. 각 행에서 표현식 1은 NULL이 아니기 때문입니다. 이때 1은 첫 번째 열의 번호가 아니라 상수 값입니다.

Oracle에서 세 가지를 한 번에 비교해 보자

아래 코드는 Oracle 19c용입니다. 코드 위의 ‘쿼리 복사’ 버튼을 누르면 WITH 데이터부터 마지막 세미콜론까지 한 번에 복사됩니다. Oracle SQL 실행 창에 붙여 넣고 한 문장씩 실행해 보세요.

WITH orders 부분에 세 행을 적어 두었으므로 테이블을 따로 만들거나 데이터를 INSERT할 필요가 없습니다. 이 데이터 이름은 아래 SELECT 문장 안에서 사용합니다.

실행 1 · 500, NULL, 500

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH orders (order_id, coupon_amount) AS (
    SELECT 201, 500 FROM dual
    UNION ALL
    SELECT 202, CAST(NULL AS NUMBER) FROM dual
    UNION ALL
    SELECT 203, 500 FROM dual
)
SELECT COUNT(*) AS row_count,
       COUNT(coupon_amount) AS value_count,
       COUNT(DISTINCT coupon_amount) AS distinct_count
FROM orders;

예상 결과 · 1행

ROW_COUNT VALUE_COUNT DISTINCT_COUNT
3 2 1

위쪽 WITH가 입력을 준비하고, 아래 SELECT가 세 가지 기준으로 셉니다. 별표는 세 행 전체, 열 이름은 500이 있는 두 행, DISTINCT는 남은 500 한 종류에 대응합니다.

NULL 한 칸을 0으로 바꾸면 어떻게 될까

이번에는 주문 행을 더하거나 빼지 않습니다. 202번의 쿠폰 금액만 NULL에서 0으로 바꿉니다. 실행하기 전에 세 결과 가운데 무엇이 달라질지 예상해 보세요.

실행 2 · 500, 0, 500

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH orders (order_id, coupon_amount) AS (
    SELECT 201, 500 FROM dual
    UNION ALL
    SELECT 202, 0 FROM dual
    UNION ALL
    SELECT 203, 500 FROM dual
)
SELECT COUNT(*) AS row_count,
       COUNT(coupon_amount) AS value_count,
       COUNT(DISTINCT coupon_amount) AS distinct_count
FROM orders;

예상 결과 · 1행

ROW_COUNT VALUE_COUNT DISTINCT_COUNT
3 3 2

행은 여전히 세 개이므로 첫 결과는 3입니다. 0도 NULL이 아닌 값이어서 두 번째 결과는 3으로 늘어납니다. 서로 다른 금액은 0과 500 두 종류가 되어 세 번째 결과는 2가 됩니다.

이것은 입력 값을 바꾼 별도 예제입니다. 실제 자료의 NULL을 0으로 채워도 되는지는 그 빈칸이 업무에서 무엇을 뜻하는지 확인한 뒤 결정해야 합니다.

숫자 옆에 무엇의 개수인지 붙여 보자

이번 표에서 2라는 결과는 “쿠폰 금액이 기록된 주문 2건”입니다. 고객을 구분하는 열은 없으므로 이를 “쿠폰을 쓴 고객 2명”이라고 바꿔 읽을 근거는 없습니다. 한 고객이 여러 번 주문할 수도 있기 때문입니다.

COUNT 문제를 읽을 때는 어떤 행이 조회 대상인지 → 괄호 안의 값이 NULL인지 → DISTINCT가 있는지 순서로 확인해 보세요. 마지막에는 결과 숫자 뒤에 “주문 몇 건”, “금액 몇 종류”처럼 세는 단위를 붙입니다.

직접 예상해 볼 질문 세 행의 쿠폰 금액이 모두 NULL이라면 세 COUNT는 각각 얼마일까요? 주문 행은 그대로 있다는 조건을 놓치지 마세요.

직접 예상해 본 뒤 풀이 확인

확인: 3, 0, 0입니다. 주문 세 행은 남아 있지만, 셀 수 있는 NULL 아닌 쿠폰 금액은 없습니다.
