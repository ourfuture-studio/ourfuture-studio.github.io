SQLD · 제약 조건과 트랜잭션

빈 문자열과 공백 한 칸은 같은 값일까

화면에서 둘 다 비어 보일 수 있어도 Oracle에서는 길이 0 문자열과 공백 한 칸을 구분해야 합니다.

이 주제 직접 체험하기

GitHub SQL 실험실은 SQLite로 실행됩니다. Oracle 전용 코드는 Oracle 체험에서 실행합니다.

핵심 먼저 Oracle 19c는 길이 0인 문자 값을 NULL로 취급합니다. 공백 한 칸은 길이가 1인 값이고, 문자 0도 NULL이 아닙니다. 이 동작을 SQLite를 포함한 모든 DBMS의 공통 규칙으로 옮기지는 않습니다.

어떤 자료와 조건을 볼까요

빈 문자열, 명시한 NULL, 공백, 문자 0을 네 행에 놓습니다. 육안으로 빈칸을 보는 대신 IS NULL과 LENGTH로 확인해 봅니다.

답을 가르는 기준은 무엇일까요

이 예제에서 EMPTY와 NULL_VALUE는 모두 IS NULL을 만족합니다. 공백은 LENGTH가 1이며 값이 있는 행으로 셉니다.

숫자 0과 문자 0은 타입이 다르지만 어느 쪽도 NULL을 뜻하지 않습니다. 문자 비교와 암묵 변환 문제를 피하려고 여기서는 모든 txt를 VARCHAR2로 명시했습니다.

Oracle에서 첫 조건을 확인해 봅니다

실행 1 · 길이와 NULL 여부

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH samples (id, label, txt) AS (
 SELECT 1, 'EMPTY', CAST('' AS VARCHAR2(10)) FROM dual
 UNION ALL SELECT 2, 'NULL_VALUE', CAST(NULL AS VARCHAR2(10)) FROM dual
 UNION ALL SELECT 3, 'SPACE', CAST(' ' AS VARCHAR2(10)) FROM dual
 UNION ALL SELECT 4, 'ZERO_TEXT', CAST('0' AS VARCHAR2(10)) FROM dual
)
SELECT label, LENGTH(txt) AS text_length,
 CASE WHEN txt IS NULL THEN 'NULL' ELSE 'VALUE' END AS state
FROM samples ORDER BY id;

예상 결과

LABEL TEXT_LENGTH STATE
EMPTY NULL NULL
NULL_VALUE NULL NULL
SPACE 1 VALUE
ZERO_TEXT 1 VALUE

조건과 구조를 바꾸어 비교해 봅니다

실행 2 · 값이 있는 행만 세기

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH samples (id, label, txt) AS (
 SELECT 1, 'EMPTY', CAST('' AS VARCHAR2(10)) FROM dual
 UNION ALL SELECT 2, 'NULL_VALUE', CAST(NULL AS VARCHAR2(10)) FROM dual
 UNION ALL SELECT 3, 'SPACE', CAST(' ' AS VARCHAR2(10)) FROM dual
 UNION ALL SELECT 4, 'ZERO_TEXT', CAST('0' AS VARCHAR2(10)) FROM dual
)
SELECT COUNT(*) AS row_count, COUNT(txt) AS value_count,
 COUNT(DISTINCT txt) AS distinct_count FROM samples;

예상 결과

ROW_COUNT VALUE_COUNT DISTINCT_COUNT
4 2 2

값을 세는 COUNT에서는 공백과 문자 0 두 행이 남습니다. 비어 보이는 칸을 모두 같은 값으로 묶으면 이 결과를 설명할 수 없습니다.

결과를 어디까지 해석할 수 있을까요

Oracle 문서는 빈 문자열을 NULL로 취급하는 현재 동작에 기대어 빈 문자열과 NULL을 같은 개념으로 설계하지 않도록 권고합니다. 이 글은 Oracle 19c의 동작을 설명하며 다른 버전·DBMS로 일반화하지 않습니다.

직접 예상해 볼 질문 txt = NULL로 EMPTY 행을 찾을 수 있을까요?
