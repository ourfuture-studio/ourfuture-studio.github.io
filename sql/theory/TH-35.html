핵심 먼저 후보 키는 모든 행을 구별하는 슈퍼키 가운데 어떤 구성 열을 빼도 그 성질을 잃는 최소 조합입니다. 최소성은 전체 후보 키 중 열 개수가 가장 적다는 뜻이 아니라 그 조합에서 불필요한 열이 없다는 뜻입니다.

어떤 자료와 조건을 볼까요

한 학생은 여러 과목을 수강하고 한 과목에는 여러 학생이 있습니다. 같은 학생이 같은 과목에 두 번 등록하지 않는 업무 규칙을 정합니다.

답을 가르는 기준은 무엇일까요

학생 번호만으로는 학생 1의 두 등록을 구분할 수 없습니다. 과목 번호만으로도 과목 10의 두 학생을 구분할 수 없습니다. 두 번호를 함께 쓰면 한 등록을 가리킵니다.

이 업무 규칙에서 (학생 번호, 과목 번호, 학생 이름)은 유일한 조합일 수 있지만 이름을 빼도 등록을 식별하므로 최소 조합이 아닙니다.

Oracle에서 첫 조건을 확인해 봅니다

실행 1 · 한 열만으로 구분되는가

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH enrollment (student_id, course_id, student_name) AS (
    SELECT 1, 10, 'MIN' FROM dual
    UNION ALL
    SELECT 1, 20, 'MIN' FROM dual
    UNION ALL
    SELECT 2, 10, 'JUN' FROM dual
)
SELECT COUNT(*) AS rows_total,
 COUNT(DISTINCT student_id) AS students,
 COUNT(DISTINCT course_id) AS courses
FROM enrollment;

실행 2 · 두 번호 조합의 중복 검사

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH enrollment (student_id, course_id, student_name) AS (
    SELECT 1, 10, 'MIN' FROM dual
    UNION ALL
    SELECT 1, 20, 'MIN' FROM dual
    UNION ALL
    SELECT 2, 10, 'JUN' FROM dual
)
SELECT student_id, course_id, COUNT(*) AS duplicate_count
FROM enrollment GROUP BY student_id, course_id
HAVING COUNT(*) > 1
ORDER BY student_id, course_id;

예상 결과

반환 행 없음 · 0행.

현재 표본에서는 두 번호의 중복 조합이 없습니다. 다만 이 검사 한 번으로 앞으로 들어올 모든 자료의 유일성이 증명되지는 않습니다. 업무 규칙을 모델에 명시하고 구현 시 제약으로 보장해야 합니다.

결과를 어디까지 해석할 수 있을까요

“최소”를 무조건 한 열로 외우지 않습니다. 두 열 후보 키와 세 열 후보 키가 서로 포함 관계 없이 동시에 존재할 수도 있습니다. NULL 허용 같은 실제 SQL 제약 조건도 별도로 검토합니다.

직접 예상해 볼 질문 두 번호가 후보 키인 이 규칙에서 학생 이름을 추가한 세 열도 후보 키일까요?

직접 예상해 본 뒤 풀이 확인

확인: 아닙니다. 슈퍼키로는 쓸 수 있지만 이름이 불필요하므로 후보 키의 최소성을 만족하지 않습니다.
