SQLD · 제약 조건과 트랜잭션

ROLLBACK은 어느 시점까지 되돌릴까

저장 지점으로 일부만 되돌리는 것과 마지막 COMMIT 이후를 모두 취소하는 것을 구분합니다.

이 주제 직접 체험하기

GitHub SQL 실험실은 SQLite로 실행됩니다. Oracle 전용 코드는 Oracle 체험에서 실행합니다.

핵심 먼저 ROLLBACK TO SAVEPOINT는 그 저장 지점 뒤의 변경만 취소하고 트랜잭션을 끝내지 않습니다. 일반 ROLLBACK은 현재 트랜잭션의 변경을 취소합니다. COMMIT으로 확정한 이전 값까지 지우지는 않습니다.

어떤 자료와 조건을 볼까요

초기 금액 10을 확정한 뒤 20으로 바꾸고 저장 지점을 둡니다. 다시 30으로 바꾼 뒤 저장 지점으로 돌아가면 무엇이 남는지 따라가 봅니다.

답을 가르는 기준은 무엇일까요

저장 지점은 변경 내용을 영구 확정하는 명령이 아닙니다. 20 시점으로 되돌린 뒤 전체 ROLLBACK을 하면 마지막 확정 값 10으로 돌아갑니다.

같은 세션·같은 연결과 자동 커밋 해제가 전제입니다. 중간에 CREATE·DROP 같은 DDL을 끼우면 암묵적 COMMIT으로 저장 지점과 롤백 범위가 달라집니다.

Oracle에서 첫 조건을 확인해 봅니다

실행 1 · 실습 기준 값 10 확정

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

개인 실습 스키마에서 같은 세션으로 실행합니다. 자동 커밋을 끄고 동일 이름의 기존 표가 있다면 실습 이름을 바꾸세요.

CREATE TABLE OFS_T45_DEMO (id NUMBER PRIMARY KEY, amount NUMBER);
INSERT INTO OFS_T45_DEMO (id, amount)
WITH seed (id, amount) AS (SELECT 1, 10 FROM dual)
SELECT id, amount FROM seed;
COMMIT;
SELECT id, amount FROM OFS_T45_DEMO;

예상 결과

ID AMOUNT
1 10

실행 2 · 일부 취소와 전체 취소

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

실행 순서: 실행 1 완료

UPDATE OFS_T45_DEMO SET amount = 20 WHERE id = 1;
SAVEPOINT after_20;
UPDATE OFS_T45_DEMO SET amount = 30 WHERE id = 1;
ROLLBACK TO SAVEPOINT after_20;
SELECT amount AS after_savepoint FROM OFS_T45_DEMO WHERE id=1;
ROLLBACK;
SELECT amount AS after_full_rollback FROM OFS_T45_DEMO WHERE id=1;

이 글에서 만든 표에만 실행합니다. DROP은 DDL입니다.

DROP TABLE OFS_T45_DEMO;

예상: 명령 완료. 조회 결과 없음.

20은 저장 지점의 값, 10은 첫 확정 값, 40은 다음 확정 값입니다. ROLLBACK이라는 단어만 보고 항상 맨 처음 값으로 돌아간다고 읽으면 안 됩니다.

결과를 어디까지 해석할 수 있을까요

COMMIT 뒤에는 그 트랜잭션의 SAVEPOINT도 유지되지 않습니다. 문법적으로 유효한 DDL은 실행에 실패해도 실행 전의 암묵적 COMMIT이 개입합니다. 문법 오류와 실행 단계의 실패를 구분하고, DDL에서 오류가 났다는 이유만으로 앞의 DML도 모두 미확정이라고 추정하지 않습니다.

직접 예상해 볼 질문 실행 2의 ROLLBACK TO SAVEPOINT 다음에 COMMIT을 한다면 20은 확정될까요?

직접 예상해 본 뒤 풀이 확인

확인: 그렇습니다. 부분 취소는 트랜잭션을 끝내지 않으므로 남은 20의 변경을 COMMIT으로 확정할 수 있습니다.
