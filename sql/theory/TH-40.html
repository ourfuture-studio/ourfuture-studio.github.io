핵심 먼저 개념 단계에서는 관리 대상과 관계를, 논리 단계에서는 속성·식별자·종속과 구조를, 물리 단계에서는 특정 DBMS의 자료형·제약·저장 및 접근 방식을 구체화합니다. 도구마다 모델 단계의 이름과 구분이 다를 수 있습니다.

어떤 자료와 조건을 볼까요

고객과 주문을 관리한다는 설명만으로는 고객 번호의 타입이나 외래 키 제약이 정해지지 않습니다. 업무 관계를 표현한 작은 조회와 실제 DDL을 나란히 봅니다.

답을 가르는 기준은 무엇일까요

논리 규칙으로 각 주문의 고객을 하나 정하고 고객 번호로 연결합니다. 아직 WITH의 예제 행에는 실제 PK·FK 제약이 걸린 것이 아닙니다.

아래 DDL에서는 Oracle의 NUMBER와 VARCHAR2를 선택하고 PK·NOT NULL·FK를 명시합니다. NUMBER(6)은 이 실습에서 정한 자릿수이며 업무에 필요한 모든 번호 범위를 뜻하지 않습니다.

Oracle에서 첫 조건을 확인해 봅니다

실행 1 · 관계를 확인하는 WITH 표본

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH customers (customer_id, customer_name) AS (
    SELECT 1, 'MIN' FROM dual
    UNION ALL
    SELECT 2, 'JUN' FROM dual
    UNION ALL
    SELECT 3, 'SOL' FROM dual
),
orders (order_id, customer_id, amount) AS (
    SELECT 101, 1, 10 FROM dual
    UNION ALL
    SELECT 102, 1, 20 FROM dual
    UNION ALL
    SELECT 103, 2, 5 FROM dual
)
SELECT o.order_id, c.customer_name
FROM orders o JOIN customers c ON c.customer_id=o.customer_id
ORDER BY o.order_id;

103 JUN

실행 2 · 개인 실습 스키마에 실제 구조 생성

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

처음 한 번만 생성합니다. 같은 이름의 표가 이미 있다면 기존 표를 지우지 말고 이 실습에서 쓸 이름을 바꾸세요. DDL은 암묵적 COMMIT을 수행하므로 다른 작업이 없는 개인 실습 스키마에서 실행합니다.

CREATE TABLE OFS_T40_CUSTOMER (
 customer_id NUMBER(6) PRIMARY KEY,
 customer_name VARCHAR2(30) NOT NULL
);
CREATE TABLE OFS_T40_ORDERS (
 order_id NUMBER(6) PRIMARY KEY,
 customer_id NUMBER(6) NOT NULL REFERENCES OFS_T40_CUSTOMER(customer_id)
);
SELECT table_name, column_name, data_type
FROM user_tab_columns
WHERE table_name IN ('OFS_T40_CUSTOMER','OFS_T40_ORDERS')
ORDER BY table_name, column_name;
