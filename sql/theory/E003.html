개념과 판단을 한눈에

행 필터(Row Filter, WHERE), 그룹 필터(Group Filter, HAVING), 그룹화(Grouping, GROUP BY)

핵심 판단 규칙

논리적 판단 흐름: WHERE → GROUP BY → HAVING. HAVING은 WHERE를 통과한 행으로 만든 그룹을 검사한다. 실제 실행 계획의 고정 순서를 뜻하지 않는다.

아래 이론과 문제·실험은 같은 원리를 다른 입력으로 확인할 수 있습니다. 숫자를 대조할 때는 각 화면에 표시된 표·조건·SQL을 먼저 확인하세요.

이 주제 직접 체험하기

GitHub SQL 실험실은 SQLite로 실행됩니다. Oracle 전용 코드는 Oracle 체험에서 실행합니다.

핵심 먼저 WHERE는 집계 전에 입력 행을 제한합니다. HAVING은 그룹의 집계 결과에 조건을 적용합니다. 두 조건에 같은 숫자가 쓰였어도 남는 합계는 달라질 수 있습니다.

어떤 자료와 조건을 볼까요

고객 1은 10원과 30원, 고객 2는 25원을 주문했습니다. 작은 주문을 먼저 빼고 합칠지, 모든 주문을 합친 뒤 고객을 고를지 비교합니다.

답을 가르는 기준은 무엇일까요

WHERE amount > 20이면 고객 1의 10원 주문은 합계 계산 전에 빠집니다. 남은 30원만 더합니다.

HAVING SUM(amount) > 20이면 고객별로 원래 주문을 합친 뒤 그 합계를 검사합니다. 고객 1의 합계는 40원입니다.

Oracle에서 첫 조건을 확인해 봅니다

실행 1 · 주문 행의 금액 조건

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH orders (order_id, customer_id, amount) AS (
    SELECT 101, 1, 10 FROM dual
    UNION ALL
    SELECT 102, 1, 30 FROM dual
    UNION ALL
    SELECT 103, 2, 25 FROM dual
)
SELECT customer_id, SUM(amount) AS total
FROM orders WHERE amount > 20
GROUP BY customer_id ORDER BY customer_id;

예상 결과

CUSTOMER_ID TOTAL
1 30
2 25

조건과 구조를 바꾸어 비교해 봅니다

실행 2 · 고객별 합계 조건

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH orders (order_id, customer_id, amount) AS (
    SELECT 101, 1, 10 FROM dual
    UNION ALL
    SELECT 102, 1, 30 FROM dual
    UNION ALL
    SELECT 103, 2, 25 FROM dual
)
SELECT customer_id, SUM(amount) AS total
FROM orders GROUP BY customer_id
HAVING SUM(amount) > 20
ORDER BY customer_id;

예상 결과

CUSTOMER_ID TOTAL
1 40
2 25

두 SQL에서 고객 번호는 같아도 고객 1의 합계가 다릅니다. 조회된 고객 목록만 비교하면 계산 기준이 바뀐 사실을 놓칠 수 있습니다.

결과를 어디까지 해석할 수 있을까요

WHERE SUM(amount) > 20을 같은 쿼리 블록에 쓰는 것은 그룹의 결과가 필요한 조건을 행 필터 자리에 놓은 것입니다. 필요한 집계를 하위 질의에서 먼저 만든 경우와는 구분합니다.

직접 예상해 볼 질문 “20원 초과 주문만 합쳐서 그 합계가 35원 이상인 고객”은 어느 조건을 쓸까요?

직접 예상해 본 뒤 풀이 확인

확인: WHERE amount > 20과 HAVING SUM(amount) >= 35를 함께 씁니다. 이 자료에서는 고객 1의 남은 합계도 30원이어서 결과는 0행입니다.
