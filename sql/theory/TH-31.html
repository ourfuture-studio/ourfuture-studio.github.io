이전 행은 저장 순서일까 정렬 순서일까

LAG와 LEAD의 옆 행은 파티션과 정렬을 정한 뒤에 결정됩니다. 앞 행이 없는 것과 앞 행의 값이 NULL인 것도 다릅니다.

이 주제 직접 체험하기

GitHub SQL 실험실은 SQLite로 실행됩니다. Oracle 전용 코드는 Oracle 체험에서 실행합니다.

핵심 먼저 LAG는 정렬된 파티션에서 앞쪽 값을, LEAD는 뒤쪽 값을 가져옵니다. 기본 offset은 1입니다. 세 번째 인자인 기본값은 범위 밖일 때 쓰며, 범위 안의 실제 NULL을 자동으로 바꾸는 값이 아닙니다.

어떤 자료와 조건을 볼까요

두 고객의 주문 번호가 번갈아 나옵니다. 고객 1의 가운데 주문 금액은 NULL입니다. 고객별 이웃 주문과 전체 이웃 주문을 비교해 봅니다.

답을 가르는 기준은 무엇일까요

PARTITION BY customer_id로 고객별 경계를 먼저 정합니다. 고객 1의 순서는 101→103→105, 고객 2는 102→104입니다.

기본 RESPECT NULLS에서는 105번 바로 앞인 103번의 실제 NULL이 그대로 반환됩니다. 앞 행이 없어서 기본값 -1이 나오는 101번과 다릅니다.

Oracle에서 첫 조건을 확인해 봅니다

실행 1 · 고객별 앞뒤 주문

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH orders (order_id, customer_id, amount) AS (
    SELECT 101, 1, 10 FROM dual
    UNION ALL
    SELECT 102, 2, 5 FROM dual
    UNION ALL
    SELECT 103, 1, CAST(NULL AS NUMBER) FROM dual
    UNION ALL
    SELECT 104, 2, 8 FROM dual
    UNION ALL
    SELECT 105, 1, 30 FROM dual
)
SELECT customer_id, order_id, amount,
 LAG(amount, 1, -1) OVER (PARTITION BY customer_id ORDER BY order_id) AS prev_amount,
 LEAD(amount, 1, -1) OVER (PARTITION BY customer_id ORDER BY order_id) AS next_amount
FROM orders ORDER BY customer_id, order_id;

예상 결과

CUSTOMER_ID ORDER_ID AMOUNT PREV_AMOUNT NEXT_AMOUNT
1 101 10 -1 NULL
1 103 NULL 10 30
1 105 30 NULL -1
2 102 5 -1 8
2 104 8 5 -1

실행 2 · 파티션을 없애면

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH orders (order_id, customer_id, amount) AS (
    SELECT 101, 1, 10 FROM dual
    UNION ALL
    SELECT 102, 2, 5 FROM dual
    UNION ALL
    SELECT 103, 1, CAST(NULL AS NUMBER) FROM dual
    UNION ALL
    SELECT 104, 2, 8 FROM dual
    UNION ALL
    SELECT 105, 1, 30 FROM dual
)
SELECT order_id, customer_id, amount,
 LAG(amount, 1, -1) OVER (ORDER BY order_id) AS prev_amount
FROM orders ORDER BY order_id;

예상 결과

ORDER_ID CUSTOMER_ID AMOUNT PREV_AMOUNT
101 1 10 -1
102 2 5 10
103 1 NULL 5
104 2 8 NULL
105 1 30 8

두 번째 결과에서 102번의 이전 값은 다른 고객인 101번의 10입니다. 함수가 고객 관계를 스스로 추론하지 않으므로 파티션 키를 적어야 합니다.

결과를 어디까지 해석할 수 있을까요

ORDER BY가 동률을 남기면 어떤 행이 바로 앞인지 불명확할 수 있습니다. 여기서는 고유한 주문 번호로 순서를 정했습니다. -1은 설명을 위한 기본값이며 실제 금액처럼 집계할 값은 아닙니다.

직접 예상해 볼 질문 WHERE amount IS NOT NULL로 먼저 걸러낸 뒤 실행 1의 LAG를 계산하면 105번의 이전 값은 무엇일까요?

직접 예상해 본 뒤 풀이 확인

확인: 10입니다. NULL 주문 행이 분석 함수 계산 전에 제외되므로 고객 1에게 남은 순서가 101→105가 됩니다.
