PARTITION BY는 왜 주문 행을 줄이지 않을까

고객별 합계를 구하면서 주문 한 건 한 건도 보고 싶다면 두 종류의 집계를 구분해야 합니다.

개념과 판단을 한눈에

그룹화(Grouping, GROUP BY), 파티션(Partition, PARTITION BY), 분석 함수(Analytic Function)

핵심 판단 규칙

GROUP BY는 그룹당 결과 행을 만들고, 분석 함수는 입력 행마다 값을 계산한다. 반복 표시된 고객 합계 30·30·5를 다시 합치면 원래 매출 35와 달라진다.

아래 이론과 문제·실험은 같은 원리를 다른 입력으로 확인할 수 있습니다. 숫자를 대조할 때는 각 화면에 표시된 표·조건·SQL을 먼저 확인하세요.

이 주제 직접 체험하기

GitHub SQL 실험실은 SQLite로 실행됩니다. Oracle 전용 코드는 Oracle 체험에서 실행합니다.

핵심 먼저 GROUP BY는 그룹별 결과 행을 만듭니다. SUM(...) OVER(PARTITION BY ...)는 각 입력 행에 그 파티션의 집계 값을 붙입니다. 그룹 합계가 같아 보여도 결과 행의 단위가 다릅니다.

어떤 자료와 조건을 볼까요

고객 1은 주문 두 건, 고객 2는 한 건입니다. 고객 합계만 보고할 때는 두 행, 주문별로 고객 합계를 곁들일 때는 세 행이 필요합니다.

답을 가르는 기준은 무엇일까요

GROUP BY customer_id에서는 주문 번호를 그대로 한 개 고를 수 없습니다. 어떤 주문을 대표로 남길지 정해지지 않았기 때문입니다.

분석 집계에서는 각 주문 행이 남아 있으므로 order_id와 amount를 함께 볼 수 있습니다. 고객 1의 합계 30은 그 고객의 두 주문 행에 반복됩니다.

Oracle에서 첫 조건을 확인해 봅니다

실행 1 · 고객마다 한 행

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH orders (order_id, customer_id, amount) AS (
    SELECT 101, 1, 10 FROM dual
    UNION ALL
    SELECT 102, 1, 20 FROM dual
    UNION ALL
    SELECT 103, 2, 5 FROM dual
)
SELECT customer_id, SUM(amount) AS customer_total
FROM orders GROUP BY customer_id ORDER BY customer_id;

예상 결과

CUSTOMER_ID CUSTOMER_TOTAL
1 30
2 5

조건과 구조를 바꾸어 비교해 봅니다

실행 2 · 주문마다 합계 붙이기

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

WITH orders (order_id, customer_id, amount) AS (
    SELECT 101, 1, 10 FROM dual
    UNION ALL
    SELECT 102, 1, 20 FROM dual
    UNION ALL
    SELECT 103, 2, 5 FROM dual
)
SELECT order_id, customer_id, amount,
 SUM(amount) OVER (PARTITION BY customer_id) AS customer_total
FROM orders ORDER BY order_id;

예상 결과

ORDER_ID CUSTOMER_ID AMOUNT CUSTOMER_TOTAL
101 1 10 30
102 1 20 30
103 2 5 5

두 번째 결과의 CUSTOMER_TOTAL을 다시 전체 합산하면 30+30+5=65가 됩니다. 주문 합계 35와 다르므로 반복 표시된 그룹 합계를 재집계할 때 주의해야 합니다.

결과를 어디까지 해석할 수 있을까요

PARTITION BY를 써도 그 앞의 조인이나 WHERE가 행 수를 바꿀 수 있습니다. “분석 함수 자체가 그룹별로 행을 접지 않는다”는 범위에서 읽습니다.

직접 예상해 볼 질문 고객별 주문 금액 비중을 구하려면 두 번째 결과의 무엇을 나눌까요?

직접 예상해 본 뒤 풀이 확인

확인: 각 주문의 amount를 customer_total로 나눕니다. 합계가 0 또는 NULL인 경우의 처리도 업무 규칙에 따라 정해야 합니다.
