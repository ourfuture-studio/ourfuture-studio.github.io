SQLD · 제약 조건과 트랜잭션

PRIMARY KEY와 UNIQUE와 NOT NULL은 무엇을 막을까

중복 금지와 값 필수는 같은 제약이 아닙니다. 한 표에 세 조건을 나누어 걸어 봅니다.

이 주제 직접 체험하기

GitHub SQL 실험실은 SQLite로 실행됩니다. Oracle 전용 코드는 Oracle 체험에서 실행합니다.

핵심 먼저 PRIMARY KEY는 키의 중복과 NULL을 금지합니다. 단일 열 UNIQUE는 중복된 NULL 아닌 값을 금지하지만 여러 NULL을 허용할 수 있습니다. NOT NULL은 값을 필수로 만들며 그 값의 중복까지 막지는 않습니다.

어떤 자료와 조건을 볼까요

회원 번호는 필수 고유 값, 이메일은 선택 입력이지만 입력했다면 고유 값, 별명은 필수이되 중복을 허용하는 업무를 정합니다.

답을 가르는 기준은 무엇일까요

세 조건을 member_id PRIMARY KEY, email UNIQUE, nickname NOT NULL로 따로 표현합니다. 번호가 다르더라도 같은 이메일을 두 번 넣으면 UNIQUE 위반입니다.

여기서 이메일은 단일 열 UNIQUE입니다. 복합 UNIQUE에서 일부 열만 NULL인 조합의 규칙까지 “NULL이면 모두 중복 허용”으로 확대하지 않습니다.

복사한 쿼리를 Oracle 체험(FreeSQL)에 붙여 넣어 실행하세요.

개인 실습 스키마에서 처음 한 번 실행합니다. 같은 이름의 기존 표는 삭제하지 말고 실습 이름을 바꾸세요. CREATE에는 DDL 커밋이 개입합니다.

CREATE TABLE OFS_T43_MEMBER (
 member_id NUMBER PRIMARY KEY,
 email VARCHAR2(40) UNIQUE,
 nickname VARCHAR2(20) NOT NULL
);
INSERT INTO OFS_T43_MEMBER (member_id, email, nickname)
WITH members (member_id, email, nickname) AS (
 SELECT 1, CAST('a@example.test' AS VARCHAR2(40)), 'MIN' FROM dual
 UNION ALL SELECT 2, CAST(NULL AS VARCHAR2(40)), 'JUN' FROM dual
 UNION ALL SELECT 3, CAST(NULL AS VARCHAR2(40)), 'MIN' FROM dual
)
SELECT member_id, email, nickname FROM members;
SELECT member_id, email, nickname FROM OFS_T43_MEMBER ORDER BY member_id;

결과를 어디까지 해석할 수 있을까요

WITH에서 중복이 없다는 조회 결과와 DB에 제약을 생성했다는 사실은 다릅니다. 이 글에서는 실제 CREATE TABLE로 제약을 만들었고, 제약 위반 입력을 별도 블록으로 분리했습니다.

직접 예상해 볼 질문 nickname에 NOT NULL만 있다면 같은 별명을 가진 회원을 두 명 넣을 수 있을까요?

직접 예상해 본 뒤 풀이 확인

확인: 그렇습니다. 별명 중복도 금지하려면 별도의 유일성 조건이 필요합니다. 이 업무에서는 중복을 허용했습니다.
